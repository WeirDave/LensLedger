## Why this release

Pressing Ctrl+C during a long job closed LensLedger. That is not what anyone
means by it during a scan that has been running for twenty minutes: they want
the scan to stop, not the program to disappear. Worse, the launcher's
"Terminate batch job (Y/N)?" prompt appeared after the fact, when answering it
either way made no difference — the server had already gone.

## What Ctrl+C does now

- **While something is running**, it stops that job at its next safe point and
  leaves LensLedger open. The log names the job it stopped and says the program
  is still running.
- **Pressing it again within five seconds** quits anyway, so it can never
  become something you cannot get out of.
- **With nothing running**, it quits immediately, as before.

Every job can be stopped this way: the photo location scan, text recognition,
meaning search, face detection, writing tags, classifying photos, and "Run all
scans".

Ctrl+Break still closes LensLedger outright. That key has always meant "stop
now" and it is left as the way out if anything ever fails to respond.

## Verified

- Full test suite: 178 tests, all passing, on Python 3.12.10 — up from 164.
- Nine new tests cover the behaviour: that a press cancels the running job and
  leaves the server answering, that it cancels every running job rather than
  the first, that it leaves idle jobs alone, that a press with nothing running
  quits, that a second press always quits, that a much later press cancels
  again rather than quitting, that the location scan is recognised under its
  own status name, and that shutting down never runs on the thread serving
  requests, which would deadlock.
- One of those tests raises a real operating-system interrupt at a real running
  server and then checks the server still answers a request, so it would catch
  the handler not being installed at all.
- Removing the cancelling step was confirmed to fail six of those tests.
