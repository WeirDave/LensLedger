# Face detection uses an NVIDIA graphics card when there is one

## Why this release

- Face detection ran on the processor on every computer, including those with an NVIDIA graphics card, because the runtime it uses was installed without graphics-card support.

## What changed

### Setup

- Setting up face detection on Windows now looks for an NVIDIA card. When one is found and its driver supports CUDA 13 or newer, the graphics-card version of the face-detection runtime (onnxruntime-gpu) replaces the processor-only version. When PyTorch with graphics-card support is already installed, the two share its CUDA libraries; otherwise the CUDA and cuDNN libraries are installed with the runtime. If the graphics-card runtime cannot be installed, the processor version is put back so face detection keeps working.
- Face detection prepares its models on the graphics card whenever the runtime offers it, and on the processor otherwise.

### Scan your photos

- The status line under **Face detection** now ends with what face detection runs on: "Using your graphics card (name)", "Using the processor", or, when a card was found that face detection cannot use yet, a sentence saying so. The same line is written to the activity log when a scan starts.
- A **Use my graphics card** button appears beside **Pause** under **Face detection** in that last case. After a confirmation it restarts LensLedger, installs the graphics-card runtime while the terminal window shows progress, and opens again when done. It is unavailable while a scan is running. Faces already found are not touched.
- When the NVIDIA driver is too old for graphics-card support, the status line says that updating the driver would allow it, and no button is shown.
- The button under **Meaning search** and the one under **Face detection** each switch only their own feature.

### Manual

- Both manuals describe the graphics-card behaviour of face detection and the new button.

## Verified

- Full test suite: all passing. New tests cover building the graphics-card requirement line, sharing PyTorch's CUDA libraries, restoring the processor runtime after a failed switch, the old-driver message, choosing graphics-card providers, and a queued switch that leaves PyTorch alone.
