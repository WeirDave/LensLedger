Small same-day fix on "Name faces": picking a name from the dropdown
suggestions didn't save it.

## "Why do I need to hit Enter?"

Fair question. The name field on `/faces-review` uses a `<datalist>` for
autocomplete suggestions — clicking a suggestion fills the box, same as
typing does, but nothing was listening for "the user just picked one,"
so it sat there until Enter or Save was pressed. From the user's side,
picking a name from a dropdown reads as a completed action; requiring a
second step afterward doesn't.

Fixed: the input now listens for the browser's `change` event, which
fires the instant a datalist suggestion is picked (not on every
keystroke, the way `input` does). If the resulting value matches one of
the known people, it saves immediately. Typing a brand-new name still
needs an explicit Enter or Save — creating a new person is a more
deliberate action than picking an existing one, and shouldn't fire just
because a field lost focus mid-thought.

## Verified

- Full automated suite (64 tests) green.
- Manually verified against the real library: simulated a datalist pick
  (set the field to an existing name, fired `change`) and confirmed the
  face saved and the card cleared within ~1.2s, matching the API round
  trip. Separately confirmed typing a brand-new name and blurring the
  field does *not* auto-save — the card stays put until Enter or Save.
