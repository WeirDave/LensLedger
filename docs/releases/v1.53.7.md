# Refused requests now report why instead of dropping the connection

## Why this release

- LensLedger refuses some requests before reading their contents: requests from another site, requests naming another host, and requests that are too large.
- The refusal was sent and the connection closed while the contents were unread or still arriving. Windows then reset the connection, and the program that sent the request could receive a connection error in place of the explanation.

## What changed

### Server

- A refused request now receives its error message. LensLedger sends the refusal first, then reads and discards the rest of the request before closing the connection.
- The discarded contents are not interpreted. Which requests are refused, and the same-site and request token checks, are unchanged.
- Reading a refused request stops after 16 MB or about five seconds.

## Verified

- Full test suite: 749 tests, all passing.
- Refused requests sent with a pause between headers and contents, and refused requests of 5 MB, could lose their error message before the change and received it in every run afterwards.
- A refusal arrives without waiting when the contents are never sent.
- The server security test that failed intermittently passed 300 repeated runs on each of Python 3.12 and 3.14.
