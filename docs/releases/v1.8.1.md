## Why this release

On the main photo screen, clicking "Move to Trash" in the sidebar, or the
batch "Trash" button with several photos selected, left the photo in the film
strip until the server had finished moving the file into the Review Bin. The
Review Bin is kept in the LensLedger data folder, so a library on a different
drive meant copying the whole file first, and large photos and videos stayed
on screen for a noticeable time after being trashed.

## What changed

- Once the confirmation is accepted, the trashed photo (or selected photos)
  now leaves the film strip straight away, and the next photo opens.
- The file move into the Review Bin continues in the background. The status
  line reads "Moving … to Trash…" until it finishes, and then the usual
  "Undo" notice appears.
- If the move fails, an error message names the photo and the page reloads,
  so the film strip shows the photo again.

## Verified

- Full test suite: 210 tests, all passing, on Python 3.12.10.
- Checked in the browser against a generated test library, with the server
  reply held back by three seconds: the thumbnail was gone from the film strip
  within 300 ms of "Move to Trash", the next photo opened, and the "Undo"
  notice appeared once the reply arrived. Undo restored the photo.
