# LensLedger v0.72.1 — Metadata publish progress and non-blocking DB

## Motivation

After v0.72.0's deferred metadata publishing, a large batch (e.g. 199 photos)
would write all JPEG metadata in one long-running request with no visible
progress. The server log stayed silent for minutes, and because the database
connection was held open the entire time, naming a new person would hang until
the publish finished.

## What changed

### Progress logging

`publish_person_metadata` now prints progress every 25 photos:
```
[Name faces] Publishing "Patricia Jean Stroop" to 199 photos…
[Name faces] Published "Patricia Jean Stroop" — 25/199
[Name faces] Published "Patricia Jean Stroop" — 50/199
...
[Name faces] Published "Patricia Jean Stroop" — 199/199
```

### Non-blocking database access

Instead of holding one database connection for the entire publish run, each
photo now opens and closes its own connection. This means other requests (like
naming a new person on the same page) can interleave between individual
metadata writes instead of waiting for the entire batch to finish.

## Verified

- **Test suite**: 80 tests, all passed.
