Two requests from live use of People review: seeing a small/ambiguous face
up close before deciding, and a way to close out a suggestion that isn't a
name-able match — instead of just leaving it in limbo as a plain "wrong."

## Double-click to inspect

People review already had an "⛶ Enlarge" button that opens the full photo
in a lightbox with the face location drawn on it — exactly what you want
for a face that's tiny, blurry, or half-hidden in the background. The photo
thumbnail itself just wasn't clickable. It now responds to a double-click
the same way the button does (`web/js/people-review.js`), with a
`cursor:zoom-in` hint on hover.

## "Not a person" and "Unknown person"

Before this, a wrong suggestion had exactly one way to be closed out:
"wrong," optionally paired with typing in the actual name. There was no way
to say *why* it was wrong — a bad detection versus a real face you simply
don't recognize — and, more importantly, nothing stopped the same
mis-detected face from resurfacing later under a *different* person's
review queue as face-clustering re-ran. Rejecting it once didn't mean
rejecting it for good.

Investigated the suggestion pipeline (`face_learning.py`) before touching
anything: it already had exactly this mechanism, just not exposed here.
The Name-faces page's "Not a person" button sets an `ignored_at` timestamp
on the face record, and `learn()`'s very first query already excludes
`ignored_at IS NOT NULL` faces from ever being proposed again, for anyone.
That's the right fix for "the detector was wrong, this isn't a face" —
so People review's new "Not a person" button reuses that exact mechanism
rather than inventing a second one.

"Unknown person" is a related but distinct claim — it *is* a real face,
you just don't know who it is — so it gets a new, parallel column
(`unknown_at` on `face_embeddings`), added the same way `ignored_at` was:
a plain `ALTER TABLE ... ADD COLUMN`, no `CHECK`-constraint rewrite. SQLite
requires a full table rebuild to add a new enum value to an existing
`CHECK` constraint, and nothing in this codebase has ever done that — so
rather than introduce that pattern for the first time, both new outcomes
resolve to the existing `state='rejected'` under the hood, with a new
`face_disposition` column on `people_review_actions` (also a plain ADD
COLUMN) recording which one it actually was, so undo can reverse the flag
along with everything else.

Both buttons appear in two places — the review card (once marked wrong)
and the lightbox itself — since the whole point of enlarging a photo is to
decide what you're actually looking at.

Also fixed while in the area: `generate_face_suggestions.py`, an offline
CLI utility for recovering suggestions from a saved reference set, never
filtered `ignored_at` at all — any face ignored via the Name-faces page
could still resurface through that script. It now excludes both
`ignored_at` and `unknown_at`, matching `face_learning.py`.

## Verified

- Full automated suite: 77 tests (74 prior + 3 new), all green. New
  coverage: a `face_learning` unit test confirming both `ignored_at`- and
  `unknown_at`-flagged faces are excluded from suggestions and
  auto-confirmation even when they'd otherwise score as a near-certain
  match; two HTTP-level tests exercising `/api/people/review/decision` and
  `/api/people/review/batch` with both new actions, asserting the
  `asset_people` row is rejected, the correct `face_embeddings` column is
  stamped (and not the other one), and — for the single-decision path —
  that undo restores both the suggestion state and clears the flag.
- Live browser session against a seeded suggestion: opened People review,
  toggled a card to "wrong," confirmed both new buttons render and are
  mutually exclusive with typing a correction name and with each other;
  double-clicked the photo and confirmed the lightbox opens with both
  buttons present; chose "Unknown person" from the lightbox and confirmed
  it closes the lightbox, updates the underlying card, and — after Save &
  publish — the database shows exactly what was designed: the suggestion
  rejected, `unknown_at` stamped (and `ignored_at` left untouched), and
  the review-action row recording `face_disposition='unknown_person'`.
