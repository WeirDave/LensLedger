# LensLedger v0.63.2 — Specific meaning search error messages

## Context

When the meaning search indexer failed to encode an image, it stored the same
generic message for every failure: "Image could not be encoded by the
meaning-search model." The Scan photos page showed this identical message for
every errored image, giving users no clue whether the problem was a corrupt
file, an unsupported format, a truncated JPEG, or something else entirely.

## What changed

The CLIP encoder's `encode_images` method now captures the actual exception
from Pillow (e.g. `OSError`, `ValueError`) and returns the exception message
as a string instead of silently returning `None`. The `build_index` function
stores this real error message in the `semantic_error` column.

Users now see specific messages like:
- "cannot identify image file 'photo.xyz'"
- "Truncated File Read"
- "image file is truncated (42 bytes not processed)"

The fallback path in `photo_search.py` for unindexed images that have no
stored error (edge case from interrupted builds) now says "Not indexed — no
error recorded. Try rebuilding the meaning index." instead of the same generic
message.

## Files changed

- `src/semantic_index.py` — `encode_images` captures exception strings;
  `build_index` stores them
- `src/photo_search.py` — fallback error message updated
- `tests/test_semantic.py` — added `FakeEncoderWithErrors` and a test that
  verifies specific error messages are stored in the database

- Test suite: 80 tests, all passing
