## Motivation

Release notes and test fixtures contained real personal names from the developer's photo library — full names of family, friends, and acquaintances used as illustrative examples in log output. Since release notes are published as GitHub Release bodies, these names were publicly visible.

One release note also referenced "Bright House Networks," a real ISP name, as a group example.

## What changed

Replaced every real personal name across 9 files with fictional equivalents:

- **Release notes** (7 files): `v0.43.21.md`, `v0.65.0.md`, `v0.65.4.md`, `v0.74.0.md`, `v0.81.4.md`, `v0.86.0.md`, `v0.87.0.md`, `v0.92.3.md`, `v0.92.4.md`, `v0.92.5.md`
- **Test fixtures** (1 file): `tests/test_server.py` — merge-people test data

All replacements use consistent fictional names that preserve the structure of the examples (suffixes like "Jr." and "III", aliases, multiple-word names for truncation demos, starts-with-"Ter" names for sort-priority demos).

The developer's own name in `LICENSE` (copyright notice) was left as-is — that's standard and intentional.

## Verified

- Test suite: 113 tests, all passing.
- Second-pass grep for all original names confirmed zero remaining hits in project-authored files (only vendored ExifTool Perl library contains unrelated matches like "Nick Ing-Simmons").
