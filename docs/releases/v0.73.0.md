## Motivation

Metadata publishing (writing person names into JPEG XMP/IPTC tags via ExifTool)
was tightly coupled to the Name Faces workflow. After confirming a batch of faces,
the frontend would immediately call the publish endpoint, writing to every photo
before the user could move on. For someone naming 10+ people in a session, this
meant waiting minutes for file I/O between each person — even after v0.72.0
deferred publishing to the end of each person's matching chain.

The user wanted full control: name faces all day at database speed, then publish
all the metadata overnight in one batch.

## What changed

### New "Publish photos" page

A dedicated page at `/publish` shows exactly what needs publishing:

- Total photos pending metadata updates
- Per-person breakdown with unpublished photo counts
- A "Publish all" button that writes metadata for every pending photo
- Progress display during the publish run

The page is accessible from the nav menu, placed between "Review people" and
"Photo map".

### Metadata publishing decoupled from naming

`name_face` (naming a single face from the grid) and `name_face_batch` (batch
confirmation from match groups) now only write database records. No JPEG metadata
is touched during the naming workflow. The frontend no longer calls
`publishPerson()` or shows publish status banners — instead it shows a brief
"done" message pointing the user to Publish photos.

### Published-at tracking

A new `published_at` column on `asset_people` tracks when metadata was last
written for each confirmed face. The migration sets `published_at = updated_at`
for all existing confirmed rows so they don't appear as unpublished. New
confirmations start with `published_at = NULL` and get stamped when
`_publish_people_metadata` successfully writes the file.

### Bulk publish endpoint

`POST /api/publish/run` publishes all pending photos (or a filtered set by
person_ids). It uses the same per-photo DB connection pattern from v0.72.1 so
other requests aren't blocked, and logs progress every 25 photos.

## Fixed during testing

The publish page template used double braces `{{...}}` for the `bootstrap_attr`
dict in the f-string, which Python interpreted as a set literal instead of an
f-string expression. Fixed to single braces matching the pattern used by all
other page templates.

The `hidden` HTML attribute on the publish actions div was overridden by
`display: flex` in CSS. Added explicit `[hidden]` selectors to ensure hidden
elements stay hidden.

## Verified

- **Test suite**: 80 tests, all passed.
- **Browser verification**: Publish photos page loads correctly, shows "nothing
  to do" when all confirmed names are already published, nav link appears in
  the correct position between Review people and Photo map.
