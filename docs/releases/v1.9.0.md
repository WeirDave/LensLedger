## Why this release

"Write all tags" kept its progress only in the running server's memory, and
nothing recorded which photos had already been written. A restart part-way
through — including "Restart now" in the "Server is running … on disk"
banner, which did not check for running work — ended the run, and starting
"Write all tags" again began from the first photo and rewrote every one,
taking a fresh safety copy of each.

## What changed

### Write all tags picks up where it left off

- Each photo now records, in the catalog, a fingerprint of exactly what was
  written to it (keywords, people, description, title and write mode) along
  with the file's size and modified time after the write. This is about
  100 bytes per photo.
- A later "Write all tags" run skips a photo when its current tags produce
  the same fingerprint and the file is unchanged. A stopped or interrupted
  run therefore continues with the photos it had not reached yet.
- A photo is written again when any of its tags, people, description or
  title have changed, when the file has changed on disk (edited elsewhere or
  restored from a safety copy), or when the write mode in Settings is
  different from the one used last time.
- The progress line reads "Wrote X of Y photos… (Z already up to date)", and
  the finished message says how many photos already had their tags and were
  skipped.
- The disk-space check before an embedded write no longer counts photos that
  have already been written.
- Photos written before this release have no record yet, so the first run
  after updating writes them once more; runs after that skip them.

### Restart waits for running work

- "Restart now" in the "Server is running … on disk" banner, and "Update
  now" in the update panel, are refused while "Write all tags" or another
  long job — the photo location scan, text recognition, meaning search, face
  detection, classifying photos or "Run all scans" — is running.
- The banner shows which job is still busy, and the "Restart now" button
  stays available for when that job has finished or been stopped with its
  "Stop" button. Stopping "Write all tags" leaves nothing half-written, and
  the next run resumes from where it stopped.

## Verified

- Full test suite: 212 tests, all passing, on Python 3.12.10. New tests
  cover a second "Write all tags" run skipping an unchanged photo, a photo
  being written again after a tag is added, a change of write mode causing a
  rewrite, and "Restart now" being refused while tags are being written.
- Checked in the browser against a generated test library, with the server's
  version and restart replies stubbed: clicking "Restart now" while a job was
  reported busy showed the job name in the banner and re-enabled the button.
