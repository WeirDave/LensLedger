# People index can restore missing links from photo names

## Why this release

- A person's photos are links stored in LensLedger's catalogue, one per photo. When a photo's catalogue entry is removed and added again, which happens when a scan no longer finds a file where it was and cannot match it to a moved or renamed copy, the link is lost. The person's name stays in the photo file, so the photo still has the name as a tag, but the person's card on the people index shows no photo for it.

## What changed

### People index

- A new **Restore from photo names** button sits beside **Tag faces**.
- It looks at the people names saved in each photo file and finds the photos where a person's name appears in the file but LensLedger has no link between the photo and that person. Names match ignoring capitals.
- A window reports how many photos, people and links would be restored. Nothing changes until **Restore** is chosen. If nothing is missing, it says so.
- Restored links count as confirmed photos for the person. The page reloads afterwards.
- Left alone: a person already linked to the photo, a match that was rejected earlier, and photos in the Review Bin.
- Keywords that are not people names are not used, so a person is only linked when the file names them as a person.
- No photo file is rewritten. The restored links are recorded as already published because the file already carries the name.
- A restored link is not tied to a particular face in the photo, so the faces stay in **Tag faces** until they are named there.

### Manual

- Both manuals describe **Restore from photo names** under **Managing people**.

## Verified

- Full test suite: all passing, including new tests for the preview, the restore, matches ignoring capitals, rejected matches, keywords that are not people names, photos in the Review Bin, and running the restore twice.
