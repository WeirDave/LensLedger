## Why this release

The "Compile Python sources" step in the Tests workflow was meant to catch a
syntax error in any program file before a release was built. It named its
files one by one, and the list had stopped growing: it covered 14 of the 25
modules in `src/`. The other 11 (`console_log`, `folder_watcher`,
`ingest_pipeline`, `media_dates`, `metadata_backups`, `person_duplicates`,
`photo_duplicates`, `photo_similar`, `semantic_classify`, `settings_config`
and `xmp_sidecar`) were never compiled by that step. Most are imported by a
test, which is why nothing slipped through, but a module no test imports
could have shipped broken.

It is the same kind of gap as the one behind the 1.13.3 and 1.14.0 ZIPs, which
left modules out and stopped at startup.

## What changed

- The compile step now runs `python -m compileall -q src tests`, so every
  module under `src/` is compiled, including any added later. It no longer
  needs editing when a module is added.
- No program code changed. The release only changes the automated checks, and
  the Release workflow runs the same Tests workflow, so it gets the wider check
  too.

## Verified

- Full test suite on Linux: 311 tests, 305 passing or skipped. The 6 that fail
  fail identically on v1.19.0 in the same environment: five run the bundled
  Windows `ExifTool.exe`, and one is a meaning-search ranking test that depends
  on the host's file-listing order. The Windows CI run is the authority for
  those.
- `python -m compileall -q src tests` run locally on Python 3.11 compiled all
  25 modules and the tests without error. It was not run locally on Python
  3.14; the Windows CI jobs for 3.11 and 3.14 are the check for that.
