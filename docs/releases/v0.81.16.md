## Scan error display overhaul

When a scan produces errors (broken files, unreadable images), the error modal on the Scan photos page previously showed relative paths with forward slashes — unusable on Windows. You couldn't click them, and copying them into Explorer didn't work because Windows expects backslashes and absolute paths.

Error paths are now full absolute Windows paths (`C:\Dropbox\Photos\2019\...`), rendered as clickable `file:///` links that open the file location directly. Each row also has a "Copy path" button, and the "Copy all to clipboard" button now copies full paths.

## GIF exclusion and permanent-error skip in meaning search

GIF files are now excluded from meaning search indexing, matching the exclusion already applied to face detection in v0.81.13. Pillow's CLIP preprocessing cannot reliably decode GIF frames, and these files were producing permanent errors on every scan.

More importantly, meaning search now skips files that previously failed with a `semantic_error`. Before this fix, every scan re-attempted all 60+ broken JPEGs in the library, wasting time and producing the same errors repeatedly. Files with a recorded `semantic_error` are now treated as permanently failed and excluded from future indexing runs.

## Changes

- Error modal paths are now full absolute Windows paths, displayed as clickable `file:///` links
- Added per-row "Copy path" button to each error entry
- "Copy all to clipboard" uses full absolute paths
- Error path text is styled with the accent color and underlines on hover
- Excluded `.gif` files from `semantic_index.build_index()` query
- Added `AND a.semantic_error=''` filter to `build_index()` so previously-failed files are not retried
- Excluded `.gif` from `semantic_index.status()` eligible and unindexed counts
- `semantic_errors()` API returns `full_path` alongside `path`
- `face_scan.list_errors()` returns `full_path` alongside `path`
- `library_errors()` API returns `full_path` alongside `path`
