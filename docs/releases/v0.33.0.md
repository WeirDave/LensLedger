Continuing the Scan photos page work from v0.32.1, this release makes scan
failures visible instead of silent. Previously OCR and face detection both
counted errors internally, but only OCR persisted *which* files failed and
why (`text_data.ocr_error`); face detection just incremented a counter and
threw the reason away. There was also no way to see the failing paths from
the UI at all — just a number.

Added a `face_scan_error` column to `assets` (schema version 10 → 11, with
an automatic migration for existing databases), so face-detection failures
are now recorded per-photo the same way OCR failures already were. Added
`/api/faces/errors` and `/api/ocr/errors` endpoints, and a small modal on
the Scan photos page: clicking an "Errors" tile now lists the affected
files and their error messages instead of just showing a count.

Also tightened the page's information density further: the job
descriptions that used to sit as permanent paragraphs under each card
heading are now collapsed into an "i" info-button popover, and the raw
database/folder paths in the Overview card are tucked behind a
"Database & folder details" disclosure.

## Fixed during testing

Before committing, ran the new feature end-to-end against a scratch
library with fake OCR and face-scan errors seeded directly into the
database. The OCR errors modal worked immediately. The equivalent
face-detection tile did not: it read `faceScan.errors` (the current
session's in-memory job counter) instead of merging in the persisted
database count the way the OCR tile does
(`Math.max(c.ocr_errors || 0, ocr.errors || 0)`). Any face-scan error
recorded in an earlier session — or before the next restart — was
invisible: the tile stayed at 0 and wasn't even clickable, despite
`/api/faces/errors` correctly returning the data.

Added a `face_scan_errors` count to `/api/diagnostics` (mirroring the
existing `ocr_errors` count) and updated the face-detection tile in
`scan-photos.js` to merge it in the same way OCR does.

## Verified

- Built a scratch library and database, seeded a fake OCR error and a
  fake face-scan error directly into the rows, and ran the real server
  against it.
- Confirmed the info popovers open/close on click, outside-click, and
  Escape; the database/folder details disclosure expands; the OCR
  errors modal opens and lists the seeded failure correctly.
- Found and fixed the face-detection errors tile bug described above,
  then re-verified against `/api/diagnostics` (now returns
  `face_scan_errors: 1`) and confirmed the tile renders as a clickable
  button showing the correct count.
