## Motivation

Every GitHub release was showing the title twice — once in the release header (e.g. "LensLedger v0.76.1") and again as an H1 heading at the top of the release body (e.g. "# LensLedger v0.76.1 — Fix accuracy percentage for single-face confirmations"). This didn't match the convention used by WaxFrame Professional, where release notes start directly with content sections and the release title stands alone.

## What changed

- Stripped the `# LensLedger vX.Y.Z — summary` H1 heading from all 104 release notes files that had one (v0.41.3 through v0.80.0). Each file now starts directly with its first content section (e.g. `## Motivation`).
- Updated `.github/workflows/release.yml` — the release title remains `LensLedger vX.Y.Z` (from the tag), and `body_path` points directly to the release notes file without needing to strip the first line.
- Updated `CLAUDE.md` release ceremony instructions to explicitly prohibit leading H1 titles in release notes, matching WaxFrame Pro's convention.

Future releases will display cleanly on GitHub: one title at the top, content body below, no duplication.

## Verified

- Test suite: 88 tests, all passed.
- Spot-checked several release notes files (v0.80.0, v0.77.1, v0.43.18) to confirm H1 lines were removed and content starts with the first section heading.
- Confirmed no `# LensLedger` lines remain in any release notes file.
