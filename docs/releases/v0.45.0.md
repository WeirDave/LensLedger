## Motivation

The Name Faces page showed unidentified faces in newest-first order with no
awareness of similarity.  If a person appeared in many recent photos, the page
would show that same person over and over — forcing the user to type the same
name dozens of times before seeing anyone else.  Meanwhile, the learning pass
(which uses confirmed names to find more matches automatically) only ran when
the user clicked "Find more matches," a button whose purpose was unclear.

The result was a confusing workflow: Name Faces felt like grinding through
duplicates, People Review existed but users didn't know when to go there, and
the learning step that connected the two was invisible.

## What changed

### Diversity sampling on Name Faces

The `/api/faces/unidentified` endpoint now uses greedy diversity sampling
instead of plain newest-first ordering.  It loads a pool of up to 500
unidentified faces, then selects faces one by one, skipping any face whose
embedding is too similar (cosine similarity >= 0.72) to an already-selected
face.  The result is one representative per visual cluster — the user sees a
variety of different people and names each once.

The existing "Also looks like X" match groups already handle the bulk
confirmation: after naming one face, the server finds similar unidentified
faces and presents them for one-click "Confirm all."  Diversity sampling makes
that flow work as intended — name one, confirm the group, move to the next
person.

### Auto-learn on empty queue

Both the Name Faces and People Review pages now automatically trigger a
learning pass when their review queue empties:

- **Name Faces**: when all cards are named/dismissed and no match groups
  remain, the system learns from confirmed faces.  If new suggestions are
  generated, it shows a "Ready for People Review" prompt with a direct link.
  If new unrecognized faces remain, it reloads those instead.

- **People Review**: when the last suggestion is reviewed, the system
  automatically re-learns and reloads.  If the learning pass found more
  matches, the review continues seamlessly.  Only when no new suggestions
  are generated does it show "People review complete."

This creates a natural workflow loop: Name Faces → People Review → repeat
until the system stops finding matches.

## Verified

- Test suite: 79 tests, all passing.
- Name Faces page loads with faces from a variety of different events/dates
  (diversity sampling confirmed via DOM inspection — faces span Holiday party,
  Birthday Trip, Christmas, Thanksgiving, Home Depot, Keith Crosby's Birthday,
  and other distinct events instead of clustering on one person).
- People Review page loads normally with existing suggestion queue.
- No console errors on either page.
