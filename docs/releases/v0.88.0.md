## Motivation

People in LensLedger can have alternate names (aliases) for search, but there was no way to categorize people into meaningful groups — things like "Family", "Friends", "Coworkers", or "The Beatles". Users want to quickly filter the People Index by group membership and search across all photos of people in a group.

## What changed

### Person groups

People can now belong to any number of named groups. Groups are created on the fly — just type a comma-separated list of group names when editing a person, and LensLedger creates the groups automatically.

### Group badges on person cards

Each person's card on the People Index displays their group memberships as small pill-shaped badges below the alias text. Badges use the existing themed badge color variables so they look consistent in both dark and light mode.

### Group filter dropdown

When at least one group exists, an "All groups" dropdown appears in the alpha bar. Selecting a group instantly filters the People Index to show only members of that group, hiding non-matching cards and empty letter headers.

### Search integration

- **People Index search**: typing a group name in the search bar filters to members of that group, alongside the existing name and alias matching.
- **Everything scope**: searching a group name returns all confirmed photos of people who belong to that group.

### Edit modal

The existing "Edit name" modal now includes a third field for groups, positioned between the alias input and the action buttons. Groups are entered as comma-separated values, just like aliases. The modal title was updated to "Edit [name]" to reflect its broader scope.

### API endpoints

Three new endpoints follow the existing person management conventions:

- `POST /api/person/groups` — replace all group memberships for a person
- `GET /api/groups` — list all groups with member counts
- `POST /api/group/delete` — delete a group (cascade removes memberships)

### Database

Two new tables (`person_groups` and `person_group_members`) with a many-to-many relationship. Schema version bumped from 15 to 16. No migration needed — `CREATE TABLE IF NOT EXISTS` handles existing databases.

## Verified

- Test suite: 88 tests passed
- Browser verification (dark mode): created groups via edit modal, confirmed badges appear on person card, group filter dropdown filters correctly, search by group name filters People Index
- Browser verification (light mode): confirmed badge theming works correctly with light-mode color variables
- Search verification: confirmed group name search returns matching people in People scope
