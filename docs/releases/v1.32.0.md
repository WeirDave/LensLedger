# Header shows how many photos need tags

## Why this release

- Nothing on the first screen of the photo viewer showed how much of the library still lacks tags, or offered a way to get to those photos.

## What changed

### Photo viewer

- The header shows a "N need tags" button next to the result summary, for example "11 need tags". Selecting it lists those photos. The button is hidden when every photo has tags, and while the list is already open.
- "Needs tags" is a new choice in the "Search scope" list. It lists the photos that have no tags yet, newest first. Text typed in the search field narrows the list by file or folder name.
- A photo counts as having tags when it has a primary subject, a tag added in LensLedger, a keyword or person name read from the photo's own metadata, or a confirmed person. Tags that were only inferred from the folder name do not count, and neither do tags hidden for that photo.
- Photos in Trash are not counted.
- When no photo needs tags, the list shows "Every photo in this library has tags".
- On phones the button stays in the header at touch-target size, while the result summary remains hidden.

## Not changed

- Search results for the other scopes, and how tags are stored or published.

## Verified

- Full test suite: all passing, including a new test that checks the count, the list, and that folder-derived and hidden tags do not count as tagged.
- Browser check on a desktop-width and a phone-width window: the button appears in the header without changing its height, links to the list, and disappears while the list is open.
