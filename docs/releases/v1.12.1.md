## Why this release

"Write all tags" skips a photo when it was last written with the same tags
and the same choice of embedded tags and sidecar. Moving from the old
"Write mode: Both" to the v1.12.0 defaults, where JPEG, HEIC, PNG, WebP and
TIFF get no sidecar, counted as a different choice for every photo. The next
run would therefore re-embed every photo already written and take a full
safety copy of each one, only to remove its sidecar. In a large library
that is hours of rewriting and a safety copy of the whole library.

## What changed

- **Only the sidecar changes when only the sidecar choice changed.** When a
  photo's embedded tags were written by an earlier run with exactly the
  current tags and the file has not changed since, "Write all tags" does not
  rewrite the photo or take a safety copy. It writes the sidecar if the file
  type's box in "Sidecar (.xmp) files for" (Settings → Metadata publishing)
  is ticked, or moves LensLedger's own sidecar to the safety copies if it is
  not.
- Such photos are counted as "already up to date" in the run summary. Moved
  sidecars are counted separately.
- A photo whose tags have changed is still written in full, as before.

## Verified

- Full test suite: 244 tests, all passing.
- New test: a photo written twice with "Write mode: Both", then switched to
  the default sidecar settings. The next run reports it as up to date,
  moves its sidecar to the safety copies, leaves the photo's bytes
  unchanged, and takes no new safety copy. The run after that reports it as
  up to date with nothing moved. Without the fix, the same run rewrites the
  photo.
- The full suite was also run with every write to the real data folder
  trapped and refused. No test attempted one.
