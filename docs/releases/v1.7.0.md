## Why this release

LensLedger has two manuals: the page at **User Manual** inside the app, and
`docs/user-manual.md` in the project. They are written separately, and neither
had been updated for the features added over the last few days. The manual
people actually read described a version of LensLedger that no longer existed.

## What the manual now covers

- **Meaning search** — what each of the three buttons does, and why "Fill in
  missing" is the one to use when the **Missing** count is not zero, since an
  ordinary run skips photos it has failed on before.
- **Text recognition** — the option to read photos that have already been read.
- **Write all tags** — what it writes, the disk-space check before it starts,
  stopping it part-way, and how files that cannot carry tags are reported.
- **Sidecar files** — what the three write modes do, and that sidecar mode
  carries the same information without modifying originals.
- **Photo safety copies** — what they are, that they are the same size as the
  photos themselves, how to see and clear them, and that clearing one means
  that write can no longer be undone.
- **Stopping a scan** — a new section covering the Pause and Stop buttons and
  what Ctrl+C now does.
- **The log file** — where it is, what it records, and that it contains real
  folder names and photo paths and should be edited before being shared.
- **`--data-dir`** — running LensLedger against a folder of your choosing.

## Fixed

One section was called "Viewing and Editing Metadata" in the app and "Viewing
and Editing Photo Metadata" in the written manual. They now match.

## Verified

- Full test suite: 190 tests, all passing, on Python 3.12.10 — up from 186.
- A new test loads the real manual page from a running server and fails if a
  section of the written manual has no counterpart on it, if a control the app
  offers is missing from either manual, if a contents entry points at a section
  that does not exist, or if the section numbering has gaps or repeats. The
  mismatched section title above was found by that test.
- Renaming a control on the page was confirmed to fail it.
- Checked in a browser: the new sections render, the contents links reach them,
  and the numbering runs in order.
