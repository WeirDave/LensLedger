# Requests from other sites are refused, protective headers on photos

## Why this release

- LensLedger already refused requests that name another host and required a request token on every change. A request that a page on another website makes through the browser was stopped only by that token.
- Pages carry protective headers, but photos, thumbnails and face pictures sent straight from disk carried none, and some carried only part of them.

## What changed

### Changes must come from LensLedger's own address

- Every request that changes something is checked for where the browser says it came from. A request that names any other site, a different port, `https`, or the `null` origin is refused with "request came from another site", and a request the browser marks as cross-site or same-site is refused the same way. The request token is still required.
- Requests that name no origin, such as scripts and command-line tools, are unaffected and are still checked by the token alone. The pages themselves are unaffected, since the browser sends their own address.

### Photos, thumbnails and face pictures

- Files sent from disk (`/media`), thumbnails (`/thumb`), face pictures (`/media-face`) and the progress stream used when confirming matches now carry `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Cross-Origin-Resource-Policy: same-origin` and a content security policy of `default-src 'none'; sandbox`.
- A library file opened directly in a browser tab is therefore never reinterpreted as another file type and cannot run scripts, and another site cannot load or frame it. Photos and videos shown inside LensLedger's pages display as before.

## Not changed

- No setting, database change, or change to how photos are scanned, tagged or published.

## Verified

- Test suite: 582 tests, all passing, including 3 new ones. They cover the origin rules (accepted and refused forms, including a different port, scheme and a lookalike address), requests with and without an origin reaching the token check, and the headers on photos, thumbnails and the original-file fallback.
