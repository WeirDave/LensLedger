## Auto-ingest field alignment fix and Run now button

### Field alignment

The auto-ingest page had a CSS layout issue where the Browse buttons for the Source folder and Destination folder fields wrapped below the input fields instead of sitting inline beside them. The `.field` grid used a two-column layout (`160px 1fr`) but the Browse button was a third element, causing it to overflow onto the next row.

Fixed by adding a three-column grid rule (`.field:has(.field-browse)`) that accommodates the label, input, and button on a single row. The mobile breakpoint was also updated to keep the button inline at narrow widths.

### Run now button

The auto-ingest pipeline previously only ran on a periodic timer (minimum 10-minute interval). There was no way to trigger an immediate run — users had to enable the pipeline and wait for the next tick.

Added a "Run now" button at the bottom of the page alongside "Save configuration". Clicking it triggers an immediate processing pass of the source folder, regardless of whether the periodic pipeline is enabled. The button shows a "Running..." state during execution and displays a toast with results (ingested, duplicates, errors) when complete. The status counters and activity log refresh automatically after a run.

Backend changes:
- Added `run_once()` method to `IngestPipeline` that executes a single `_process_source()` pass and returns the stats delta.
- Added `/api/ingest/run` POST endpoint that calls `run_once()` and returns the results.
