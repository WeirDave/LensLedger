## Why this release

When a log line in the LensLedger console window was longer than the window
was wide, the terminal wrapped the rest of it back to the left edge, under
the column of timestamps. The continuation looked like the start of a new
entry and broke up the timestamp column.

## What changed

- Long lines in the console window are wrapped by LensLedger itself, at the
  window's width when the line is written. Continuation lines are indented to
  start under the message text, so every line that begins at the left edge
  starts with a timestamp.
- Lines that fit are printed as before. Output that is redirected to a file
  or another program, and the log file in the application data folder, are
  not wrapped.
- Lines already printed keep the wrapping they were given if the window is
  resized afterwards.

## Verified

- Full test suite: 229 tests, all passing. New tests check that short lines
  are unchanged, that continuation lines start under the message and stay
  within the width, and that no wrapping happens when output is not a
  terminal or the window is too narrow.
- Wrapped output checked by printing a long "Run all scans" line at a
  110-column width: the second line began under the message text.
