# Biggest groups of unnamed faces first, and faster face matching

## Why this release

Naming people was slow going for two reasons.

- **The order.** The People page picked unnamed faces at random. A stranger who
  appears in one photo was offered as readily as someone who appears in hundreds,
  so naming effort was spread evenly over a very uneven library. The picker also
  treated two faces as "different" up to a similarity of 0.78, while the "Also
  looks like" group joins faces from 0.72, so the same person could appear on
  several cards and each of those cards was a wasted click.
- **The waiting.** Every "Confirm all", "Confirm all remaining" and name click
  searched the library for look-alikes in plain Python, decoding and comparing
  up to 50,000 face records one number at a time. "Learn from confirmed people"
  did the same for every face against every learned person.

## What changed

### Biggest groups first

- The People page now splits a random sample of up to 3,000 unnamed faces
  (one per photo) into groups of faces that look alike, using the same 0.72
  similarity that "Also looks like" uses, and offers one card per group, the
  largest group first. Singletons come last.
- Each card shows a "+N similar" badge. N counts the other unnamed faces in the
  whole library (up to 50,000 are searched) that look like that face, so it
  predicts what "Also looks like" will offer once the card is named. A card with
  no look-alikes shows no badge.
- Faces with unreadable stored data can never join a group, so up to three
  slots per page are kept for them. They stay on the page to be named or
  dismissed instead of lingering in the unidentified count.
- The page's introduction mentions the new order and the badge.

### Faster matching

- Looking for look-alikes after naming a face, "Confirm all", "Confirm all
  remaining", the first-card grouping, and "Learn from confirmed people" now
  compare faces in bulk with NumPy. NumPy is installed with face detection; the
  base install does not have it, and every one of these still works without it,
  using the previous plain-Python comparison. Without NumPy the People page
  keeps its random order and shows no badge, because grouping is too slow there.
- The matches, thresholds and auto-confirm rules are unchanged. Learning from
  confirmed people reached the same decisions as before on the test data
  described below.
- Faces are now compared only with faces whose stored data is the same size.
  Previously a face with a different size of data was compared on whichever
  part of it happened to line up.

### Face cutoff report

- LensLedger calls two faces the same person at a similarity of 0.72 (0.75 and
  0.90 for automatic confirmation). Those cutoffs were set by hand, and nothing
  showed whether they suit a given library: too strict leaves groups small and
  the naming manual, too loose merges different people.
- `src/face_threshold_report.py` measures it. It uses the faces already named as
  the answer key and reports how similar two faces of one person are compared
  with two faces of different people, then what each cutoff from 0.30 to 0.90
  would reach and get wrong. It also reports how many unnamed faces have a
  look-alike at each cutoff. The current cutoffs are marked.
- Run it from the LensLedger folder with the catalogue file, which is
  `.LensLedger\LensLedger-<name>.sqlite3` inside the photo library by default:
  `python src\face_threshold_report.py --db "<that file>"`. `--json` prints JSON,
  `--earliest N` sets the hand-named block size and `--seed` repeats a run.
  It needs NumPy, which face detection installs.
- It opens the catalogue read-only and never changes it. SQLite may leave two
  empty side files (ending in `-wal` and `-shm`) beside the catalogue, which are
  harmless. The output holds only counts, percentages and similarity values: no
  names, file paths, folders, dates, or face or photo numbers, so it can be shared.
- Faces LensLedger confirmed automatically were confirmed because they scored
  high, which flatters the numbers. The report therefore also gives a block for
  each person's earliest-named faces (8 by default), which lean on faces named by
  hand. It cannot see people who have not been named, so a wrong match against
  an unnamed stranger is not counted.

### Updater and CI

- `face_math.py` and `face_threshold_report.py` are part of the release ZIP and required by the updater, so
  an update that lacks it is refused instead of leaving the People page broken.
- The Windows test job installs NumPy, so the fast path is exercised in CI as
  well as the plain-Python path.

## Fixed during testing

- A first full run failed an existing test (`test_release_zip_has_every_module`) because the updater's list of
  required files did not include `face_math.py`. An update that carried the new
  module but not that line would have been accepted; it is now listed and the
  test passes.
- The first version of the grouping took 1.02 s to build one page of cards on
  20,000 faces, against 0.41 s for the old random sample. Skipping a needless
  copy of the matrix and a cheaper length calculation brought that to 0.61 s.

## Measurements

All on generated test data (invented identities as random 512-number vectors,
the same size InsightFace's `buffalo_l` produces). No photo or face from any real
library was used. They show the cost of the work, not how well it suits your
photos.

| What | Before | After |
|---|---|---|
| One similarity pass over 20,000 faces | 1.86 s | 0.08 s |
| Learn from confirmed people, 6,000 faces and 60 people | 12.0 s | 1.16 s |
| Building one page of 30 cards, 20,000 faces | 0.41 s | 0.61 s |
| Distinct people among those 30 cards (150 people, uneven photo counts) | 17 | 30 |
| Share of all photos belonging to the people shown | 53% | 71% |

Learning from confirmed people produced the same 5,280 suggestions and the same
number of automatic confirmations before and after.

The page-build time went up, not down, because it now does the grouping. It is
paid once per page of cards; the waits after each click are where the time was
saved.

## Verified

- Full test suite: 401 tests. 5 of them (publishing tests in `test_server.py`)
  error on the Linux machine this was developed on because the bundled
  `ExifTool.exe` is a Windows program and cannot run there. The same 5 error
  identically on the previous version, before any of these changes. The other
  396 ran: 366 passed and 30 were skipped.
- The new tests (28: 16 for matching and grouping, 12 for the cutoff report) cover the bulk comparison against a plain ranking on both
  NumPy and the fallback, rows that are empty, wrong-sized, all zero or not a
  number being left out, a query of the wrong size being refused, groups coming
  out biggest first, each face joining only one group, the limit on groups, the
  People page offering the biggest group first with the right "+N similar"
  counts, the page working with NumPy switched off, faces with unreadable
  data staying on the page, the cutoff report's numbers on people with known
  similarities, that its output contains no name, path, folder or id, that the
  catalogue file is byte-for-byte unchanged by a run, and clear messages for a
  missing catalogue, an old catalogue, too few named people, and no NumPy.
  A deliberate change that reversed the group order made the new page test fail,
  and it passed again once restored.
- The face, learning, duplicate and server tests were re-run with NumPy made
  unavailable: the same 5 errors and nothing else, with only the NumPy-specific
  tests skipped.
- The cutoff report was run on a generated library of 7,400 faces (60 invented
  people with 40 named faces each, plus 5,000 unnamed). It took about 6 seconds,
  its figures matched how the data was built (same-person pairs centred on 0.72,
  so 53% were reached at the 0.72 cutoff), the catalogue's checksum was the
  same afterwards, and the output contained none of the invented names or
  folder names.
- Checked in a browser against a generated test library of 66 invented faces
  (three identities of 40, 15 and 5 photos plus six strangers): the first three
  cards showed "+39 similar", "+14 similar" and "+4 similar", the strangers had
  no badge, and the badge and layout were correct in the light and dark themes.
