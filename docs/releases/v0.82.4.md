## Summary

Follow-up to v0.82.3. The error path links were changed from broken `file:///` anchors to `href="#"`, which showed `#` in the status bar and still didn't open anything useful. The path text is now plain (not a link), and a dedicated "Open folder" button opens the containing folder in the OS file manager.

## What changed

- **Frontend**: The path in error rows is now a plain `<span>` instead of an `<a>` link. Added an "Open folder" button next to "Copy path" that calls `/api/reveal-path` to open the containing folder.
- **Server**: The `/api/reveal-path` endpoint now opens the parent folder directly (not the file with `/select,`), matching the user's expectation for error files — you want to see where it is, not open a broken image.
