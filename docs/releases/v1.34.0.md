# Thumbnails in photo lists, a faster metadata reader, safer import

## Why this release

- Photo lists and people cards loaded each full-size original, and each HEIC photo was converted to JPEG again on every request.
- Reading embedded tags took time proportional to the square of the metadata block's size when the block held many tags that were never closed, and photos in HEIC, PNG, WebP and TIFF were read into memory whole to find that block.
- **Import database** and **Empty trash** relied on the file locations recorded in the imported database without checking them.
- A person's name was placed into the photo viewer as markup instead of as text.

## What changed

### Photo lists and cards

- The strip of photos under the viewer, the photo on each person's card, the two cards in the **Possible duplicates** comparison, the **Card photo for** picker, the avatars in **Manage groups** and the photos in **People review** now load thumbnails instead of the originals. Opening a photo in the viewer or its full-size lightbox still loads the original.
- Thumbnails come in three sizes (160, 320 and 640 pixels on the longest side). A request is answered with the smallest size that is at least as large; a request for more than 640 pixels, a photo that cannot be shrunk, and anything that is not an image are answered with the original file.
- Each thumbnail is made the first time it is needed and kept in a new `Thumbnails` folder inside the application data folder. Its file name comes from the photo's location, size and modified time, so an edited photo gets a new thumbnail. The folder is kept under about 1 GB by removing the oldest thumbnails first; deleting any of them is safe, as they are made again. The folder is listed under **Data directory** in the manual.
- A new `/thumb?id=` address serves them, subject to the same checks as photo files.

### Embedded tag reading

- Photos whose metadata holds many unclosed tags are read in time proportional to their size.
- Photos in HEIC, PNG, WebP and TIFF are read in 1 MB pieces rather than into memory whole. A metadata block larger than 16 MB is skipped. The tags read from ordinary files are unchanged.

### Import and the Review Bin

- **Import database** in **Settings** checks the database in the ZIP before replacing the current one and refuses one that is damaged, is not a LensLedger catalog, or is newer than the installed version supports. The current database is left as it was.
- Pickle files (`.pkl`, `.pickle`) inside an export's `FaceData` folder are no longer imported. The message after the import says how many were skipped.
- **Empty trash** and **Delete** in **Trash & restore**, and restoring a photo, now act only on files inside the Review Bin folder. An entry that names a file elsewhere is left alone and reported. **Empty trash** shows how many entries were left alone.

### Photo viewer

- A person's name shown on a face box in the viewer is displayed as text, so characters such as `<` and `&` appear as typed.

## Not changed

- No setting, database change or change to how photos are scanned, tagged or published.
- Photo, video and RAW files are not touched. The first time a list is opened after updating, thumbnails are made as the photos scroll into view.

## Verified

- Test suite: 579 tests, all passing, including 18 new ones. They cover the metadata reader on files with many unclosed tags and across read boundaries, the Review Bin and import checks, the thumbnail sizes, caching, fallback and trimming, and the viewer name.
