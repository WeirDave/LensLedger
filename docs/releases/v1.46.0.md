# Meaning search uses an NVIDIA graphics card when there is one

## Why this release

- Meaning search ran on the processor even on computers with an NVIDIA graphics card. The standard Windows install of PyTorch has no graphics-card support, and nothing in LensLedger detected the card or said which device was in use. Indexing a large library took hours.

## What changed

### Setup

- Setting up meaning search on Windows now looks for an NVIDIA card. When one is found, LensLedger downloads the PyTorch build that can use it (about 2.5 GB, from PyTorch's own download site) before installing the rest of the meaning-search software. The build is chosen from the CUDA version the installed driver supports. If that download fails, setup continues with the processor version.

### Scan your photos

- The status line under **Meaning search** now ends with what meaning search runs on: "Using your graphics card (name)", "Using the processor", or, when a card was found that the installed PyTorch cannot use, a sentence saying so. The same line is written to the activity log when indexing starts.
- A new **Use my graphics card** button appears beside **Pause** under **Meaning search** only in that last case. After a confirmation it restarts LensLedger, downloads the graphics-card build of PyTorch while the terminal window shows progress, and opens again when done. If the download fails, meaning search keeps using the processor and the button remains. It is unavailable while a scan is running.

### Speed

- On a graphics card, photos are encoded in batches of 64 (previously 16) in half precision. Vectors differ from the processor's only in the fourth decimal place, so photos already indexed do not need indexing again.
- The photos of each batch are opened and shrunk side by side, on the processor as well as on a graphics card.

### Manual

- Both manuals describe the graphics-card behaviour and the **Use my graphics card** button under **Meaning search**.

## Verified

- Full test suite: all passing. New tests cover reading the CUDA version from both header styles `nvidia-smi` prints, choosing the PyTorch build for a driver, deciding when a switch is offered, the pip arguments, carrying out a queued switch once at start, and the device status lines.
