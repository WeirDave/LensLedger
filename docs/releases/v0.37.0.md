The OCR, meaning search, face detection, and "Run all scans" sections of
the Scan photos page all had progress bars with percentage and ETA. The
photo locations (GPS) scan and the onboarding library scan did not — they
showed only elapsed time or an endlessly-animating indeterminate bar,
giving no indication of how far along the scan was or how long it would
take.

## What changed

### Backend: total_estimate in library scan progress

`scan_library()` in `photo_index.py` now includes `total_estimate` — the
count of known assets in the database before scanning — in every progress
callback. On a first-time scan this is 0 (no prior data), but on any
rescan it gives a reliable estimate of how many files will be visited.

### Scan photos page: location scan progress bar

Added a `<div class="progress-bar">` to the Photo locations section of
the scan page HTML. The JS now uses `total_estimate` to:

- Show a determinate progress bar with percentage when the estimate is
  available (rescans)
- Show an indeterminate (animated) bar when it is not (first scan)
- Show an ETA ("~Xm Ys remaining") once enough elapsed time has passed
  to extrapolate

### Onboarding page: determinate progress bar

The onboarding scan always showed an indeterminate sliding-gradient bar.
Now, when `total_estimate > 0` (user is re-scanning or resuming), the bar
switches to a determinate fill with percentage and ETA. The progress
message updates to show "X% · N of ~M files — ~Xm Ys remaining" instead
of just the generic "Discovering photos…" text.

The CSS was updated to start the bar at `width: 0` by default and only
apply the sliding animation when the `.indeterminate` class is present.

## Verified

- Test suite: 79 tests, all passing (the new `total_estimate` field
  appears in test output as `total_estimate: 0` for first-time scans).
- Browser testing: started a location scan on a 50,909-file library.
  The elapsed text showed "0%" initially and the progress bar appeared.
  The scan completed quickly (all files unchanged) so no ETA was shown
  (ETA requires >3 seconds elapsed and some files remaining). Ran "Run
  all scans" which exercised all four scan types in sequence — progress
  bars, step counts, and elapsed times all displayed correctly with no
  JS console errors.
