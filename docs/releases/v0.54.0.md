## Motivation

A comprehensive UX audit from a customer standpoint revealed that the product was missing basic orientation cues: the navigation menu had no indication of which page you were on, the current photo library was never shown anywhere outside the home page summary line, and several settings lacked context that would help a first-time user understand what they do.

The user specifically called out: "we don't even show the current photo library folder in the settings!"

## What changed

### Active-page highlighting in navigation menu

Every page now passes its identity to the shared `nav_menu()` function. The current page's link gets an accent-colored left border and bold text, so users always know where they are when they open the menu.

### Library path visible on every page

The navigation menu now shows the current library name at the bottom of the panel, with the full path available as a tooltip on hover. The `nav_menu()` function accepts `current_page` and `library_root` parameters — all seven page renderers pass both.

### Settings library list shows full paths

The library list in Settings previously showed only the leaf folder name (e.g. "Photos"). It now shows the full path (e.g. "C:\Dropbox\Photos"), making it clear which folder each entry refers to — especially useful when multiple libraries share the same leaf name.

### Confirmation dialogs for destructive actions

Switching libraries and removing libraries from the list now prompt for confirmation before proceeding. The prompts explain what will happen (switch keeps the old library in the list; remove only deletes the entry, not photos or index data).

### Help text improvements

- **Database export/import** in Settings now has an introductory paragraph explaining that export creates a portable copy of tags, people, and scan results — useful for backups or moving to a new machine — and that photos are not included.
- **OCR "Only since"** date field has a tooltip explaining it skips photos taken before the selected date.

### Map empty-state link fix

The empty-state message on the Photo Map previously linked to the home page (`/`). It now links to `/scan-photos`, which is the action the user actually needs to take to populate the map.

## Verified

- Test suite: 79 tests passed
- Browser verification: Settings page renders with full library paths, active menu highlighting works on home, scan, settings, and auto-ingest pages, library name and path display in menu footer on all pages, no console errors
