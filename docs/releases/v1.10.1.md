## Why this release

A restart from "Restart server" in the menu, "Restart now" in the "Server is
running … on disk" banner, or "Update now" could leave LensLedger stopped
with no window open. Since v1.8.2 the old LensLedger window closes itself as
soon as its server stops for a restart. The new LensLedger window is opened
at that same moment, and in Windows Terminal, when the old window was the
last tab, closing it could shut down the Terminal window while the new tab
was still being handed to it. The new LensLedger then never started.

v1.10.0 addressed a different possible cause (the restart closing a new
window that inherited the old window's process number). That check remains,
but it did not stop this.

## What changed

- After a restart, the old LensLedger window stays open for about five
  seconds, showing "Restarting LensLedger in a new window...", and then
  closes itself. The new window is already open by then.
- The restart waits up to 15 seconds for the old window to close on its own,
  and only closes it by force if it is still open after that (as happens with
  a "Start LensLedger.cmd" from before v1.8.2, which waits at "Press any key
  to continue").

## Verified

- Full test suite: 218 tests, all passing, on Python 3.12.10. The updated
  tests check that the restart opens the new window, then waits for the old
  one, and only then closes it if it is still there.
- Restarted a running LensLedger on Windows 11 in Windows Terminal through
  "Restart server" twice in a row. Each time it was answering again within
  four seconds, and afterwards exactly one LensLedger window and one server
  process remained. Before this change, the same restart left no LensLedger
  running.
