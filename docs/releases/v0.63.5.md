# LensLedger v0.63.5

## Auto-import: remove library-wide hash scan

### The problem

v0.63.4 cached the destination hash index but still built it on first run — hashing all 50K+ photos in the library, which took minutes and blocked the import from actually doing anything. The entire duplicate-detection-by-hash approach was wrong for this use case: auto-import moves files from Camera Uploads into date-sorted subfolders. If a file with the same name already exists at the destination, just append a numeric suffix (`_1`, `_2`, etc.) — which the code already did after the hash check.

### What changed

- **Removed the destination hash scan entirely.** No hashing of source or destination files. Import starts instantly regardless of library size.

- **Removed duplicate tracking stats** from the pipeline, the status page, and the "Run now" toast.

- **Filename collisions** are still handled by the existing counter suffix logic — if `photo.jpg` already exists at the destination, it becomes `photo_1.jpg`.

- **Kept all the v0.63.4 visibility improvements**: error logging, cloud placeholder logging, upload-in-progress logging, candidate count.
