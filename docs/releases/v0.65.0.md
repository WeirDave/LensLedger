## Motivation

The Review People page showed 8 large full-photo cards at a time, each repeating the filename, date, and folder path. Users had to scroll through many batches to review a single person. Meanwhile, the Name Faces page already proved that compact face crop thumbnails let you process faces much faster.

## What changed

### Compact thumbnail grid

The Review People page now displays up to 100 face crop thumbnails in a dense flexbox grid instead of 8 large photo cards. Each thumbnail is 120px wide with a square aspect ratio, showing just the cropped face. Confirmed faces have a green border; rejected faces get a red border with reduced opacity.

- Click a thumbnail to toggle between confirmed and rejected.
- Hover to reveal the Enlarge button (top-right) and disposition button (bottom-right).
- The status bar shows "X confirmed · Y rejected" counts that update live.

### Enhanced lightbox

The Enlarge button opens the existing lightbox overlay with new additions:

- **File info**: filename and date displayed at top-left so you can identify the photo without leaving the lightbox.
- **Toggle button**: "Mark as wrong" / "Mark as correct" to flip the decision from inside the lightbox.
- **Correct name**: a person picker input appears when the face is marked wrong, letting you assign the correct name directly in the lightbox.
- **Disposition buttons**: "Not a person" and "Unknown person" for edge cases.

### Batch limit increase

The server-side batch validation limit was raised from 8 to 200 for both the decision and undo endpoints, matching the new frontend capacity.

### Terminal logging

All people review decisions now print to the terminal with the `[Name faces]` label:

```
[Name faces] Confirmed "William George Peters Jr." in dscf0010_1.jpg
[Name faces] Rejected "William George Peters Jr." in IMG_2044.jpg
[Name faces] Corrected "William George Peters Jr." → "David Paine" in DSC_0123.jpg
[Name faces] Marked not a person in blurry_shot.jpg
[Name faces] Marked unknown person in crowd_photo.jpg
```

Both the batch endpoint (`/api/people/review/batch`) and single-decision endpoint (`/api/people/review/decision`) log consistently.

## Files changed

- `src/photo_search.py` — batch limit 8→200, filename lookup + print logging in both decision handlers, lightbox HTML updated with info/toggle/correction elements
- `web/js/people-review.js` — rewritten: compact `buildCard()` with face crops, click-to-toggle, enhanced `openLarge()` with info/toggle/correction, `maxVisible` raised to 100
- `web/css/people-review.css` — replaced large card grid with `.thumb-grid`/`.review-thumb` compact layout, added lightbox info/correction styles, updated mobile breakpoint
