## Fix: the release ZIP was missing program files

The downloadable ZIP named its program files one by one and had not kept up
with the program. The ZIPs for 1.13.3 and 1.14.0 contained 14 of 23 modules:
`console_log`, `settings_config`, `folder_watcher`, `ingest_pipeline`,
`metadata_backups`, `person_duplicates`, `photo_duplicates`,
`semantic_classify` and `xmp_sidecar` were left out. A copy installed from
one of those ZIPs stopped at startup with `No module named 'console_log'`,
and the in-app updater would have replaced a working managed install with
one that cannot start, because it only checked for a handful of files.

- The ZIP now includes the whole `src` folder, so a new module cannot be
  left out again.
- The in-app updater's list of files a download must contain now names every
  module, so an incomplete download is refused instead of installed.
- A test reads the packaging step and the updater's list and fails if either
  leaves out any file in `src`.
- **Releases 1.15.0 and 1.16.0 are included in this one.** Copies of 1.13.3
  or 1.14.0 that are git checkouts, or run from a source folder, were not
  affected.

## Why the main change


**Exact duplicates** only finds files that are identical byte for byte. The
copies that clutter a real library are usually not: the same photo shared and
saved at a smaller size, re-exported at a different quality, or one of ten
near-identical frames from a burst. None of those appear in **Exact
duplicates**, so they could only be found by eye.

## What changed

**Search scope → Similar photos**

- New **Search scope** option, **Similar photos**. It lists photos that look
  alike without being the same file. Each set is shown together in the
  filmstrip, separated by a bar and labelled "1 of N", exactly like the sets
  in **Exact duplicates**.
- The largest file in a set is listed first, since a resized or recompressed
  copy is smaller than its original. Names marked as a copy go last.
- A set made only of byte-identical files is not listed here; it is already
  in **Exact duplicates**.
- Typing part of a folder or file name narrows the list to sets with a photo
  whose path contains it, and still shows the whole set.
- Select the extras with Ctrl+click and choose **Trash selected**; the
  review bin and **Undo** work as before.

**How photos are compared**

- Each photo gets a 64-bit fingerprint of its pattern of light and dark
  (a difference hash of a 9×8 greyscale thumbnail, after applying the
  photo's orientation flag). Two photos are grouped when at most 5 of those
  64 bits differ. Resizing, recompression and small edits change only a few
  bits; different photos differ in roughly half.
- Nearly flat pictures (a blank wall, a black frame) are never grouped, since
  every flat picture would match every other.
- Because the fingerprint ignores colour, a colour photo and a
  black-and-white version of it match. Two plain pictures with the same
  layout can also match, so each set is worth a look before anything is
  trashed.
- Videos and RAW files have no fingerprint and are not compared.

**Scanning**

- The fingerprint is computed during the library scan. Libraries indexed by
  an earlier version are fingerprinted on their next scan, which decodes each
  photo once. On the test machine this took about 0.05 seconds for a
  12-megapixel JPEG, so a library of 10,000 photos adds about ten minutes to
  its next scan. It happens once; later scans only fingerprint new and
  changed photos.

**User manual**

- Search scopes describes **Similar photos** in the written manual and the
  in-app manual.

## Verified

- A ZIP built with the release step's own command extracts to every module and
  starts (`LensLedger 1.17.0`); the published 1.14.0 ZIP fails on import.
- New test: every file in `src` is in the ZIP and in the updater's required
  list. It fails against the previous packaging step.
- 10 new tests: a resized, recompressed and lightly edited copy staying within
  the threshold while another photo does not; a copy stored with an
  orientation flag matching the upright one; files that cannot be decoded
  getting no fingerprint; the smaller copy grouped under the original; flat
  pictures matching nothing; the name filter keeping whole sets; a photo in
  the review bin leaving its set; a library indexed earlier gaining
  fingerprints on the next scan; the scope over HTTP, with an exact pair left
  out.
- Each rule was checked to fail with it removed: the distance threshold, the
  flat-picture rule, the exact-pair exclusion, the orientation flag and the
  backfill. Two of these first survived because the test data was too easy;
  the tests were tightened until they failed.
- In Chromium against a synthetic library: the scope listed resized copies
  with their originals, and a rescan of a database built before this release
  filled in every fingerprint.
