## Summary

v0.81.17 added `LOAD_TRUNCATED_IMAGES` so Pillow tolerates damaged JPEG
streams, but photos that had already failed with "broken data stream" were
permanently stuck — face detection skipped them because `face_scanned` was
already set, and meaning search skipped them because `semantic_error` was
non-empty.

## What changed

`photo_index.py` now clears "broken data stream" errors at database open time:

- Resets `face_scanned=0` and `face_scan_error=''` for any asset whose
  face scan error contains "broken data stream."
- Resets `semantic_error=''` for any asset whose semantic error contains
  "broken data stream."

These UPDATEs are idempotent — once the errors are cleared, subsequent
startups match zero rows. A `con.commit()` follows immediately so the
implicit transaction does not interfere with later `BEGIN IMMEDIATE` calls.

## Fixed during testing

The initial version omitted `con.commit()` after the UPDATE statements.
Python's sqlite3 module auto-starts an implicit transaction for DML, and
the merge-people endpoint's `BEGIN IMMEDIATE` failed with "cannot start a
transaction within a transaction." Adding the commit resolved this.

## Verified

- Full test suite: 88 tests, all passing.
- Confirmed the merge-people test that was broken by the missing commit now
  passes consistently.
