## Fix folder watcher causing "database is locked" during scans

When meaning search (or OCR or face detection) was running and the folder watcher's timer fired, the watcher would start a library scan concurrently. Both operations wrote to the SQLite database at the same time, and since WAL mode only allows one writer, the 30-second busy timeout would expire and the active scan would fail with "database is locked."

### Root cause

The `watcher_scan()` function only checked whether a library scan was already in progress (`library_job` state). It did not check whether any other scan type — meaning search, OCR, face detection, or "run all scans" — was active. When the watcher timer fired during one of those scans, it proceeded to call `scan_library()`, creating two concurrent database writers.

### Fix

Added checks for all scan job states (`scan_all_job`, `semantic_job`, `ocr_job`, `face_scan_job`) to `watcher_scan()`. If any scan is running, the watcher silently skips and tries again at the next interval. Each check acquires the appropriate lock to safely read the job state.
