After the v0.95.0 globe release, photo markers failed to appear on initial
page load. The globe rendered correctly but no location markers were visible
until the user interacted with the page.

## What was wrong

The viewport element had zero height when the fetch callback fired during
initial page load — the browser hadn't finished CSS layout yet. The
`clusterPoints()` function projects 3D sphere positions to 2D screen
coordinates using `viewport.clientWidth` and `viewport.clientHeight`. With
height 0, every point projected to `y = 0`, collapsing all 4,026 locations
into a single grid cell and producing one giant cluster instead of 29.

A secondary issue: `requestAnimationFrame` callbacks stop firing when the
browser tab is inactive or hidden, so the animate loop's recluster logic
could never recover from the bad initial render.

## What changed

Two fixes in `web/js/map.js`:

1. **`scheduleRecluster()` now includes a `setTimeout` fallback.** When
   `needsRecluster` is set, a `setTimeout(…, 80)` fires as a safety net.
   The callback skips work if the animate loop already handled it, or if the
   viewport still has zero height. When it does run, it calls
   `updateCamera()` and `renderer.render()` to ensure fresh projection
   matrices before rendering markers. This handles both the stalled-rAF case
   and the zero-height-viewport race.

2. **`window.onresize` now triggers a recluster.** When the viewport gains
   its real dimensions (or changes size), markers re-render with correct
   screen projections.

3. **`needsRecluster` starts as `false`.** No wasted render attempt before
   data has loaded.

## Verified

- Full test suite: 101 tests passed
- Visual verification in browser: markers appear correctly on fresh page load
  with 29 visible clusters across the Americas, Europe, and Asia
- Verified in both dark and light themes
