## Why this release

Three problems showed up when installing LensLedger fresh and pointing it at
a library of ordinary camera and phone files.

- **Most photos had no date.** A photo's date came only from a date written
  into its file or folder name. Cameras and phones name files `IMG_1234.jpg`
  or `DSC01234.JPG`, so in a typical library almost every photo showed
  "Date unknown", and the date filter, **◀ Day** / **Day ▶** and
  **Newest first** / **Oldest first** did nothing useful — even though the
  date the photo was taken sits in its EXIF data, which the scan already
  opens to read GPS.
- **There was no way to find duplicate photos.** Every scan already
  fingerprints each file, but nothing used that to show copies.
- **A new installation scanned a folder nobody chose.** Automatic folder
  watching is on by default, and its first check ran about 30 seconds after
  launch against the startup guess — the Pictures folder, or the home folder
  when there is none — before the setup page had been answered. It indexed
  and text-scanned that folder, left a hidden `.LensLedger` folder inside it,
  and recorded it as a library, so the next visit opened on "Welcome back —
  your library couldn't be found" instead of setup.

## What changed

**Dates**

- A photo's date is now the date it was taken: EXIF `DateTimeOriginal`,
  then `DateTimeDigitized`. When neither is present, a date in the file or
  folder name is used as before; failing that, the EXIF date the file was
  last saved by an editor.
- Dates in camera and phone file names without separators are recognised:
  `IMG_20240704_120000.jpg`, `PXL_20240704_…`, `20240704_120000.mp4`,
  `Screenshot_20240704-…png`.
- A camera with an unset clock (`0000:00:00`) or a date in the future no
  longer produces a date.
- Libraries indexed by an earlier version are re-dated on their next scan,
  once per photo, without rewriting anything else. The automatic folder
  check does this within a few minutes of updating.

**Exact duplicates**

- New **Search scope** option, **Exact duplicates**, also in the menu as
  **Duplicate photos**. It lists every photo stored more than once,
  byte for byte. Each set of copies sits together in the filmstrip, with the
  likely original first: names marked as a copy (`(copy)`, `Copy of`,
  `(2)`) go last, then the shortest name.
- To remove extras, Ctrl+click them in the filmstrip and choose
  **Trash selected**. They go to the review bin, so the removal can be
  undone; a set with only one copy left outside the bin drops off the list.
- Typing part of a folder or file name narrows the list to sets with a copy
  whose path contains it, and still shows the whole set.
- Only files that are identical throughout are listed. The fingerprint each
  scan stores covers the start of the file and its size, so it is used to
  find candidates and a full-file comparison decides. A photo that has had
  tags written into one copy is no longer byte-identical and is not listed.

**First run**

- Until a library has been chosen, the app always opens on setup, writes
  nothing into the Pictures or home folder, and the automatic folder check
  skips with "Automatic check: skipped — no photo library has been chosen
  yet" in the console.
- Installations that already have a library are unaffected.

**User manual**

- Search scopes, date sources and the duplicate workflow are documented in
  both the written manual and the in-app manual.
- The folder-watching defaults now match the app: on, every 5 minutes. The
  manual previously said off, every 30 minutes.

## Verified

- 13 new tests, all passing: EXIF date taken from a camera-named file;
  date taken beating a folder date; folder date beating an editor's save
  date; an unset camera clock giving no date; compact phone file names;
  an existing library re-dated on rescan; identical files grouped with the
  original first; two files that share the stored fingerprint but differ
  later not reported; a copy in the review bin ending the set; the
  name filter keeping whole sets; the duplicates scope over HTTP; the first
  page load before setup writing nothing into the guessed folder; a recorded
  library counting as chosen.
- Each new test was checked to fail with its feature removed.
- Full suite on Linux: 279 tests, the same 7 Windows-only tests failing as
  before this change (they need the bundled `ExifTool.exe` or Windows OCR);
  the Windows CI run covers them.
- In Chromium against a synthetic library of 78 generated camera-style
  files with EXIF dates and six exact copies: every photo dated after a
  rescan of a database built by v1.13.3; **Newest first** in date order;
  **Exact duplicates** showing six sets, original first; Ctrl+click on a
  copy and **Trash selected** removing that set from the list.
- A fresh installation with photos in the home Pictures folder: two loads
  of the home page showed setup, the automatic check at 30 seconds
  skipped, and the Pictures folder was left unchanged.
