## Why this release

"Find duplicates" on the People page compared every word of a name,
including text after a comma. Names written as "Name, Band" or
"Name, Role" describe the person after the comma rather than naming them.
Anyone whose alternate name was that description (a band name, for
example) was then paired with every other person who shared it, under
"One name is part of the other".

## What changed

**People page — "Find duplicates"**

- Only the part of a name before the first comma is compared.
  "Aldo Brennick, The Lanterns" and "Mira Castellan, The Lanterns" are no
  longer paired, and neither is paired with someone whose alternate name is
  "The Lanterns".
- "Aldo Brennick, The Lanterns" and "Aldo Brennick" are now listed as
  **Same name**.
- A generational suffix after a comma, as in "Aldo Brennick, Jr.", is still
  part of the name, so a "Jr." and a "Sr." are still never paired.
- The reason "Same name apart from punctuation, accents or capitals" now
  reads **Same name**.

## Verified

- Full test suite, all passing.
- New test: shared text after a comma does not pair two people, a name with
  and without a description matches as the same name, and a "Jr." after a
  comma still keeps a Jr/Sr pair apart.
- Run read-only against a copy of a real library's database: the pairs
  that came only from shared text after a comma were gone, and the
  remaining pairs were all plausible duplicates.
