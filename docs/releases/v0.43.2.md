# LensLedger v0.43.2 — Fix trash deletion hang

## What was wrong

Clicking "Empty trash" or the per-item "Delete" button in the trash panel
appeared to hang: the button would disable after confirmation but nothing
else happened — no reload, no error message, no progress.

## Root cause

Both `empty_review_bin` and `delete_from_review_bin` in the server executed
`DELETE FROM faces WHERE asset_id=?`, but the table is actually called
`face_embeddings`. The nonexistent table name caused a `sqlite3.OperationalError`,
which the server caught and returned as a 500 JSON error. On the JS side,
neither the "Empty trash" nor the single "Delete" button had a `try/catch`
around their `await api(...)` call, so the thrown error was silently swallowed
— leaving the button disabled with no feedback.

## What changed

- **Server** (`src/photo_search.py`): Changed `DELETE FROM faces` to
  `DELETE FROM face_embeddings` in both `delete_from_review_bin` and
  `empty_review_bin`.
- **Server**: Added `DELETE FROM search_fts WHERE asset_id=?` to both
  methods. The FTS virtual table has no foreign-key cascade, so deleting
  the `assets` row left orphan search-index entries behind.
- **Frontend** (`web/js/viewer.js`): Wrapped the "Empty trash" and
  single-item "Delete" button handlers in `try/catch` blocks that
  re-enable the buttons and call `setStatus(e.message, true)` on failure.

## Verified

- Full test suite: 79 tests passed.
