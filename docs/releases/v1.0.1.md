## Summary

When files are moved or renamed in the photo library, LensLedger's inventory scan detects the move and updates the file path in the database. However, the meaning search error column (`semantic_error`) was not being cleared during this update. This caused two visible problems:

1. **Stale error paths**: The error dialog showed the file's *current* path at the top of each error card, but the error message text still contained the *old* path from when the indexing originally failed. For example, a file now at `2018\...` would show an error referencing `2017\...`.

2. **Permanently stuck errors**: Because `semantic_error` was never cleared on move, these files were excluded from re-indexing (`WHERE semantic_error=''` filter in `build_index()`), so they could never succeed even though the file now existed at the updated path.

A secondary cosmetic issue: Python's `OSError` string representation escapes backslashes (`C:\\Dropbox\\` instead of `C:\Dropbox\`), making Windows paths in the error detail harder to read.

## Changes

**Backend — `src/photo_index.py`**: Added `semantic_error=''` to the UPDATE statement that fires when a file move is detected (alongside the existing `scan_error=''` clear). Moved files are now re-queued for meaning search indexing at their new path.

**Frontend — `web/js/scan-photos.js`**: The error detail text now normalizes double backslashes to single backslashes before display, so Windows paths read naturally.
