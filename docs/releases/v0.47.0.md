# LensLedger v0.47.0 — Clickable scan errors and better error reporting

## Motivation

When scans completed with errors, the user had no way to find out what went wrong. The Errors count was visible but not clickable for photo location and meaning search scans, there was no API to retrieve error details, and completion messages said nothing about errors. The meaning search section showed "66 remaining" permanently with no explanation — these were files the model could not encode, but they were counted as "remaining" rather than "failed," giving the impression the scan was stuck or incomplete.

## What changed

### Clickable error metrics across all scan types

- **Photo locations (GPS):** the Errors metric is now a clickable button that opens a modal listing every file that failed during the scan, with the error message for each. Errors are stored per-file in a new `scan_error` column on the `assets` table and served via a new `/api/library/errors` endpoint.
- **Meaning search:** the Errors metric is now clickable, showing which images the model could not encode. Failures are tracked in a new `semantic_error` column on the `assets` table and served via a new `/api/semantic/errors` endpoint.
- **OCR and face detection** already had clickable errors — no changes needed there.

### Fixed "remaining" count in meaning search

Files that the meaning-search model cannot encode are now correctly classified as "failed" rather than "remaining." The Remaining count reaches 0 when indexing is truly done, and the failed count appears in the Errors metric. This resolves the "66 remaining with nothing happening" problem.

### Better completion messages

All scan types now report error counts in their completion messages when errors occurred:
- Photo locations: "Scan complete with N errors — click the Errors count below for details."
- OCR: "OCR complete with N errors — click the Errors count below for details."
- Meaning search: "Meaning index complete with N errors — some images could not be indexed."
- Face detection: "Face detection complete with N errors: X faces found — click the Errors count below for details."
- Run all scans: reports the total error count across all sub-scans.

### Database schema additions

- `assets.scan_error` — stores per-file errors from the photo location scan (cleared on successful re-scan).
- `assets.semantic_error` — stores per-file errors from meaning search indexing (cleared on successful re-indexing).
- Both columns are added via idempotent ALTER TABLE migrations on first connect.

## Verified

- Test suite: 79 tests, all passing.
- Browser verification: confirmed the scan page renders correctly, API endpoints return correct data (`/api/library/errors` returns 0 errors, `/api/semantic/errors` returns 66 errors with file paths), and the error count logic produces the correct values (verified via JavaScript injection against the live page).
