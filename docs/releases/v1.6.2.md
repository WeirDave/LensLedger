## What changed

**"Restore last publish" no longer offers what it cannot do.** The button on a
photo was enabled whenever LensLedger had a record of writing to that photo,
without checking that the safety copy it would restore from was still there.
Safety copies are now cleared automatically once they pass the age or size
limits, so the button could outlive the copy behind it and fail when pressed.
It is now offered only when the copy still exists.

**The safety-copy limits say what they cost.** Both settings under "Metadata
publishing" now state that once a copy is cleared, that write can no longer be
undone. The limits exist so the copies cannot fill the disk, but the trade-off
was not written down anywhere the reader would see it.

## Verified

- Full test suite: 186 tests, all passing, on Python 3.12.10 — up from 180.
- New tests write to a real photo and then restore it, confirming the file
  comes back byte for byte, that restoring twice is refused rather than
  quietly doing nothing, and that a restore attempted after the copy has been
  cleared explains itself.
- Further tests check the button's availability directly: not offered before
  anything is written, offered once a copy exists, and no longer offered once
  the copies are cleared. Restoring the old behaviour was confirmed to fail
  that last one.
