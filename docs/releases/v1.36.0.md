# Auto-import skips known files and dates videos correctly

## Why this release

- Auto-import moved every new file it found, even when a byte-identical copy was already in the library, and added a numeric suffix to the name when the destination already held a file of that name. Re-uploaded files accumulated as extra copies. The manual stated that duplicates were skipped.
- Auto-import read the date of a photo from its embedded capture time and used the file's modified time for everything else. Videos and camera RAW files were therefore filed under the day they were copied or uploaded, not the day they were taken. The library scan already read the correct date from those files.
- Each new file waited five seconds, one after another, to confirm that its upload had finished. A batch of 100 files waited more than eight minutes before the first was moved.

## What changed

### Auto-import

- **Known files stay put.** Before a file is moved, LensLedger looks for a byte-identical copy in the open library. A candidate with the same size and the same start of file is compared in full, so a similar file is never mistaken for a copy. A file that matches stays in the source folder. The **Activity log** on the **Auto-import photos** page lists it once as "skip duplicate", not again on every check. Files in the Review Bin do not count as being in the library.
- **Run summary.** The result of **Run now** and the status of the pipeline include a count of files skipped because they were already in the library.
- **Videos and RAW files use their own date.** The destination folder is built from the capture time inside a photo. For a video or camera RAW file it is the date stored in the file; a date in the file name is used next, and the modified time only when nothing else is available.
- **One wait per batch.** File sizes are read, one wait of five seconds follows for the whole batch, and sizes are read again. Files whose size changed, and empty files, are left for the next check.
- If the library cannot be consulted, for example while no library is chosen, files are imported as before.

### Documentation

- The **Auto-import Photos** section of the manual, in the written manual and on the manual page, describes duplicate skipping, the date used for sorting and the upload wait. The earlier statement that duplicates were skipped now describes what happens.

## Not changed

- No setting, database change or change to scanning, tagging or publishing.
- Files already imported are not moved or re-dated. Only files imported from now on use the new date rule.

## Verified

- Test suite: all tests passing, including new ones for the date of a video with no embedded date, the fallback to the modified time, a single wait covering a batch, a file that grows during the wait, a known file being left in place and reported once, a failing library lookup not blocking an import, and the library lookup recognising a byte-identical file while rejecting a different picture and a file with the same start and size but other contents.
