A comprehensive three-part audit identified issues across code quality, security, and user experience. This patch addresses every code-level finding.

## Security hardening

**Decompression bomb protection** — `Image.MAX_IMAGE_PIXELS` was set to `None` in `semantic_index.py`, globally disabling Pillow's protection against maliciously large images. A crafted 100,000×100,000 pixel image could cause out-of-memory crashes. Now set to `300_000_000` (300 megapixels), which covers every real-world camera sensor while blocking decompression bombs.

**SQL column allowlist** — The face disposition undo path in `photo_search.py` used an f-string to interpolate a column name into SQL. While the value came from a fixed dict lookup (making it currently safe), the pattern was fragile. Added an explicit allowlist assertion (`if disposition_column not in {"ignored_at", "unknown_at"}: raise ValueError`) so any future dict modification cannot regress into SQL injection.

**Dependency pinning** — All three requirements files (`requirements.txt`, `requirements-semantic.txt`, `requirements-face.txt`) now use bounded version ranges (e.g., `Pillow>=12.3,<13`) instead of open-ended `>=` specifiers, preventing unexpected major-version breakage or supply-chain compromise.

## Code quality

**Inline styles eliminated from viewer.js** — Moved 11 inline style violations to CSS:
- The focused face box overlay (12 CSS properties including 4 hardcoded colors) is now styled via the `.focused-face-box` class in `viewer.css`
- Status/error/warning/success colors replaced with `.status-error`, `.status-warning`, `.status-success` CSS classes instead of `style.color='#e25c70'` literals
- The trash panel empty bar, toast visibility, and suggestion label toggling all use CSS classes now
- `stage-nav` buttons get their z-index from CSS rather than JS
- Settings toggle-row margin uses `.toggle-row-spaced` instead of `style="margin-top:14px"`

**Quick Guide panel reformatted** — The entire guide panel was built in a single ~2000-character line with all styling inline. Broke it into readable multi-line code with CSS classes (`.guide-heading`, `.guide-body`, `.guide-note`, `.guide-footer`).

**Silent exceptions replaced with logging** — Five `except Exception: pass` blocks that silently swallowed errors now log the failure:
- `folder_watcher.py:89` — scan tick errors
- `ingest_pipeline.py:45` — EXIF extraction fallback (kept as pass with explanatory comment)
- `ingest_pipeline.py:250` — cloud placeholder detection (kept as pass with explanatory comment)
- `photo_search.py:4255` — log file reading errors
- `photo_search.py:5212` — watcher scan function errors

## Verified

- Full test suite: 88 tests passed

- Confirmed no hardcoded hex color literals remain in viewer.js
- Confirmed CSS classes render correctly in both light and dark themes (using CSS custom properties)
