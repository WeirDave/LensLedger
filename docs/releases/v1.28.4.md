# Merged people keep their faces, calmer scan page, unused settings removed

## Why this release

- Merging two people left their named faces unassigned.
- The Scan your photos page made far more requests than it needed, and more with every button press.
- Five Settings controls were saved but never used.
- The Publish page and the server had two smaller faults.

## What changed

### People

- Merging people (**Merge people**, above the list of people when the search scope is People) now moves the faces already named with the merged person to the person that remains. Previously those faces became unidentified faces again once the merged name was removed, and had to be named a second time.
- After a merge, the remaining person's name is written into every supported photo type: JPEG, HEIC, PNG, WebP and TIFF. Only JPEG files were rewritten before, so other types kept the merged names.

### Scan your photos

- The page now refreshes through a single loop. Each start button also asked for an immediate refresh, and every such request started another loop that ran for as long as the page stayed open. Pressing five start buttons made the page poll six times as often.
- Database health and library counts are fetched every 5 seconds while a scan is running and every 30 seconds when nothing is running, and once more as soon as a scan finishes so the final counts appear. Safety copy figures are fetched every 30 seconds. The running and idle scan states keep their previous rates of 0.7 and 4 seconds.
- A page in a hidden browser tab refreshes every 15 seconds and refreshes at once when the tab is shown again.

### Settings

- Removed **OCR worker threads**, **OCR batch size**, **Photos per page**, **Default sort order** and **Filmstrip thumbnail size**. Their values were stored in the settings file and read nowhere. The **Display preferences** section held only the last three and is removed with them.
- Values already stored in an existing settings file stay in the file and are ignored.
- The user manual and the in-app manual no longer list these settings, nor the worker and batch size rows in the text recognition table, which described controls that do not exist on the Scan your photos page.

### Publish page

- The light and dark button was attached by two scripts. It is now attached only by the shared theme script, so the choice is saved under the same key as on every other page and a click changes the theme once.

### Page requests

- A page address that carries an unusual character where a number is expected, for example a person number, now gets a normal reply. Previously the connection ended with no reply.
- Any other unexpected error while a page or status request is handled is now answered with an error message (400 for a bad value, 500 otherwise) and written to the log, as already happens for actions that save changes.

## Not changed

- No database format changes.
- **Meaning search batch** and every other setting work as before.

## Verified

- Full test suite: 502 tests, all passing.
- New tests cover faces staying with the remaining person after a merge, a merge of a non-JPEG photo, replies to malformed numbers in page addresses and to errors inside a request, a single scheduler and limited expensive requests on the Scan your photos page, the theme button being bound once, and the removed settings.
- The scan page's refresh logic was also run against simulated pages and requests: five rapid refresh calls leave one pending timer, and a minute of idle time makes 17 status requests and 2 requests for database health, down from 96 each.
