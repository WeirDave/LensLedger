# Missing people links are restored after every scan

## Why this release

- A person's photos are links stored in LensLedger's catalogue. When photos are renamed or moved, a scan can drop a photo's catalogue entry and add it again, and the link is lost while the person's name stays saved in the photo file. Restoring those links was a manual action on the people index. It now happens after each scan.

## What changed

### Scans

- After every scan that runs to completion, whether started by hand, by **Run all scans** or by folder watching, LensLedger links photos to the people whose names their files carry as people metadata where the link is missing. The names match ignoring capitals.
- A scan that is paused does not restore anything.
- The activity log records how many links were restored, with no names.
- Left alone: a person already linked to the photo, a person removed from a photo, a match rejected earlier, a name hidden from the photo with the tag's remove button, and photos in the Review Bin.
- No photo file is rewritten. Restored links are not tied to a particular face, so those faces stay in **Tag faces** until they are named there.

### Settings

- **Settings** > **People** has a new switch, **Restore people from photo names after each scan**. It is on by default. Turning it off returns to restoring only on request.

### People index

- **Restore from photo names** remains, for restoring on request. It now also leaves out names hidden from a photo with the tag's remove button.

### Manual

- Both manuals describe the automatic restore and where to turn it off.

## Verified

- Full test suite: 692 tests, all passing, including new tests for a completed scan restoring links, the setting turned off, a paused scan, a person removed from a photo staying removed after a scan, and a hidden name being left alone.
