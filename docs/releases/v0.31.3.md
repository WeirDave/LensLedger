Prompted by a live "Run all scans" pass sitting at ~45 hours remaining on
its face-detection step, ~4.2 seconds/photo, single-threaded on CPU.
Before touching anything, benchmarked where that time actually goes
(`FaceAnalysis.get()` on real photos from the library, with timing around
decode / detect / per-model inference) rather than guessing.

InsightFace's `buffalo_l` pack ships five ONNX models: `detection`,
`recognition`, `genderage`, `landmark_3d_68`, and `landmark_2d_106`.
`FaceAnalysis` loads and runs all five by default. `face_scan.py` and
`face_locations.py` (`load_insightface_runtime()` in the latter, shared by
both) only ever read two things off the result: `face.bbox` (from
detection) and `face.normed_embedding` (from recognition). The other three
models still ran, for every face, on every photo — pure waste.

The benchmark made the cost concrete: a 19-face group photo (2003 Buccaneers
parade) took ~13 seconds per pass with the full model set, and ~1.5 seconds
with `allowed_modules=["detection", "recognition"]` restricting it to the
two InsightFace actually asked to run — an ~8-9x difference on exactly the
kind of crowd photo that was dragging the ETA out. A 6-face photo went from
~4.7s to ~1.2s. Detection and recognition are the same models producing the
same bboxes and embeddings either way — nothing downstream (face matching,
auto-confirm, suggestion thresholds) changes, since neither of the two
retained models is affected by which other models also happen to run.

Grepped the codebase first for any read of `.landmark`, `.gender`, `.age`,
or similar `Face` attributes before making this change — none exist
anywhere in `src/`, confirming those three models' output was never
consumed.

## Verified

- Full automated suite: 77 tests, all green
  (`PYTHONPATH=src python -m unittest discover -s tests`).
- Benchmarked against real photos pulled from the live library (19-face,
  15-face, and 6-face group photos): identical face counts detected with
  the restricted model set as with the full one, at roughly 4x-9x less
  wall-clock time depending on face count per photo.
