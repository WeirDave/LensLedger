# LensLedger v0.70.0 — Continuous face matching on Name Faces

## Motivation

When you name a face on the Name Faces page, the system finds up to 50 similar
unidentified faces and groups them as "Also looks like [Name]" with a "Confirm
all" button. This was already a big time-saver over typing the same name
repeatedly — but it stopped after one round. If the person appeared in hundreds
of photos, you'd confirm 50, the group would disappear, and you'd have to wait
for the person to surface again randomly in the grid (or go to Review People).

The user wanted the match group to keep going: confirm a batch, automatically
search for more, show the next batch, and repeat until there are no more
matches. Less churn, more flow.

## What changed

### Backend — new `/api/faces/find-more` endpoint

A new POST endpoint accepts a `person_id` and:

1. Gathers all confirmed face embeddings for that person.
2. Computes a centroid vector (using the existing `centroid()` function from
   `face_learning`).
3. Searches up to 50,000 unidentified faces for matches above the 0.65
   similarity threshold.
4. Returns up to 50 matches, sorted by similarity.

Using a centroid rather than comparing against every individual confirmed
embedding keeps the search fast regardless of how many faces have been
confirmed — one dot product per candidate instead of N.

### Frontend — match group chaining

After "Confirm all" succeeds (no failures), the JavaScript now calls
`/api/faces/find-more` with the person's ID. If more matches come back, a new
match group replaces the old one. This chains naturally: each "Confirm all"
triggers another search, and the centroid improves with each round (more
confirmed faces = more representative center). The loop ends when the endpoint
returns zero matches.

The status text updates to "Looking for more…" between rounds so the user knows
what's happening.

## Verified

- **Test suite**: 80 tests, all passed.
- The endpoint correctly computes a centroid from confirmed embeddings and
  returns matches in the expected format.
- The frontend chains match groups: confirm → find more → new group → repeat.
- When no more matches exist, the group is removed cleanly and the grid
  tops up normally.
