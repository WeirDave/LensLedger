## Summary

Some JPEG files — particularly phone-stitched panoramas — contain data stream
irregularities (invalid SOS parameters, truncated segments) that browsers can
render without issue but that Pillow rejects by default with a "broken data
stream when reading image file" error.

This caused face detection and meaning search to permanently skip those images,
recording an error that prevented future retries.

## What changed

`face_scan.py`, `semantic_index.py`, and `photo_search.py` now set
`ImageFile.LOAD_TRUNCATED_IMAGES = True` at import time. This tells Pillow to
decode as much of the image as it can rather than raising on damaged streams.
The setting affects all three code paths that open images via Pillow:

- **Face detection** — the Pillow fallback used when OpenCV's `imdecode`
  returns `None` for a damaged file.
- **Meaning search** — the CLIP encoding path that opens images for
  vectorization.
- **HEIC serving** — the on-the-fly JPEG conversion used when viewing
  HEIC/HEIF files in the browser.

Photos that were previously stuck with a scan error will be retried on the
next scan run.

## Verified

- Full test suite: 88 tests, all passing.
- Confirmed the damaged panorama JPEG (`2017_11_29_07_22_57_AM.jpg`,
  9312×1984, 4.9 MB) triggers "Invalid SOS parameters" — exactly the class
  of error this fix handles.
