## Why this release

In large libraries, "Write all tags" on the Publish photos page stopped
before writing anything and showed "Error: too many SQL variables". Before
writing, the run estimates how much disk space the safety copies will need.
That estimate looked up every photo in the run with a single database
query, one query parameter per photo. SQLite caps a single query at 32,766
parameters, so any run covering more photos than that failed.

## What changed

- The disk-space estimate now looks photos up in batches of 500, so a run
  of any size gets past it.
- The disk-space check itself is unchanged: when there is not enough room
  for the safety copies, the run still stops with the same message.
- Only runs with the write mode set to embedded (or both) were affected.
  Sidecar-only runs skip the safety copies and never ran this lookup.

## Verified

- Full test suite: 233 tests, all passing.
- New regression test: 1,201 tagged photos, with the database's parameter
  limit lowered to 999. Without the fix it fails with the original error.
  With the fix the run gets through the lookup, counts all 1,201 photos,
  and reaches the disk-space check.
