## Why this release

LensLedger had no way to restart itself on demand: the only restart control
was the "Restart now" button in the "Server is running … on disk" banner,
which appears only when newer code is already on disk. That restart could
also leave LensLedger stopped altogether. Since v1.8.2 the old LensLedger
window closes itself when its server stops for a restart; the restart then
started a new window and closed the old one by its process number. Windows
can hand a new process the number of one that has just exited, and when the
new window received it, the restart closed the new window before its server
started.

## What changed

### Restart server in the menu

- The menu (☰) has a new "🔄 Restart server" item under "Help & Support",
  on every page.
- After confirmation, LensLedger stops and starts again in a new window. A
  notice across the top of the page reads "Restarting LensLedger…", and the
  page reloads once the server is back.
- It works for a source checkout, an installed copy and an extracted
  download alike.
- While "Write all tags", a scan, face detection, text recognition, meaning
  search, classifying photos or "Run all scans" is running, the restart is
  refused and the notice names the job that is still busy.

### Restart no longer closes its own new window

- The restart now closes the old window only if it was created before the
  new one was started. A new window that happens to receive the old window's
  process number is left running.
- This applies to "Restart now" in the banner, "Update now" in the update
  panel, and "Restart server" in the menu.

## Verified

- Full test suite: 217 tests, all passing, on Python 3.12.10. New tests
  cover the restart endpoint relaunching the running copy, the restart being
  refused while face detection runs, the menu item appearing on a page, and
  the old-window check being limited to windows created before the relaunch.
- The creation-time check was run through PowerShell on Windows 11 against a
  live process: a process created after the cutoff was left alone and one
  created before it was matched.
- Checked in the browser against a generated test library, in light and dark
  themes, with the restart request stubbed: the menu item appears under
  "Help & Support", a refusal shows the busy job's name in the notice, and a
  successful restart reloads the page once the server's start time changes.
