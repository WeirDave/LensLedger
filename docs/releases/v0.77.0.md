## Motivation

LensLedger's console output was the only record of what the application did — scans, imports, people review decisions, metadata publishes. When the terminal window closed, all of that history was lost. For a public project where users will need help troubleshooting scan failures, processing issues, or unexpected behavior, having no persistent record made support nearly impossible.

Additionally, renaming a person via "Edit name" on the People page wrote updated metadata to every linked photo's JPEG tags, but produced no console output at all — making it invisible in the terminal and impossible to verify after the fact.

## What changed

### Persistent log file

All activity that appears in the terminal is now also written to a log file on disk at `<data_root>/Logs/LensLedger.log`. This includes:

- Server startup (version, library path, database path)
- Scan progress and results (photo locations, OCR, meaning search, face detection)
- Auto-import activity
- Folder watcher checks
- People review decisions (confirmations, corrections, rejections, dispositions)
- Batch confirmations and confirm-all rounds
- Metadata publish operations
- Person rename and alias changes

The log file rotates automatically at 5 MB with one backup kept (`LensLedger.log.1`), so it won't grow unbounded.

### Rename logging

When a person's primary name is changed or aliases are updated via the "Edit name" dialog, the terminal and log file now show what happened:

- `[People review] Renamed "Jimmy Weaver" → "James Weaver", updated 12 photo(s), published 12`
- `[People review] Aliases for "James Weaver": Jim Weaver, Jimmy Weaver`

### Unified logging

All `[People review]` and `[Publish]` console output now goes through the `console_log` function, which means every line gets a consistent timestamp and is captured in both the terminal and the log file. Previously these lines used raw `print()` calls with no timestamp and no file logging.

### Settings page

The log file path is now shown on the Settings page alongside the database and application data paths, so users know where to find it.

## Files changed

- `src/console_log.py` — upgraded from a simple timestamped `print()` wrapper to a dual-output logger (terminal + rotating file). Includes `shutdown()` for clean handler cleanup.
- `src/app_paths.py` — added `log_dir()` path function.
- `src/photo_search.py` — converted all raw `print("[People review]..."` and `print("[Publish]..."` calls to use `console_log()`. Added rename/alias logging to `set_person_names()`. Added startup version line. Added log file path to Settings page.
- `tests/test_server.py` — added `console_log.shutdown()` call in `tearDown` to release the log file handle before temp directory cleanup on Windows.

## Verified

- Test suite: 80 tests passed.
- Confirmed log file is created in the `Logs` directory with proper rotation settings.
- Confirmed all People review, Publish, and rename operations produce timestamped console output.
