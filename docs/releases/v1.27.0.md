# Select all and Select none on People groups

## Why this release

Faces offered at a lower similarity (0.60 to 0.72) are outlined so they get a
closer look, and 1.25.1 raised the idea of leaving them unticked by default. On a
real library every lower match in a group turned out to be correct, so unticking
them would only add a click to each group. They stay ticked. What was missing was a
quick way to change the whole selection at once.

## What changed

- Each "Also looks like" group header has **Select all** and **Select none**
  buttons. Every face is still ticked when a group opens, lower matches included.
- **Select all** is greyed out when every face is already ticked, and **Select
  none** when none is.
- **Confirm all** is greyed out while no face is ticked. Before, confirming with
  nothing ticked quietly skipped the whole group, which Select none would have made
  easy to do by mistake. **Not these** is the button for skipping, and it works as
  before.
- A failed confirmation re-enables the buttons according to what is ticked, not all
  of them.

## Not changed

- Lower matches are still ticked by default and still outlined, and the header still
  says how many there are.
- Nothing on the server changed.

## Verified

- Full test suite: 463 tests. 5 of them (publishing tests in `test_server.py`) error on
  the Linux machine this was developed on because the bundled `ExifTool.exe` is a
  Windows program, exactly as on 1.26.0. The other 458 ran: 428 passed and 30 were
  skipped. The change is in the page script only, so no Python test covers it.
- The People page was driven in Chromium in the light and dark themes against the
  real server with invented faces: a group opens with all five ticked, Select all
  and Confirm all enabled state correct; Select none unticks all five and greys out
  Select none and Confirm all; ticking one face enables both Select buttons and
  Confirm all; Select all ticks all five again. No page errors, and the header
  buttons read clearly in both themes.
