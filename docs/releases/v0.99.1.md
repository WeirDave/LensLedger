## Fix model cache detection for HuggingFace hub

The model download status on the Settings page always showed "Not downloaded" for all models, even ones that were successfully downloaded. Clicking Download worked (the model was fetched), but the UI never updated to reflect it.

### Root cause

The `model_cache_info()` function looked for `.pt` files in `~/.cache/clip/`, which was the cache location used by older versions of open_clip. Current versions of open_clip download models via the HuggingFace hub, which stores them in `~/.cache/huggingface/hub/models--timm--{model_name}/snapshots/{hash}/open_clip_model.safetensors`. The old code never found any files because the directory didn't exist.

### Fix

- Replaced `MODEL_FILENAMES` (mapping to `.pt` filenames) with `MODEL_HF_REPOS` (mapping to HuggingFace hub repo directory names like `models--timm--vit_base_patch32_clip_224.openai`)
- `model_cache_info()` now scans the HuggingFace hub snapshots directory for `.safetensors`, `.pt`, or `.bin` files and sums their sizes
- Respects the `HF_HOME` environment variable for non-default cache locations
- `delete_cached_model()` now removes the entire HuggingFace hub repo directory using `shutil.rmtree`

## Verified

- Test suite: 101 tests passed
- Confirmed ViT-B-32 and ViT-L-14 correctly detected as downloaded in `~/.cache/huggingface/hub/`
