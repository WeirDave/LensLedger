## Motivation

The People Index shows a card for each person with a representative photo, but the photo was always chosen automatically — the most recent confirmed photo. There was no way to pick a better image (for example, a clear face shot instead of a wide group photo where the person is barely visible).

## What changed

### Database

Added a `card_asset_id` column to the `people` table (nullable, references `assets`). Schema version bumped to 15. When set, this column takes priority over the dynamic most-recent-confirmed-photo query; when NULL, the original automatic selection is used.

### People Index — "Change photo" button

Each person card now has a "Change photo" button (positioned at the bottom right, opposite the existing "Edit name" button). Clicking it opens a modal showing up to 24 of that person's most recent confirmed photos as a thumbnail grid. The currently selected card photo is highlighted with a border. Clicking any photo sets it as the card photo, updates the card image in-place, and closes the modal.

### Viewer — "Set as card photo" button

When viewing a specific person's photos (scope = People, person selected), a "Set as card photo" button appears in the person result bar alongside the stats. Clicking it sets the currently viewed photo as that person's card image on the People Index.

### API

- `GET /api/person/photos?person_id=N` — returns up to 24 recent confirmed photo IDs and the current `card_asset_id` for the photo picker modal.
- `POST /api/person/card-photo` — accepts `person_id` and `asset_id` (or `null` to clear) and updates the `card_asset_id` column.
