## Why this release

"Write mode" offered one choice for the whole library: embedded, sidecar, or
both. With PNG, WebP and TIFF now embedded (v1.11.0), sidecars are only
needed for file types that cannot carry embedded tags. Photos that had
received sidecars before those formats could be embedded kept those `.xmp`
files next to them, even though the same tags are now inside the photos.

## What changed

### Settings → Metadata publishing

"Write mode" is replaced by two controls:

- **"Embed tags in photo files"** — on by default. Writes into JPEG,
  HEIC/HEIF, PNG, WebP and TIFF files, keeping a safety copy of each photo
  first.
- **"Sidecar (.xmp) files for"** — one checkbox per file type: JPEG,
  HEIC / HEIF, PNG, WebP, TIFF, GIF and BMP. By default only GIF and BMP are
  ticked, marked "(cannot embed)", since a sidecar is the only place their
  tags can go.

A saved "Write mode" choice carries over: "Embedded" becomes these defaults,
"Both" ticks every file type, and "Sidecar" turns embedding off and ticks
every file type. The new controls take over when the settings are next
saved. To leave photos untouched, turn off embedding and tick every file
type.

### "Write all tags" and single-photo writes

- Each photo gets embedded tags, a sidecar, or both, according to its file
  type's settings.
- **Old sidecars are moved aside.** When a file type's sidecar box is off and
  tags are embedded in a photo, LensLedger's own sidecar for that photo is
  moved to the safety copies, under a name containing
  `.before-sidecar-removal-`. It is cleared with the other safety copies
  under the same retention settings ("Keep photo safety copies for (days)",
  "Total size limit for safety copies (GB)"). The finished run says how many
  were moved.
- **What is never moved:**
  - A sidecar written by another program. Only a file whose opening block
    matches exactly what LensLedger writes is treated as LensLedger's own, so
    Lightroom and Capture One sidecars stay in place.
  - A sidecar that another media file with the same name in that folder also
    uses. `IMG_0001.jpg` and `IMG_0001.cr2` both use `IMG_0001.xmp`, so the
    sidecar stays.
- **Skipped photos are listed.** A photo whose file type is set to get
  neither embedded tags nor a sidecar is listed under "photos were skipped",
  with the reason. Writing tags to a single such photo reports that nothing
  is set to be written for its file type.
- A JPEG too damaged to rewrite still gets a sidecar, whatever the JPEG
  sidecar setting, and is listed under "got a sidecar file instead".
- Photos already written with the same tags and the same choice are not
  rewritten. JPEG and HEIC photos written under the previous "Embedded"
  default count as up to date and are skipped.
- The "Not enough disk space" refusal now explains how to switch to
  sidecar files, which need no safety copies.

## Fixed during testing

The new tests passed on their own but failed in the full suite. When no
settings file existed, the settings loader returned the built-in defaults
themselves rather than a copy. An existing test that changed a loaded
setting therefore changed the defaults for every later test in the same
process. The loader now returns a copy. The same thing would have affected
any code that edited loaded settings before a settings file existed.

## Verified

- Full test suite: 243 tests, all passing. Real settings and library-state
  files were unchanged by the run.
- New tests:
  - Default plan per file type: JPEG, HEIC, PNG, WebP and TIFF embed with no
    sidecar; GIF and BMP get a sidecar only. Extensions are matched
    regardless of case.
  - A saved "Write mode" of "Both" or "Sidecar" is read as the choice it
    stood for. Saved per-type choices keep their defaults for any type not
    saved.
  - One "Write all tags" run on a folder holding four sidecars:
    - LensLedger's own sidecar next to a PNG was moved to the safety
      copies with its contents intact.
    - A Lightroom-style sidecar next to a PNG was left untouched.
    - A LensLedger sidecar shared by a PNG and a `.cr2` of the same name was
      left in place.
    - The GIF received its sidecar.
    - The PNG carried its keywords embedded.
  - With embedding off and GIF sidecars off, the GIF is listed as skipped and
    no sidecar is written; a single-photo write for it is refused with a
    plain reason.
- Settings page checked in a browser against a synthetic library with a
  separate data folder, in light and dark themes and at 1280 and 800 pixels
  wide. The checkboxes show the defaults, wrap cleanly at the narrower
  width, and do not overflow the card. Ticking PNG and saving stored the
  choice; the choice was still ticked after a reload.
