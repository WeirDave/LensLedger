# Automatic checks stop restarting scans that have nothing to do

## Why this release

- Folder watching and **Auto-import** start text recognition, meaning search and face detection only when files are waiting for them. The waiting counts included files those scans never finish: videos, camera RAW files, GIFs and other formats a scan cannot open, and photos a scan had already failed on.
- A library holding any such file started meaning search and face detection again on every automatic check, every five minutes by default, loading their models each time. With **Auto-classify photos after meaning search** switched on, photo tagging ran again with them.

## What changed

### Automatic checks

- Meaning search and face detection count only photos they can open and have not already failed on. Text recognition counts only photos it has not already failed on.
- A photo that text recognition or face detection could not read is tried again the next time that scan runs, whether for new photos, from **Run all scans** or from its own button on the **Scan your photos** page.
- A photo that meaning search could not read is retried with **Fill in missing**, as before.

### Meaning search model

- Meaning search counts photos not yet indexed by the model chosen under **Settings**, **Meaning search**. After a different model is chosen, the next automatic check indexes the library with it, downloading the model first if needed.

### Activity log

- The **Scan status** line reads "no photos waiting to be scanned" in place of "all photos fully processed".

### User manual

- The **Folder watching** section describes when an automatic check starts each scan.

## Verified

- Full test suite: 740 tests, all passing, including new tests that nothing is left waiting after face detection and meaning search have run on a library with a video, a camera RAW file, a GIF and an unreadable photo.
