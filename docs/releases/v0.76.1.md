# LensLedger v0.76.1 — Fix accuracy tracking for People Review confirmations

## Motivation

After v0.76.0 shipped, accuracy percentages on the People Review page were
showing as "-1%" (displayed as "1% accuracy — review more to improve") for
people whose faces were confirmed through the single-face naming endpoint.
The batch confirmation endpoint correctly recorded review actions, but the
single-face `name_face()` endpoint was inserting `NULL` into the `NOT NULL`
`previous_json` column of `people_review_actions`, causing a database error.

## What changed

Fixed the `name_face()` endpoint in `photo_search.py` to pass `'{}'` instead
of `NULL` for the `previous_json` column when inserting a review action record.
This matches the behavior already in place for `name_face_batch()`.

With this fix, every face confirmation — whether single or batch — now creates
a `people_review_actions` record, so accuracy percentages calculate correctly
from the first confirmation onward.

## Verified

- **Test suite**: 80 tests, all passed.
- The previously failing test `test_naming_a_face_returns_similar_unidentified_faces_as_matches`
  now passes — it exercises the exact code path that was broken.
