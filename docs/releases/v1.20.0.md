## Why this release

Star ratings arrived in 1.19.0 but lived only in LensLedger's catalog. A photo
you gave five stars here looked unrated in every other program, and "Write all
tags" wrote everything else LensLedger holds but not that.

Two rules made this more than adding a field:

- **No rating in LensLedger must mean "leave the file alone."** Writing 0 for
  an unrated photo would wipe out a rating Lightroom or another program had
  already put in the file.
- **Every path that touches a file had to agree.** The embedded write and the
  `.xmp` sidecar are separate code, and each needed the rating.

## What changed

**Write all tags writes the rating**

- A rated photo gets `XMP:Rating` (1–5) written into the file along with its
  keywords, people, description and subject. It is in the same single write,
  with the same safety copy, so an interrupted run still cannot leave a photo
  half-written.
- The rating is checked when the file is read back, and a file type that cannot
  carry it is reported with the other fields it could not carry.
- The `.xmp` sidecar gets an `xmp:Rating` element for a rated photo. Sidecars
  written by earlier versions are still recognised as LensLedger's own.

**What happens when the file already has a rating**

- Unrated in LensLedger: the file's rating is not touched, whatever it is.
- Rated in LensLedger and the file holds a different rating: LensLedger's
  rating replaces it. Writing tags already makes the file match LensLedger for
  keywords and descriptions, and this follows the same rule. The rating being
  replaced is saved in the safety copy and in the record of the write.
- Clearing a rating in LensLedger does not clear it in the file. That follows
  from the first rule: an unrated photo leaves the file alone.

**Which photos are written**

- A photo that has a star rating and nothing else is now included in **Write
  all tags**. Before, only photos with tags, confirmed people or text were.
- Changing a rating makes that photo count as changed, so the next run writes
  it again. Unrated photos keep the marker they were written with, so an
  upgrade does not rewrite a library that is already up to date.

**Not in this release**

- Only **Write all tags** writes the rating. Publishing one photo's description
  and subject, and publishing people, are unchanged.
- A rating already in a file is not read in on scan, so a rating set in another
  program does not show up in LensLedger. That is a separate change.

## Database

No change. The rating is read from the existing `asset_ratings` table.

## Fixed during testing

- Several of the new checks passed even with the rule they test removed. The
  photo used for the "only a rating" check already qualified because of a tag
  taken from its folder date, and the sidecar check only covered the batch
  path, not writing one photo or the fallback used when a JPEG cannot be
  embedded. The photo now has its tags removed first, and each of the three
  sidecar writes has its own check. Every rule was then checked to fail with
  it removed.
- The sidecar's rating element declares its own namespace instead of adding it
  to the opening block. The opening lines are how LensLedger recognises its own
  sidecars, and changing them would have stopped older sidecars from being
  recognised.

## Verified

- Full test suite on Linux with the official command: 321 tests, 316 passing or
  skipped. The 5 that fail are the same five that run the bundled Windows
  `ExifTool.exe`, as in 1.19.2. The Windows CI run is the authority for those.
- The same suite on Linux with a system ExifTool 12.76 in place of the bundled
  one: 321 passing, including those five.
- 10 new tests: the sidecar carrying a rating and still being recognised; no
  rating element for an unrated photo or an out-of-range value; the rating
  written into the file and the old one kept in the record of the write;
  an unrated photo leaving the file's rating alone, and not adding one where
  there was none; a photo with only a rating being written; changing a rating
  writing the photo again; unrated photos keeping their earlier marker;
  one photo written to a sidecar; and the sidecar used when a JPEG cannot be
  embedded.
- Each rule was checked to fail with it removed: the guard that stops an
  unrated photo writing a rating, the unchanged marker for unrated photos, the
  marker changing with the rating, the batch including rated photos, the
  sidecar skipping unrated photos, the old rating being recorded, the rating
  being written, and the rating reaching each of the three sidecar writes.
- ExifTool reads `Rating: 4` back from a sidecar this version writes, and finds
  none in an unrated one. Checked on a generated image, not a real photo.
- The in-app manual served by the running app shows the new wording, checked
  against a generated test library.
- **Limit of the checking:** the embedded write was exercised on generated JPEGs
  with Linux ExifTool. It was not run on Windows with the bundled ExifTool, or
  against files that Lightroom wrote. The Windows CI run covers the former.
