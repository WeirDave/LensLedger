## Context

When a user clicked "Confirm all remaining" in People review, the server-side
operation could run for several minutes across multiple rounds (e.g. 238 faces
confirmed across 6 rounds over ~4 minutes). During this time, the UI showed only
a static message: "Confirming remaining matches for [name]… (this may take a
moment)" with no indication that anything was still happening. The terminal log
showed round-by-round progress, but nothing in the browser told the user the
operation was alive.

## What changed

**Backend** — The `/api/faces/confirm-remaining` endpoint now streams
Server-Sent Events (SSE) instead of returning a single JSON response. Each
round emits a progress event with the round number and running total of
confirmed faces. A final `done` event carries the same data the old JSON
response did.

**Frontend** — The "Confirm all remaining" button handler now reads the SSE
stream with a `fetch` + `ReadableStream` reader. While the operation runs, a
small spinning animation appears next to live-updating text like
"Round 3: 217 confirmed so far…". When the stream completes, the match group
is removed and the done status is shown, exactly as before.

**CSS** — Added `.confirm-progress-spinner`, a 14px inline spinner using the
existing `@keyframes spin` animation, matching the visual language of spinners
already used elsewhere in the app.

## Verified

- Test suite: 87 tests, all passing.
- Visual verification: injected mock match-group into the People review page to
  confirm the spinner and progress text render correctly in the match-status
  area with proper alignment, sizing, and animation.
