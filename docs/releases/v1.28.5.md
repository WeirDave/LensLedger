# Settings are checked before saving, safer database import

## Why this release

- A bad value in a saved setting could stop LensLedger starting or break the Settings page.
- Importing a database could replace the index while a scan was writing to it, write outside the Face Data folder, and leave the previous database's write-ahead files behind.

## What changed

### Settings

- Saving checks each value before writing anything. A value outside its range is refused with a message that names the setting and the allowed range, and the settings file is left as it was. The checked values are: **Meaning search batch** (1 to 128), the **Check interval (minutes)** for folder watching and for Auto-import (5 to 1440), **Keep photo safety copies for (days)**, the total size limit for safety copies, the classification threshold, and the on/off options.
- Before this release the file was written first, and the check interval was converted afterwards, so a bad value was stored and the save then failed. At the next start the same conversion failed again.
- Saving now changes only the settings it is given. Other stored settings are kept, and keys this version does not use are kept too.
- Settings read from an existing file are checked in the same way. A damaged or out-of-range value is replaced by its default, so it cannot break the Settings page, Auto-import page or startup. Other values in the file are kept.
- Auto-import now starts with its saved **Check interval (minutes)**. It used 10 minutes until the next save regardless of the saved value. The default of 10 is now part of the default settings.
- Saving the Auto-import configuration is checked the same way.

### Import database (Settings, Photo libraries)

- The import is refused while a scan, text recognition, meaning search, face detection, tag writing, classification, publish or run-all job is running, with a message naming what to wait for.
- An export that contains a face file whose path leads outside the Face Data folder is rejected before the database or any face file is replaced.
- An export whose schema version cannot be read is reported as not a valid LensLedger export.
- The index being replaced is saved with a SQLite online backup in the `Database Backups` folder. Previously its main file was copied next to it, which left out changes still held in the write-ahead file.
- The previous database's write-ahead and shared-memory files are removed after the replacement, so they are not applied to the imported database.
- A statement that changed nothing and an unclosed connection in the path-rewriting step were removed.

## Not changed

- The export format, and the path rewriting from the exported library folder to the current one.
- Settings that are valid are stored exactly as before.

## Verified

- Full test suite: 517 tests, all passing.
- New tests cover refused values and the unchanged settings file, text numbers stored as numbers, partial saves keeping other settings, unknown keys kept, damaged stored values replaced by defaults, a Settings page that opens with unusable stored values, a refused save through the server, an export with a path outside Face Data, an import during a running job, an import that replaces the database and clears leftover files, and an unreadable schema version.
