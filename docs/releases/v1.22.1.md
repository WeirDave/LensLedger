# Auto-import always scans the photos it imports

## Why this release

Auto-import moves new photos from the source folder into the library and then
asks for a scan so they are indexed, read for text, and so on. That request was
missed in two cases, and the photos sat unscanned until the next scheduled
check or a manual scan:

- Folder watching was switched off. The scan request was ignored whenever
  watching was off, which left auto-import's own scan dependent on an unrelated
  setting.
- **Run now** on the Auto-import page imported photos without asking for a scan
  at all. Only the timed import did.

## What changed

- A few seconds after auto-import moves photos into the library, LensLedger
  scans them: photo locations first, then text recognition, meaning search and
  face detection where they are installed.
- This happens whether the import came from the timer or from **Run now**, and
  whether or not folder watching is switched on. With watching off it runs a
  single scan and leaves watching off.
- With watching on, the request moves the next regular check up, as before.
- If another scan is already running at that moment, the scan is skipped and
  the photos are picked up on the next scheduled check. That behaviour is
  unchanged and still depends on folder watching being on.
- The user manual (both copies) describes the behaviour.

## Verified

- New tests cover the one-off scan with watching off, repeated requests
  collapsing to one scan, a failing scan not blocking later requests, and
  **Run now** requesting a scan only when something was imported. Fixtures are
  synthetic temporary files.
- Full suite: 373 tests run. All pass except five `test_server` workflow tests
  that need the Windows ExifTool binary and fail the same way without this
  change on the Linux machine used for testing.
- Not verified in a browser or against a real camera-upload folder.
