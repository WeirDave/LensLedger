## Motivation

When editing a person on the People Index, the groups field was a plain text input where you had to type group names separated by commas. There was no way to see which groups already existed in the library, so you had to remember or look them up on the Manage Groups page first. This made assigning groups error-prone and slow.

## What changed

The plain-text groups input in the Edit Person modal is now a **tag/chip picker**:

- **Existing groups as chips** — groups already assigned to this person appear as removable pill-shaped tags with an × button.
- **Dropdown of available groups** — clicking the input or typing opens a dropdown listing all groups in the library with their member counts, excluding groups already assigned.
- **Type-to-filter** — typing narrows the dropdown to matching groups.
- **Create inline** — if the typed text doesn't match any existing group, a "+ Create" option appears at the bottom of the dropdown.
- **Keyboard support** — arrow keys navigate the dropdown, Enter selects the highlighted option or creates a new group, Backspace on an empty input removes the last tag, Escape closes the dropdown.

The dropdown fetches the full group list from `/api/groups` when the modal opens, so newly created groups from other sessions are always visible.

### Styling

Group chips in the modal reuse the existing `--badge-*` CSS variables for consistency with group badges shown on person cards. The dropdown uses `--modal-bg` and `--menu-hover` variables, so it renders correctly in both light and dark themes.

## Verified

- Test suite: 88 tests passed.
- Browser verification: confirmed in both light and dark themes — chips render correctly, dropdown filters on typing, selecting a group adds a chip and removes it from the dropdown, × button removes chips, "+ Create" option appears for new group names.
