## Why this release

LensLedger's server listens only on this computer, and every change it makes
requires a request token that is embedded in its own pages. That still left
one route in from the web: a site can make its own domain name resolve to
`127.0.0.1` (DNS rebinding). The browser then treats LensLedger as part of
that site, so the site's scripts could load a LensLedger page, read the
request token from it, and use it — or simply download photos.

GitHub code scanning (CodeQL) was also enabled for the repository. Its first
run flagged the places where a path sent to the server is used on disk, and
one redirect that copied the address's query string into a response header.

## What changed

- **Requests for any other host name are refused.** Every request must carry
  a `Host` of `localhost`, `127.0.0.1` or `[::1]` (any port), which is what the
  browser sends when LensLedger is opened normally. Anything else receives
  "403 Forbidden" before the request is read. No setting is involved.
- **Library paths are checked after links are resolved.** The "Repair"
  button and the file-name link that opens the containing folder, both in
  the list of failed photos on the Publish photos page, and "Open folder" on
  the Scan photos page's error list, confirm that the path they are given
  stays inside the current library, using the fully resolved path. The
  safety copy "Repair" makes is checked the same way against the
  safety-copy folder.
- **The old `/people-review` address** now redirects to `/people/review`
  with only the person number, instead of copying the whole query string into
  the redirect.

Opening, adding, moving and removing libraries still accept any folder:
choosing a folder anywhere on the computer is what those controls are for.

## Verified

- Full test suite: 247 tests, all passing.
- New tests: requests with `Host: rebound.example` are refused for a page,
  a photo and a POST action, while `localhost`, `127.0.0.1`, `[::1]` and
  `LOCALHOST` are answered; paths such as `../data/outside.jpg`, an absolute
  path outside the library, `""` and `.` are rejected; the `/people-review`
  redirect drops everything except a numeric person.
