LensLedger can now keep its installed application current without using a Git
working copy or mixing executable code with private photo-library data.

The new managed installer places the application in the user's private Programs
folder. LensLedger checks GitHub periodically and displays an update notification,
but installation always requires explicit approval. Downloads are matched against
GitHub's SHA-256 release digest, inspected for unsafe archive paths, and validated
for required files and the expected version before anything is replaced.

Updates use complete-directory staging instead of extracting over an old copy.
The prior managed version remains beside the installation as a rollback copy.
Git repositories, mixed source folders, unsafe paths, and unmanaged targets are
never overwritten.

For existing pre-v0.16 installations, the installer can migrate the catalog from
beside the old application into LensLedger's per-user data directory. Migration
uses SQLite's online backup API, upgrades and verifies the copy, records the
detected photo-library root, copies local face/recovery data when appropriate,
and leaves the original installation untouched.

## Included

- Managed per-user installer
- In-app update notification and approval panel
- Private-repository authentication through GitHub CLI or an explicit token
- Release size and SHA-256 verification
- ZIP traversal and symbolic-link defenses
- Required-file and version validation
- Complete-directory replacement with rollback preservation
- Legacy catalog, face-data, metadata-backup, and Review Bin migration
- Automatic restart and previous-copy recovery after updater failure

## Verified

- Twenty-four automated database, server, semantic, service, and updater tests
  pass locally.
- A disposable copy of a large pre-v0.16 catalog upgraded to schema 6 with
  SQLite integrity `ok` and no foreign-key errors.
- The migration retained cataloged assets, people, tags, and scan history while
  registering the detected photo-library root.
- The original legacy database was opened read-only and left in place.
