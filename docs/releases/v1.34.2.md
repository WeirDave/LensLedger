# Safer embedded metadata, deprecated Pillow call removed

## Why this release

- The embedded metadata block in a photo is XML supplied by whoever made the file, and it was parsed whether or not it declared entities, which is how an expanding "XML bomb" is built.
- Finding similar photos used a Pillow function that Pillow deprecates and removes in version 14. `requirements.txt` already stops short of Pillow 14, so nothing was broken, but the update to Pillow 14 would have needed this change first.
- The release and test workflows referred to the actions they run by version label, which can be moved to different code, and the release workflow could write to the repository in every job.
- Two functions had no callers.

## What changed

### Embedded metadata

- A metadata block that contains a document type declaration or an entity declaration is skipped. A photo with such a block shows no embedded title, description or people from it. No ordinary editing program writes these declarations, and all other metadata is read as before.

### Similar photos

- The picture fingerprint used to find similar photos reads its pixels with a call that Pillow is keeping. The fingerprints, and therefore the matches, are the same as before.

### Release process

- `actions/checkout`, `actions/setup-python` and `softprops/action-gh-release` are referenced by full commit, with the version noted beside each. Dependabot continues to propose updates.
- The release workflow has read-only access by default; only the job that creates the GitHub Release can write.

### Cleanup

- Removed `get_library_id` and `get_asset_classifications`, which nothing called, and an import of the latter.
- The fingerprint that records which tags were last written to a photo is marked as not used for security. The values are unchanged, so no photo is rewritten.

## Not changed

- No setting, database or workflow change for anyone using the application.

## Verified

- Test suite: 586 tests, all passing, including 4 new ones. They cover the pinned actions and the release workflow's permissions, and metadata blocks with and without entity declarations. The suite no longer prints the Pillow deprecation warning.
- A static security scan of the source and a scan of the required packages for known vulnerabilities found no vulnerable package. The scan's remaining findings are SQL built from fixed column names and lookups, and trusted local files, none of which take outside input.
