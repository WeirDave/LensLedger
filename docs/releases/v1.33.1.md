# Confirmations open inside the page on every page, manual catches up

## Why this release

- Most confirmations and error messages outside the photo viewer's trash buttons still used the browser's own dialogs. A browser that has blocked further dialogs for a page answers such a dialog with Cancel and shows nothing, so the button it guards appears to do nothing. This was already fixed for the trash buttons in v1.32.1 and v1.32.4.
- The manual did not describe several recent additions to the photo viewer.
- The updater checked for the Python files and a handful of web files, so a download missing other page scripts or stylesheets would still have been accepted.

## What changed

### Confirmations and messages

- Every confirmation and error message now opens as a panel inside LensLedger. Escape or a click outside the panel cancels. No page uses the browser's own dialog any more.
- **Scan your photos:** putting back the originals of interrupted writes, reading every photo again for text recognition, reading every photo again for meaning search, and **Delete every safety copy**.
- **Settings:** deleting a downloaded model, switching, moving and removing a library, and installing meaning search or face detection.
- **Manage groups:** deleting a group.
- **Menu, every page:** **Restart**.
- **Photo viewer:** merging people (both the merge form and the duplicate finder), installing an update, stopping a running job to continue, restoring a photo from its safety backup, **Empty trash** and **Delete** in **Trash & restore**, and the failure messages after trashing one or several photos. The confirmation for **Trash this photo** and **Trash selected** uses the same panel, so a confirmation opened from **Trash & restore** appears above it instead of replacing it.
- **People page (faces review):** failure messages after trashing, undoing a trash, or restoring skipped faces.
- Actions that remove something (deleting a model, library entry, group, safety copies or trashed photos) have a red button. Others, such as **Switch**, **Restart** and **Install and restart**, use the normal button colour.
- Adding a library in **Settings** asks where to store its database with two buttons, **Inside the photo library folder** (the default) and **Application data folder**, and **Cancel**. This replaces typing 1 or 2.

### Manual

- The user manual and the in-app manual describe the **Needs tags** search scope and the **N need tags** header button, the collapsible side-panel sections, the **Preview & publish** and **Restore last publish** bar, the **Details** and **Close details** buttons on phones, the **Move to Trash?** panel and the other in-page confirmations, and the Pillow 13 install on launch.

### Updates

- An update is refused when the downloaded release lacks any file under `web/` or `assets/`, in addition to the Python files and the files already checked.

### Changelog

- The changelog gains the missing entry for v0.63.7.

## Not changed

- The Python server, the database, and what each confirmed action does.
- The photo viewer's own panels for people, aliases, card photos and Trash & restore still open in the viewer's modal; only confirmations moved.

## Verified

- Test suite: 559 tests, all passing. Tests added: every page loads the shared dialog before its own scripts, no page script uses the browser's own dialogs, the shared script provides the confirm, notice and choice dialogs and is the only place they are defined, and the updater requires every file under `web/` and `assets/`.
- Browser, with a generated test library in light and dark themes: the choice dialog for the database location, the **Restart** confirmation (Escape closes it, **Cancel** closes it and sends no request), a confirmation opened above the open **Trash & restore** panel, and the real **Trash this photo** button.
