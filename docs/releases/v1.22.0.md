# Update dialog lists what changed since the installed version

## Why this release

The update dialog only stated that a newer version was available. It gave no
indication of what the update contained, so the release notes had to be looked
up separately on GitHub before deciding to install.

## What changed

### What's new list in the update dialog

- The update dialog, opened from the **Check for updates** menu item (which
  reads "⬆ Update available · vX.Y.Z" while an update is waiting), now lists
  what changed in every release newer than the installed version. The list sits
  directly above the **Download, install & restart** button.
- The heading reads "What's new since your version (N releases)", or "What's
  new in this update" when there is only one.
- Releases are listed newest first. Each one can be collapsed or expanded, and
  the newest is open by default.
- The text comes from the GitHub release notes of each release. A note's
  opening subtitle is shown next to its version number. Sections headed
  "Files changed", "Verified" or "Verification" are not shown, and very long
  notes are shortened.
- Up to the 30 most recent releases are listed. When all 30 are newer than the
  installed version, the list ends with "Older changes are listed on the
  release page."
- The list appears only while an update is available. It is not shown when
  LensLedger is up to date, while the check is running, or when a restart is
  waiting to apply an update that is already on disk.
- If the list of releases cannot be fetched (no connection, a GitHub limit, an
  unreadable reply), the dialog looks and behaves as it did before, without the
  list. Installing the update is not affected.
- Release text is shown as plain text. Only bold and code formatting is
  applied, and no HTML from the notes is ever interpreted.
- In a short window the list scrolls inside the dialog, and the buttons stay
  visible at the bottom.
- `GET /api/update/status` now includes a `changelog` entry with the releases
  (`version`, `title`, `notes`, `url`) and a `truncated` flag. The check is made
  by the server together with the existing update check, using the same GitHub
  sign-in as the update itself.
- The list is drawn by new files `web/js/release-changelog.js` and
  `web/js/release-changelog.css`, which are part of the release ZIP and of what
  the updater requires.

### Release notes open with a subtitle

- Release notes now open with a one-line subtitle, written as a `#` heading
  without the version number. The update dialog shows it next to the version in
  the What's new list. This release's subtitle is "Update dialog lists what
  changed since the installed version". Notes for earlier releases have no
  subtitle, so only their version number is shown.
- The release notes rule in `CLAUDE.md` describes the convention, and a test
  checks that the notes for the version being released follow it.

## Verified

- Full test suite: 367 tests, all passing, on Python 3.12.10.
- New tests cover reading the GitHub release list (newest first by version
  number, drafts and prereleases skipped, a first-line subtitle used as the
  title, sections headed Files changed, Verified or Verification removed, a
  heading further down left alone, sizes limited), keeping only releases newer
  than the installed version, the 30-release limit, failures giving an empty
  list, the update check still reporting an available update when the list
  cannot be fetched, the new files being served with the version in their
  address, and the subtitle convention for these release notes.
- Checked in the browser at 1366×650 against a generated test library, with the
  update check run against the public GitHub release list as if an older version
  were installed: five releases were listed newest first with the newest open,
  the install button stayed on screen, and the layout was correct in both the
  dark and light themes. The one-release heading, the "Older changes" line, and
  the absence of the list for an up-to-date copy or a waiting restart were
  checked with the update status replaced by test values. Notes containing HTML
  were shown as text.
