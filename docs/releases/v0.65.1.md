# LensLedger v0.65.1 — Fix dark thumbnails for faces without bounding boxes

## Motivation

Some faces in the Review People queue were imported from the legacy recovered catalog without bounding box coordinates. The face crop endpoint (`/media-face`) requires box data and returns 404 when it's missing, causing those thumbnails to render as dark empty boxes instead of showing the photo.

## What changed

The `buildCard()` function in `people-review.js` now checks `hasFaceBox(item)` before attempting a face crop URL. Faces without box data fall back to the full photo thumbnail (`/media?id=`). An `onerror` handler provides an additional safety net in case the crop fails for any other reason.

## Files changed

- `web/js/people-review.js` — thumbnail URL selection now checks for box data availability

## Verified

- **Test suite**: 80 tests, all passing.
- **Root cause**: `import_face_db()` in `photo_index.py` stores `(None, None, None, None)` for bounds when the import TSV has only 4 columns (embedding without position data). The face crop endpoint correctly returns 404 for these, but the thumbnail code was unconditionally using the crop URL when `face_id` was set.
