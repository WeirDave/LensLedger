## Why this release

Automatic folder checking ran more and more often the longer LensLedger was
left open.

Each check is a timer that schedules the next one. Asking for a check —
which auto-import does as soon as it finishes importing — scheduled a new timer
without cancelling the one already set. If that happened while a check was
running, the running one scheduled its own replacement afterwards and the extra
timer was simply left behind. From then on the folder was checked twice as
often, and again each time it recurred.

On a large library each check is a full pass over every file, so this quietly
turned a scan every thirty minutes into something considerably busier.

## Also fixed

Once the timers were tracked properly, a second fault showed up underneath: a
check that finished would cancel any check that had been requested while it was
running, and reschedule at the full interval instead. Auto-import asks for a
check the moment it finishes importing, so newly imported photos could wait a
further thirty minutes to be noticed.

A check now only schedules the next one if nothing has superseded it.

## Verified

- Full test suite: 202 tests, all passing, on Python 3.12.10 — up from 196.
- The folder watcher had no tests at all. It now has six, covering the minimum
  interval, the reported status, that stopping prevents any further check, that
  a check which raises does not take the watcher down with it, that requesting
  a check during another leaves only one timer pending, and that such a request
  is not discarded.
- Restoring the original behaviour was confirmed to fail the matching test in
  each case: three timers pending instead of one, and the requested check never
  happening.
