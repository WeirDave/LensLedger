# Publish all follows the sidecar choices in Settings

## Why this release

- **Publish all** on the Publish photos page always wrote confirmed names into the photo files, even when Settings under Metadata publishing was set to leave photos untouched and use sidecar files. **Write all tags** already followed those choices.

## What changed

### Publish photos page

- **Publish all** reads the Metadata publishing choices in Settings for each file type:
  - Sidecar only: an `.xmp` file next to the photo receives the photo's tags and confirmed names. The photo itself is not changed and no safety copy is made.
  - Embed and sidecar: the names are written into the photo as before, and the sidecar is written as well.
  - Neither: the photo is listed as not written, with the reason, and its names stay unpublished.
- A photo whose `.xmp` file was created by another program is listed as not written, with the reason, and that file is left as it is. The same applies when several pictures share one name and another one keeps the sidecar.
- A photo counts as published once its names are in the photo or in its sidecar, so it no longer appears in the pending list.
- The page introduction and the manual describe this.

### Not changed

- The single-photo publish in the viewer, people merges, and name confirm and reject actions still write into the photo.

## Verified

- Test suite: 553 tests, all passing, including 4 new ones for sidecar-only, embed and sidecar, neither, and another program's sidecar. One existing test that checked the publish lock the instant the response arrived now waits for the lock to be released.
