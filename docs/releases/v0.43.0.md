# LensLedger v0.43.0 — HEIC image support and tooltip fix

## Motivation

103 photos were stuck as permanent "Remaining" and "Errors" in the meaning
search and face detection scanners. Investigation revealed two root causes:

- **22 were HEIC files** from iPhones. Pillow cannot decode HEIC without the
  `pillow-heif` package, so every scan attempt silently failed and the files
  reappeared as "remaining" on the next run.
- **81 were genuinely corrupt JPEGs** (truncated, broken data streams, or
  garbage headers from old partial syncs). These are a separate issue to
  address later.

Additionally, info-button popovers on the scan-photos page were appearing in
the top-left corner of the viewport instead of next to the button that was
clicked.

## What changed

### HEIC/HEIF support

- Added `pillow-heif>=0.16` to `requirements.txt` (base dependency).
- Registered `pillow_heif` with Pillow via `register_heif_opener()` in all
  four modules that call `Image.open()`: `photo_search.py`, `photo_index.py`,
  `metadata_reader.py`, and `semantic_index.py`. Registration is wrapped in
  `try/except ImportError` so LensLedger still starts if `pillow-heif` is
  not installed.
- Added `.heif` to `MEDIA_EXTENSIONS` in `photo_index.py` (`.heic` was
  already present).

### Tooltip positioning fix

- Added `position:relative` to `.card` in `scan-photos.css`. The
  `.help-popover` elements use `position:absolute` but were siblings of
  (not children of) the `.section-title` that had `position:relative`.
  Without a positioned ancestor inside the card, they fell through to the
  viewport origin.

## Verified

- Test suite: 79 tests passed.
- Confirmed `pillow-heif` successfully opens HEIC files that previously
  failed with "cannot identify image file."
- Browser verification: info popovers on the scan-photos page now appear
  directly below their heading, inside their card, for all sections.
