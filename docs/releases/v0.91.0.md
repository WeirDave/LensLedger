## Context

LensLedger scans and detects faces in all image types — JPEG, PNG, GIF, BMP, TIFF, WebP, and HEIC/HEIF. However, only JPEG and HEIC/HEIF files support writing embedded metadata (IPTC/XMP) back into the file. Previously, when you tagged faces on non-publishable file types and then hit "Publish all," those files would appear as failures with "Not a publishable file type." This was confusing and noisy — the screenshot that prompted this fix showed 17 photos failed, all of them TIFFs, BMPs, PNGs, and GIFs that never had a chance of succeeding.

## What changed

**Publish page filters non-publishable files.** The pending counts, per-person publish, and bulk "Publish all" now only include assets whose file type supports embedded metadata. Non-publishable files no longer appear in the publish queue at all — no more guaranteed failures cluttering the results.

**Publish reminder banner is accurate.** The "N people tagged across N photos — not yet published" banner on the Tag Faces page now counts only publishable photos, so the number matches what will actually succeed when you click "Publish now."

**"Not publishable" badge on Tag Faces cards.** Face cards for non-publishable file types now show a small "Not publishable" badge with a tooltip: "This file type does not support embedded metadata — tagging still works for search." This makes it clear at a glance that tagging a PNG or BMP is still useful (it feeds search and people pages) but won't produce a published metadata write.

**Face detection unchanged.** All image types are still scanned for faces. The person-to-photo association is stored in the database regardless of file type, so search, people pages, and browsing all benefit from knowing who's in every photo.

A `_PUBLISHABLE_SQL` constant was added alongside the existing `PUBLISHABLE_EXTENSIONS` set to keep the SQL filter consistent and DRY across all six query sites.

## Verified

- Test suite: 88 tests passed.
- Browser verified the Publish page in both dark and light mode — only 2 publishable JPEGs shown (previously 17+ including non-publishable types).
- Confirmed the 2 remaining publish failures are legitimate (a corrupt JPEG missing its EOI marker, and a PNG masquerading as a `.jpg`).
- Verified the `/api/faces/unidentified` endpoint returns the `publishable` field on every face.
- Verified the publish reminder banner counts only publishable photos.
