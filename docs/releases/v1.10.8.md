## Why this release

On Windows, "Show in folder" opened Explorer at the right folder with the
photo selected, but the Explorer window appeared behind the browser. With
nothing visibly changing, the button looked broken. The cause is Windows'
foreground lock: LensLedger's server runs as a background process, and
Windows does not let a background process put a new window in front of the
one the user is working in.

## What changed

- After opening Explorer, LensLedger finds the new Explorer window and
  brings it to the front, restoring it first if it is minimised.
- Applies everywhere LensLedger opens a folder on Windows:
  - "Show in folder" in the enlarged-photo view on the People page
  - Double-clicking a photo to reveal it
  - The folder links in the error lists on the Scan photos and Publish
    photos pages
- macOS and Linux are unchanged.
- If the Explorer window cannot be found within three seconds, the folder
  still opens as before, just without being brought forward.

## Verified

- Full test suite: 232 tests, all passing.
- Ran a test server against a generated synthetic library and checked which
  window was in front after each request, with the browser in front
  beforehand:
  - Before the fix, the browser stayed in front and the Explorer window
    opened behind it.
  - After the fix, Explorer was in front for "Show in folder" (twice in a
    row) and for a folder link.
- Clicked "Show in folder" in the People page's enlarged-photo view and
  confirmed the button sends the reveal request.
