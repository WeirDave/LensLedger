## Why this release

Some photos could not be written by "Write all tags", "Publish all" or
single-photo publishing. Each one was listed under "photos could not be
written" with the ExifTool message `Error: [minor] MakerNotes offsets may be
incorrect (fix or ignore?)`, often followed by a warning such as
`Fixed incorrect URI for xmlns:MicrosoftPhoto`.

The maker note is the camera manufacturer's private block inside the EXIF
data. Some older cameras, and photo editors that move the EXIF block without
updating the maker note, leave it with offsets that no longer line up.
ExifTool reads these photos without trouble, but it classes the mismatch as a
minor error. It refuses any write that touches EXIF, such as the photo
description, unless it is told that minor errors may be ignored.

## What changed

- All metadata writes now pass ExifTool's "ignore minor errors" option. The
  affected photos are written normally.
- The maker note is carried over as it was. It is not moved or
  reinterpreted, and its values read the same before and after the write.
- The existing safeguards are unchanged. A verified safety copy is taken
  before each write, the picture pixels are compared afterwards, and the
  photo is restored from the safety copy if anything fails.
- Photos that failed in an earlier run are still pending, so running
  "Write all tags" or "Publish all" again picks them up.

## Verified

- Full test suite: 234 tests, all passing.
- New regression test: a synthetic photo whose maker note sits later in the
  file than its offsets claim. Without the fix, "Write all tags" fails with
  the same "MakerNotes offsets may be incorrect" error. With the fix the
  write succeeds, the description and keywords land in the file, the pixels
  are identical, and the maker note reads back unchanged.
- A scratch copy of an affected photo, outside the library, produced the
  same error without the fix. With the fix it was written, the pixels were
  identical, and the maker-note and EXIF values were unchanged.
