# LensLedger v0.63.4

## Auto-import performance and visibility

### The problem

Auto-import was silently failing on a library with 50,000+ photos. The console showed "Auto-import: checking for new photos" followed by "no new photos found" — even though Camera Uploads was full of new photos waiting to be imported.

Three issues combined to cause this:

1. **Rehashing the entire library every cycle** — `_process_source()` called `content_hash()` on every file in the destination folder (50K+ photos) to build a dedup set before checking even one source file. For a large library this could take minutes or throw an exception.

2. **Silent exception swallowing** — `_on_tick()` wrapped the entire processing call in `except Exception: pass`. If the hash scan or anything else threw, the user saw "no new photos found" instead of the actual error.

3. **Silent cloud placeholder skipping** — Dropbox Camera Uploads files that weren't fully synced (smart sync cloud-only) were skipped with no log message, making it look like nothing was there.

### What changed

- **Cached destination index**: The destination hash set is now built once on first run, then updated incrementally as files are ingested. Subsequent cycles skip the expensive scan entirely. Progress is logged every 5,000 files during the initial build.

- **Exception logging**: Processing errors are now logged to the console (`Auto-import: error during processing — <details>`) instead of silently swallowed.

- **Cloud placeholder logging**: When files are skipped because they're cloud-only (not downloaded), the count is logged (`Auto-import: skipped N cloud-only files (not downloaded)`).

- **Upload-in-progress logging**: Files that fail the stability check (still being uploaded) now log individually.

- **Candidate count**: Before processing, the pipeline now reports how many photos it found to check.

- **Hash cache invalidation**: The cached hash set is cleared when the destination folder changes via settings.
