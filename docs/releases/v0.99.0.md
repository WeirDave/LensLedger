## Download models from the Settings page

Previously, the only way to download a meaning search model was to select it and then run a meaning search scan — the download happened implicitly inside the indexing job. If you wanted to pre-download a larger model (like ViT-L-14 at ~1.8 GB) before running a scan, there was no way to do it. The model cards showed "Not downloaded" status but offered no action to fix that.

### What changed

Each model card on the Settings page now has a **Download** button when the model isn't already cached locally. Clicking it:

1. Starts the download in a background thread
2. Shows a toast confirming the download has started
3. Logs progress to the terminal log (`Model download: downloading ViT-L-14/openai (~1.8 GB)…`)
4. Polls the server every 3 seconds to detect completion
5. Updates the model card to show "Downloaded" once finished
6. Shows a success or error toast when done

Only one model download can run at a time. The download button appears on all models that aren't cached, and disappears once a model is downloaded (replaced by a Delete button if it's not the active model).

### Backend

- New `/api/semantic/download-model` POST endpoint that validates the model, starts a background thread calling `encoder_for()`, and tracks state via `model_download_job`
- Download state (`model_download`) included in `/api/semantic/status` response for polling
- Download progress logged to the terminal via `console_log`
