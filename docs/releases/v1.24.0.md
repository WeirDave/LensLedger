# Restarts keep the same terminal window

## Why this release

Every restart of LensLedger — **Restart server** in the menu, **Restart now** in
the banner, or installing an update — opened a new console window and then closed
the old one. In Windows Terminal that meant a new tab or window each time, and the
tab you had put LensLedger in was gone. The same pattern was also why a restart
needed a few seconds' pause in the old window: closing the last tab too early took
the new window down with it.

## What changed

- `Start LensLedger.cmd` now stays open and starts the server again in the same
  window when the server stops to restart (exit code 75). Windows Terminal ties a
  tab to the process that launched it, so the launcher has to be the one that
  keeps running; attaching a different process to the console would not have kept
  the tab.
- The restart loop is a single parenthesised block with no labels or `GOTO`. `cmd`
  reads a batch file as it goes, and an update replaces `Start LensLedger.cmd`
  while it is running; this way nothing is read from the file after the update.
- The launcher sets `LENSLEDGER_RESTART_MARKER` to a temporary file. For an
  in-place restart of a source checkout or a plain restart, the server just exits
  and the launcher starts it again; no helper process is needed.
- For an update of a managed install, the server creates the marker, the updater
  helper installs with `--no-launch`, and the helper deletes the marker when it
  finishes, whether the install worked or not. The launcher waits for the marker
  to go (up to ten minutes) and then starts whichever copy is on disk, so a failed
  install brings back the previous version in the same window.
- After a restart the launcher repeats the Python package check, so an update that
  needs a new package gets it installed before the server starts.
- The server only skips the helper window when the launcher says it supports this
  (the marker variable is set). A server started any other way, or by an older
  copy of `Start LensLedger.cmd`, restarts as before. An update from 1.23.x
  therefore opens one new window; every restart after that stays in place.
- The restart confirmation no longer says the server restarts "in a new window".

## Verified

- Full suite: 423 tests, 5 errors, 30 skipped. The 5 errors are in the publish
  and People tests that run `tools/ExifTool/ExifTool.exe`, which cannot run on the
  Linux machine this was built on (`Permission denied`); they fail the same way on
  1.23.1 without these changes.
- Five new tests cover: a restart with the marker set spawns no helper; a managed
  update creates the marker and passes `--no-launch --restart-marker`; a helper
  that cannot start deletes the marker; the updater deletes the marker after a
  successful and after a failed install; and a failed install does not relaunch
  from the helper.
- **Not verified on Windows.** The launcher loop could not be run here. Check one
  restart each of **Restart server** and an update in Windows Terminal and in a
  plain console before relying on it.
