## Motivation

LensLedger scans photos to extract tags, identify people, and read text — but until now, all of that knowledge lived only in the LensLedger database. Other apps (Lightroom, Google Photos, Capture One, etc.) couldn't see it because the results were never written back to the photos' own metadata. Users have been asking for a way to push scan results into EXIF/XMP/IPTC tags so their entire photo ecosystem benefits from LensLedger's analysis.

## What changed

### Semantic auto-classification

A new `semantic_classify.py` module classifies photos against a built-in vocabulary of ~50 common categories (landscape, portrait, food, beach, mountain, wedding, etc.) using the CLIP embeddings that meaning search already computes. Each photo gets up to 5 category tags above a similarity threshold of 0.22. Tags are stored in `asset_tags` with source `'semantic_auto'` and appear in the asset detail panel as "Auto tags."

Classification can be triggered three ways:
- **On demand** via the "Classify photos" button on the Publish page.
- **Automatically** after meaning search completes, when "Auto-classify photos after meaning search" is enabled in Settings.
- **Via API** at `POST /api/classify/start` with progress polling at `GET /api/classify/status`.

### XMP sidecar file support

A new `xmp_sidecar.py` module writes standard XMP sidecar files (`.xmp`) alongside photos. These contain `dc:subject` keywords, `dc:title`, `dc:description`, `lr:hierarchicalSubject`, and `Iptc4xmpExt:PersonInImage` — the same fields that Lightroom, Capture One, and other DAM tools read from sidecar files. This is the safe option for users who don't want to modify their original photos.

### Configurable write mode

A new "Metadata publishing" section in Settings lets users choose how LensLedger writes metadata:
- **Embedded** — modifies JPEG/HEIC files directly (with safety backups and pixel verification, as before).
- **Sidecar** — writes `.xmp` files next to photos without touching originals.
- **Both** — writes embedded metadata and creates sidecar files.

The setting is stored in `settings.json` under `publish.write_mode`.

### "Write tags to photos" batch action

The Publish page now has a "Write all tags" button that writes all accumulated metadata (semantic auto-tags, confirmed people names, OCR-extracted text) to photos in the configured write mode. This combines what was previously people-only publishing into a single action that covers all scan results.

A per-photo "Write tags" action is also available via `POST /api/write-tags` with an asset ID.

### Updated docstring

The `photo_index.py` module docstring has been updated to reflect that scan results can now be written back to photos via the publish system, replacing the previous "never modify photos" language.

### New files

- `src/semantic_classify.py` — CLIP-based photo classification against a vocabulary.
- `src/xmp_sidecar.py` — XMP sidecar file generation.
- `tests/test_metadata_writeback.py` — tests for classification, sidecar writing, settings, and API endpoints.

### New API endpoints

- `POST /api/classify/start` — start background classification of all semantically-indexed photos.
- `POST /api/classify/cancel` — cancel a running classification.
- `GET /api/classify/status` — poll classification progress.
- `POST /api/write-tags` — write all tags to a single photo (`id` + optional `write_mode`).
- `POST /api/write-tags/batch` — batch write tags to all photos (`scope`: all/classified/people).

- Test suite: 113 tests passed (Python 3.11).
- XMP sidecar files verified to contain correct namespace declarations, keywords, people, titles, and descriptions.
- Semantic classification verified to store tags with correct source and confidence values.
- Settings page verified to include metadata publishing section with write mode and auto-classify toggle.
- Asset detail API verified to return `auto_tags` and `write_mode` fields.
- Classify status endpoint verified to return idle state.
- Write tags endpoint verified to create sidecar files in sidecar mode.
