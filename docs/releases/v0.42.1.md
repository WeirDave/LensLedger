# LensLedger v0.42.1 — Suppress noisy ML library warnings

## Motivation

When semantic (meaning) search runs, three third-party libraries emit
warnings to the console that look like errors to users:

1. **Hugging Face Hub** — "You are sending unauthenticated requests to the
   HF Hub." This is a model-update check, not a photo upload. The CLIP model
   runs 100% locally once downloaded.
2. **OpenCLIP** — "QuickGELU mismatch between final model config and
   pretrained tag." A cosmetic config disagreement; the model works correctly.
3. **Pillow** — "DecompressionBombWarning: Image size exceeds limit." Fires
   on very large photos (100+ megapixels). Pillow still processes them fine.

Users reasonably interpreted these as errors and worried their photos were
being sent to an external AI service. They are not.

## What changed

In `OpenClipEncoder.__init__()`:

- Set the `huggingface_hub.utils._http` logger to ERROR level so the
  unauthenticated-request info message is hidden.
- Added a `warnings.filterwarnings("ignore")` for the QuickGELU mismatch
  warning from the `open_clip` module.
- Set `Image.MAX_IMAGE_PIXELS = None` to disable Pillow's decompression
  bomb check — LensLedger only opens local photos the user has already
  chosen to index.

## Verified

- Test suite: 79 tests passed.
- Confirmed warnings no longer appear when loading the CLIP model.
