## Context

When publishing metadata fails on a corrupt JPEG (missing EOI marker, truncated data, or a PNG saved with a `.jpg` extension), the only option was to Google the error, open the file in Paint or Photoshop, and re-save it manually. That's a lot of friction for something Pillow can fix in one line.

## What changed

**Built-in Repair button.** Each failed file in the Publish failure table now shows a "Repair" button (for publishable file types only — JPEG, HEIC/HEIF). Clicking it:

1. Creates a timestamped safety backup under the backup root (`{stem}.before-repair-{timestamp}{ext}`)
2. Opens the image with Pillow's `LOAD_TRUNCATED_IMAGES` enabled
3. Converts to RGB and re-saves as JPEG at quality 95
4. Preserves EXIF data when present
5. Preserves JPEG chroma subsampling (`subsampling: "keep"`) for files that are actually JPEG-encoded — skips this for non-JPEG originals (e.g. a PNG saved with a `.jpg` extension) to avoid a Pillow error
6. Updates the asset record in the database (size, mtime, indexed_at)
7. If anything fails, restores the original from the backup

After repair, the button changes to "Repaired" and the reason text updates to "Repaired — re-publish to write metadata", prompting the user to run publish again.

**API endpoint.** `POST /api/publish/repair` with `{path: "relative/path.jpg"}`. Path-traversal safe — resolves against the library root and validates containment.

## Fixed during testing

The initial implementation used `subsampling: "keep"` unconditionally. When repairing a PNG file that had been saved with a `.jpg` extension, Pillow raised `"Cannot use 'keep' when original image is not a JPEG"`. Fixed by checking `img.format` and only applying `subsampling: "keep"` when the original is actually JPEG-encoded.
