## Why this release

A photo location scan that follows a large clean-up of the library could appear
to stop just short of the end. The progress bar and the console stayed on the
last "Discovered … media files" count while the scan kept working.

At the end of each scan, files that are no longer in the library are removed
from the index. Removing a photo also clears its rows in the face data, which
had no index on the photo it belonged to, so every removal read through all
stored faces. With tens of thousands of detected faces this took around half a
second per deleted file, and none of this step was reported as progress.

## What changed

- The face data and the metadata-publishing history are now indexed by photo.
  The indexes are created automatically the first time LensLedger opens the
  database after updating, which takes a few seconds on a large library.
- While deleted files are being removed, the "Photo locations (GPS)" card on
  the Scan photos page reads "Removing deleted files from the index — N / total…"
  and the console logs the same count every ten seconds.

## Verified

- Full test suite: 203 tests, all passing, on Python 3.12.10 — up from 202.
- A new test deletes files between two scans and checks that the removal is
  reported with its total, that every deleted file is removed, and that both
  new indexes exist.
- On a library of about 48,000 files and 96,000 detected faces, looking up a
  photo's face rows took about 0.4 seconds without the index.
