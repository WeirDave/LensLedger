## Why this release

Since v1.9.0, a restart is refused while a long job is running, with a
message saying to wait for it to finish or stop it first. Some of those jobs
have no stop control on the page where the message appears — in particular
the photo location scan that runs each time LensLedger starts — so "stop it
first" could not be acted on.

## What changed

- **Banner:** in the "Server is running … on disk" banner, a refused
  "Restart now" now changes to **"Stop and restart"**. Clicking it stops the
  running job at its next safe point, waits for it (up to a minute), and then
  restarts. The banner reads "Stopping the running job, then restarting…"
  while this happens.
- **Menu:** the notice from "🔄 Restart server" (menu ☰, under "Help &
  Support") shows a **"Stop and restart"** button when the restart is
  refused, with the same effect.
- **Update panel:** "Update now" and "Restart" ask whether to stop the
  running job and continue.
- The stop is the same one Ctrl+C in the LensLedger window uses: each job
  finishes the item it is on and leaves nothing half-written. The photo
  location scan runs again after the restart.
- If a job has not stopped within a minute, the restart is not started and
  the message says which job is still running.

## Verified

- Full test suite: 219 tests, all passing, on Python 3.12.10. A new test
  starts a simulated location scan, asks for "Stop and restart", and checks
  that the scan is told to stop, stops, and the restart then goes ahead.
- Checked in the browser against a generated test library, with the server
  replies stubbed: after a refusal naming the photo location scan, the banner
  button read "Stop and restart" and the menu notice showed a "Stop and
  restart" button; clicking either sent the restart with the stop request
  and showed "Stopping the running job, then restarting…".
