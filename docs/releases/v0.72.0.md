## Motivation

Two bottlenecks remained in the Name Faces matching flow:

1. **Reviewing obvious matches**: with 50,000 faces, most matches at similarity
   ≥0.75 are clearly the same person. Reviewing them manually wastes time.
2. **Metadata writing**: ExifTool reads and rewrites each JPEG file to embed
   person names. At ~1 second per photo, confirming 200 faces meant waiting
   3+ minutes for file I/O before the next round could even start.

## What changed

### Auto-confirm high-confidence matches

`find_more_faces` now splits results into two tiers:
- **High confidence (≥0.75)**: auto-confirmed in the database immediately, no
  review needed. The match group header shows how many were auto-confirmed.
- **Borderline (0.65–0.75)**: returned for manual review as before. These are
  the ambiguous ones where human judgment matters.

This means the user only sees faces that actually need their attention. A person
with 500 matches might have 450 auto-confirmed and only 50 shown for review.

### Deferred metadata publishing

`name_face_batch` no longer writes JPEG metadata during confirmation — it only
writes database records (sub-second for hundreds of faces). A new endpoint
`/api/faces/publish-person` handles all metadata writes at once after the
matching chain is exhausted.

The frontend calls `publishPerson()` only when `find_more_faces` returns zero
matches (no more to review or auto-confirm). This means the interactive
confirm-and-search loop runs at database speed, and the slower metadata
publishing happens exactly once at the end.

### Frontend changes

- Match group header shows "N auto-confirmed, M to review" when auto-confirms
  happened.
- Progress bar updates with "Writing [name] to photo metadata..." during the
  final publish phase.
- When only auto-confirms remain (no borderline matches), a brief status banner
  shows the count before publishing.

## Verified

- **Test suite**: 80 tests, all passed.
- Auto-confirm correctly splits matches at the 0.75 threshold.
- Batch confirmation skips metadata publishing (DB-only).
- Publish endpoint writes metadata for all confirmed assets of a person.
- Frontend chains correctly through auto-confirm → review → publish.
