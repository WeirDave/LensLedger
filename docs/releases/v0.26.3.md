Fixed the fix. 0.26.2 shipped a same-day answer to "why do I need to hit
Enter?" — and got the wrong event.

## `change` vs. `input`

0.26.2 listened for the input's `change` event to auto-save a datalist
pick. That's the event you'd reach for by default, and it's wrong here:
`change` only fires once the field loses focus — exactly the "click
something else first" behavior the user was reporting as the bug. Picking
a suggestion from a datalist dropdown actually fires `input` immediately,
per the HTML spec; `change` follows later, on blur, same as it would for
any manually typed text.

Swapped the listener to `input`. A pick now saves the moment it's made.
Typing a brand-new name still doesn't trigger a save mid-keystroke,
because the check requires an exact match against a known person — it
can't match until the name is fully typed, at which point Enter or Save
is still the deliberate confirmation for "yes, create this new person."

## Verified

- Full automated suite (64 tests) green.
- Manually verified against the real library, live: dispatched the actual
  event a real datalist selection fires (`input`, not a synthetic
  `change`) and confirmed the face saved and its card cleared in under a
  second. Separately typed a new name character-by-character and
  confirmed no premature save — it only commits on Enter/Save, as before.
