## Context

When opening the Name faces page, there was no visual feedback while the
initial batch of faces loaded from the server. Users saw the intro text,
an empty grid, and the "No unidentified faces" empty state all at once,
which made it look like the page was broken or had nothing to show —
leading to premature button clicks.

## What changed

Added a centered loading overlay with a spinner and "Loading faces..." in
large text. While the initial fetch runs:

- The overlay is the only visible content in `<main>`
- The intro paragraph, face grid, match groups, and empty state are all
  hidden via the HTML `hidden` attribute
- The header bar still shows "Loading faces..." in the progress area

Once the fetch completes (success or error), the overlay disappears and
all page content is revealed.

### Implementation details

- HTML: loading overlay div added as the first child of `<main>`; intro,
  match-groups, and face-grid start with `hidden` attribute
- CSS: spinner animation, overlay styling, and `[hidden]` overrides for
  elements whose class rules set `display: grid` (which otherwise
  overrides the `hidden` attribute's built-in `display: none`)
- JS: `initialLoadDone` flag prevents `checkEmpty()` from showing the
  empty state before the first fetch completes; the `finally` block of
  `loadMore()` unhides all content and dismisses the overlay

## Verified

- Test suite: 79 tests passed.
- Browser verification: simulated the loading state and confirmed only
  the spinner and heading are visible; all other content is hidden.
  After loading completes, the overlay disappears and face cards,
  intro text, and controls appear correctly.
