## Fix CI test failures for model management

The v0.98.2 release added model download visibility and settings-based model selection to `_run_semantic_index_job`. This introduced calls to `encoder_for()` and `model_cache_info()` via local imports inside the function, which made them impossible to patch in tests. In CI (where open_clip and torch are not installed), `encoder_for()` raised a `RuntimeError`, causing two tests to fail.

### Root cause

The function used a local `from semantic_index import encoder_for, model_cache_info, SUPPORTED_MODELS` inside `_run_semantic_index_job`. Because these were local imports, `patch.object(photo_search, ...)` couldn't intercept them — the function bound directly to the imported names, bypassing any module-level patches.

### Fix

- Removed the local import from `_run_semantic_index_job`
- All semantic_index functions are now imported at the top of `photo_search.py` with aliased names (`semantic_encoder_for`, `semantic_model_cache_info`, `SEMANTIC_SUPPORTED_MODELS`)
- The function references these module-level names, which tests can patch
- Updated both affected tests (`test_optional_semantic_job_and_viewer_scope` and `test_scan_all_chains_all_four_steps_when_optional_scans_are_installed`) to also patch `semantic_encoder_for` and `semantic_model_cache_info`
- Added `MagicMock` to test imports

## Verified

- Test suite: 101 tests passed
- Both previously-failing tests now pass with the patched encoder and model cache
