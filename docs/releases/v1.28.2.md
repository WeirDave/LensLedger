# Safer scans, longer-lived safety copies, working menu buttons

## Why this release

Five defects could lose data or leave controls dead:

- A scan of a photo folder that was unavailable emptied the index.
- Safety copies of older photos were deleted straight after being made.
- Saving the current library forgot where its database lives, and forgot libraries on drives that were not connected.
- A failed bulk move to the Review Bin could leave files in the bin with the library still listing them.
- Three buttons did nothing because the page blocks inline scripts.

## What changed

### Scanning

- A scan now stops with an explanatory message when the photo folder cannot be reached, for example an unplugged drive or a disconnected network share. The index is left as it was. Previously every photo counted as deleted, and the people, tags and review history attached to them were removed. The automatic check every few minutes was affected the same way.
- A scan that finds no photos at all in a folder whose index holds photos also stops and leaves the index unchanged.
- A subfolder that cannot be read during a scan is counted under **errors** on the **Scan your photos** page, and the folder name is listed in the error details. Its photos stay in the index instead of being removed. Photos deleted elsewhere in the library are still removed as before.
- A first scan of a folder that exists but is empty still completes normally.

### Safety copies

- The age of a safety copy is now taken from the date and time in its file name, which is when the copy was made. It was taken from the file's modified time, which a copy inherits from the photo, so a copy of a photo last changed more than 30 days earlier was removed by the next clean-up. The setting **Keep photo safety copies for (days)**, under "Metadata publishing" on the Settings page, applies to the copies as intended, and **Undo** and **Restore from safety copy** keep working for that period.
- The same age decides which copies are removed first when the total exceeds **Total size limit for safety copies (GB)**.
- A file without a timestamp in its name falls back to its modified time.

### Libraries

- Saving the current library, which happens after every scan, no longer discards the record of where each library's database is stored. A library whose database is kept in the application data folder keeps opening its own database after a scan and a restart.
- Libraries whose folders are not currently available, such as a library on a disconnected drive, stay in the list of known libraries and remain available under reconnect.
- **Remove** next to a library on the Settings page removes only that library. **Relocate** keeps the other entries and the database locations.

### Review Bin

- If moving several photos to the Review Bin fails part way, for example because one file is locked or an id is repeated, the photos already moved are returned to their folders and the library is left unchanged. Previously they stayed in the bin while the library still listed them at their original locations.
- Moving a single photo is protected the same way.

### Menu buttons

- **Report an issue** and **Copy diagnostics** in the navigation menu work again on every page. They were attached as inline handlers, which the page's content security policy blocks.
- **Got it, don't show again** on the People page now dismisses the introduction and keeps it hidden on later visits.
- A new test fails if any served page contains an inline event handler attribute.

## Not changed

- No database or settings format changes. Existing libraries, safety copies and state files are read as before.
- Photos moved to the Review Bin without an error behave as before.

## Verified

- Full test suite: 492 tests, all passing.
- New tests cover a scan of a missing folder, of a folder that has become empty, of a library with an unreadable subfolder, and of a library with ordinary deletions; the age of a safety copy of an old photo; library state kept across a save, a removal and a relocation; a bulk move that fails part way (this test fails without the fix); and the absence of inline event handlers in served pages.
