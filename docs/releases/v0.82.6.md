The v0.82.5 release refactored inline styles in `viewer.js` into CSS classes. During that refactor, the `openMenuPanel` function was reformatted from a single ~2000-character line into readable multi-line code. The rewrite introduced Unicode smart quotes (RIGHT SINGLE QUOTATION MARK, U+2019) as JavaScript string delimiters throughout the function — 104 right and 25 left single quotation marks. JavaScript does not recognize these as string delimiters, so the entire viewer page failed to load with `SyntaxError: Invalid or unexpected token`.

## What changed

Replaced all Unicode smart single quotes (U+2018, U+2019) with ASCII single quotes (`'`) in `viewer.js`. For strings containing English apostrophes (`don't`, `file's`, `Person's`), switched the string delimiter to double quotes so the apostrophe doesn't terminate the string.

Also replaced the same smart quote in `person-picker.js` (one occurrence in `"New person's name"` placeholder text — this was content inside an HTML attribute and did not cause a syntax error, but was inconsistent).

## Fixed during testing

The initial smart-quote replacement (global find-and-replace of U+2019 → `'`) fixed the string delimiters but created three new syntax errors where English apostrophes now collided with the single-quote string delimiter:
- Line 186: `You don't need to name every face` — changed to double-quoted string
- Line 223: `the file's metadata` — changed to double-quoted string
- Line 352: `Person's name` placeholder — changed to double-quoted string

After fixing, browser verification initially appeared to still fail due to the immutable cache header (`max-age=31536000`) serving the old broken `?v=0.82.5` file from cache. Bumping the version to 0.82.6 generated new cache-busted URLs (`?v=0.82.6`), and a fresh browser tab confirmed the fix.
