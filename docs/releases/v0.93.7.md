## What changed

The scan error dialogs (OCR errors, face detection errors, etc.) had two usability issues:

1. **"Copy path" copied the full file path**, but the typical workflow is to click "Open folder" (which opens Explorer/Finder to the containing directory) and then search for the file. Pasting a full path into Explorer's search bar doesn't help — you need the filename.

2. **File paths looked like clickable links** (accent color, underline on hover, pointer cursor) but clicking them did nothing. This was confusing — they appeared interactive but weren't.

## How it works now

- **"Copy filename" button** extracts and copies just the filename (e.g. `IMG_6319.JPG`) instead of the full path. This pairs naturally with the "Open folder" button: open the folder, then paste the filename into the search bar to find the file.

- **Paths are plain selectable text** — still styled in the accent color for visibility, but with a text cursor and no hover underline. You can click and drag to select the path text if you need the full path as a fallback.

## Verified

- Test suite: 88 tests passed.
- Browser verification: confirmed the error modal shows "Copy filename" buttons and paths render as plain selectable text without link-like hover behavior, in both light and dark themes.
