# Combinable filters and saved collections

## Why this release

- The search scope menu mixed what to search (image tags, folder context, meaning) with whole views (people, duplicates, needs tags). Only one date, one person and one minimum rating could be applied, and Meaning search ignored the date and rating filters altogether.
- Nothing about a photo's camera, size or shape was searchable, and a search could not be saved to run again.
- A search that matched more than about 32,000 photos ended in an error, because the matches were passed to the catalog as one list that SQLite limits.

## What changed

### More filters

- **More filters** is a button in the toolbar on the home page, next to the Rating menu. It opens a panel with these fields, all empty by default:
  - **Taken from** and **Taken until**: a range of dates typed as `YYYY-MM-DD`, either of which can be left empty.
  - **People (all of them)**: one or more people. A photo is shown only when every selected person is confirmed in it. A face that is only suggested does not count.
  - **Type**: photos, videos or RAW files.
  - **Shape**: landscape, portrait or square, judged from the picture's size after any rotation the camera recorded.
  - **Location**: photos that have a GPS location, or that have none.
  - **Camera**: part of the camera make or model.
  - **Folder contains**: part of a folder name, matched literally.
- Filters combine with each other, with the search box, the date picker, the Rating menu and every search scope, including Exact duplicates, Similar photos, Needs tags and Meaning search. An invalid date is ignored.
- Every active filter appears as a button under the toolbar. Choosing it removes that filter. The panel opens by itself when a filter is active, and the button shows how many are.
- On a narrow screen the filters sit behind the existing **Filters** button, with **More filters**, **Collections** and **View** in one row.

### Collections

- **Collections** in the toolbar opens a window listing the saved collections of the open library, each with a **Delete** button, and a field to save the current search under a name with **Save current search**. **Save as collection…**, under the toolbar when a filter is active, opens the same window with the name field selected.
- A collection stores the search, its scope and its filters, not the photos, so photos added later that match it appear in it. The page number and the selected photo are not stored.
- Saving under a name already in use, in any capitalisation, replaces that collection. A search with nothing set cannot be saved. A library keeps up to 100 collections, and each library has its own.
- Deleting a collection does not affect any photo.

### Meaning search and large searches

- Meaning search ranks every indexed photo and then applies the date, rating, people and other filters, so the first page shows the best matches among the photos that pass. Without a filter it behaves as before. The "rated" note in the page heading now also appears for Meaning search.
- A search matching more than about 32,000 photos returns its results. The matches are held in a temporary table in place of a single long list.

### Camera, size and shape

- During a scan, the camera make and model and the picture's width and height are read from each photo and stored in the library's database (schema version 27). A library indexed by an earlier version reads them once, on its next scan. Videos and RAW files have none and are left out when these filters are used.

### Duplicates

- **Keep best copies** in the Exact duplicates view acts on the sets that the current filters show.

### Documentation

- The manual, in the written manual and on the manual page, describes More filters and Collections, and the README lists them under highlights. The earlier statement that the Rating menu does not apply to Meaning search now describes what happens.

## Not changed

- The Search scope menu keeps its current entries. Existing links and bookmarks keep working.
- No photo or file is changed.

## Verified

- Test suite: all tests passing, including new ones for reading and validating each filter, every filter run against a catalog of generated photos (shape, type, date range, folder, camera, location and several people at once), camera and size being read during a scan and filled in for an older library, a camera orientation swapping width and height, long lists of ids being checked in chunks, saving, listing, replacing and deleting collections with a limit of 100, the page's filter buttons and panel, Meaning search narrowed by filters, a search matching 33,000 photos in both sort orders, and Keep best copies honouring the filters.
- Browser: the toolbar, filter panel, filter buttons and the Collections window were checked in the light and dark themes at desktop width, and the collapsed and open filter controls at phone width, against a generated library.
