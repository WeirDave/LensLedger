## Context

After clicking "Restart" in the stale-version banner, the new console
window opened but was completely blank — no startup messages, no banner,
nothing. The server worked fine (browser loaded), but the terminal showed
nothing. The "Loading LensLedger..." message from v0.43.7 flashed briefly
then vanished.

## Root cause

In `lensledger_updater.py`, `launch_lensledger()` created the new cmd.exe
process with both `stdin=subprocess.DEVNULL` and
`creationflags=CREATE_NEW_CONSOLE`. On Windows, when Python's `subprocess`
receives any explicit standard handle (even just stdin), it populates all
three handles in `STARTUPINFO`. Since stdout and stderr weren't specified,
Python filled them from the parent process's handles — which were the
updater's log file (`last-update.log`). This meant `CREATE_NEW_CONSOLE`
created the visible window, but the process's stdout pointed at the log
file instead of the console. All output — the .cmd echo, the Python
loading message, and the full startup banner — went to the log file.

Confirmed by reading `%LOCALAPPDATA%\LensLedger\Updates\last-update.log`,
which contained the complete startup output that should have appeared in
the console.

## What changed

Removed `stdin=subprocess.DEVNULL` from the Windows path in
`launch_lensledger()`. With `close_fds=True` and `CREATE_NEW_CONSOLE`
alone, the new process gets proper console handles for all three streams.
This also means `pause` at the end of `Start LensLedger.cmd` works
correctly (it was previously reading from DEVNULL and would have returned
immediately).
