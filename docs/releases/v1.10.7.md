## Why this release

Before writing into a photo, LensLedger makes a safety copy named after the
photo with a label and timestamp added, such as
`.before-people-<timestamp>.jpg`. For a photo whose filename was already
close to the 255-character limit that most filesystems place on a single
name, the added text pushed the copy's name over the limit. Windows rejected
it with "The filename, directory name, or volume label syntax is incorrect"
(WinError 123), and the photo was listed under "photos failed" on the
Publish photos page without anything being written.

## What changed

- Safety-copy names that would exceed 255 characters are shortened. The end
  of the photo's name is trimmed and replaced with a short hash of the full
  name, so two long names that begin the same way still get separate copies.
  The label and timestamp are kept, so the copy is still recognised,
  counted and pruned as a safety copy.
- Applies to every write that takes a safety copy: publishing people
  metadata, "Write all tags", restoring from the Publish photos page, and
  "Repair".
- Photos with shorter names get the same copy names as before. Restoring a
  photo uses the copy's recorded location, so shortened names restore
  normally.

## Verified

- Full test suite: 232 tests, all passing. New tests check that short names
  are unchanged, that a long name is shortened to 255 characters or fewer and
  can be written to disk, and that two long names sharing a prefix produce
  different copy names.
- Reproduced the original failure outside the app: copying a file to a
  270-character name on Windows raised WinError 123. The shortened name was
  written successfully.
