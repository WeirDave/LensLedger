# Scans remove deleted and moved photos much faster

## Why this release

- When many photos had left the library folder, the next library scan removed them from the index one at a time. Each removal read the whole search index, so the larger the library, the slower every removal became.
- The whole removal was saved only at the end. Until then, other changes had to wait and could fail, and a scan that stopped partway kept none of the removals.
- Moved photos, emptying the trash, and rebuilding the search index read the whole search index once or more for each photo in the same way.

## What changed

### Library scans

- Photos that are no longer in the library folder are removed in batches of 500, with one pass over the search index for each batch.
- Each batch is saved as soon as it is done, with a short pause before the next so that other changes can be saved. The removal count shown during the scan advances one batch at a time.
- **Pause scan** also stops removal, between batches. Photos already removed stay removed, and the next scan removes the rest.
- A photo moved to the trash or put back in the library folder while a scan is running is still kept, along with its tags and people.
- Photos moved to another folder within the library are matched to their new location with far fewer passes over the search index. Their tags and people are kept, as before, and the matching is still saved all at once.
- Photos new to the library are added to the search index without first searching it for an older entry.
- Search index entries that belong to no photo are cleared at the start of a scan.
- Two database indexes were added so that removing a photo no longer reads the whole People review history and trash list. They are created automatically when the database is next opened.

### Trash

- **Empty trash** deletes photos in batches of 500 and saves each batch as it finishes. A photo restored while the trash is being emptied is kept.

### Command line

- `database_tools.py rebuild-search` no longer searches for an old entry before writing each new one.

## Verified

- Full test suite: 785 tests, all passing.
- On a large generated test library, removal of missing photos went from about 35 photos per second to more than 2,500.
- On the same library, a scan that found 2,000 photos moved to new folders went from about 230 seconds to about 19.
- Another program writing to the database while photos were being removed waited about a tenth of a second at most. Before the change, most of its attempts gave up after 30 seconds.
