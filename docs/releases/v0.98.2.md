## Model download visibility and settings-based model selection

When running meaning search with a model that hasn't been downloaded yet (e.g. switching to ViT-L-14 for the first time), the download could take many minutes with no feedback in the terminal log or scan page — the status just showed "Loading the optional local meaning model…" the entire time.

### Download progress in logs

The semantic indexing job now checks whether the selected model file exists on disk before loading it. If the model needs downloading:
- The terminal log shows: `Meaning search: Downloading model ViT-L-14 (~1.8 GB)… this may take several minutes`
- The scan page status updates to the same message
- After the download completes, indexing proceeds normally with the usual progress updates

If the model is already cached, the log shows `Meaning search: loading model ViT-L-14/openai` instead.

### Settings-based model selection

Previously, `build_semantic_index` always used the default model (`ViT-B-32/openai`) regardless of what was selected in Settings. Now the indexing job reads `settings.scan.semantic_model` and passes the configured encoder to `build_semantic_index`, so changing the model in Settings actually takes effect on the next run.

## Verified

- Test suite: 101 tests passed
- Download detection uses `model_cache_info()` to check for cached `.pt` files before loading
- Model selection reads from settings and falls back to default if the configured model is unsupported
