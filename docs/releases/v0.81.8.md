## What changed

The Publish photos page showed "Starting publish..." with a progress bar stuck at 0% for the entire duration of a publish run. For large batches (e.g. 330 photos), this could take several minutes with no visual feedback — the bar only jumped to 100% when everything was done.

The publish operation itself worked correctly and logged progress to the server console, but the frontend had no way to see intermediate progress because the `/api/publish/run` endpoint returned a single response only after all photos were processed.

## How it works now

The backend now tracks publish progress in a shared state variable (`publish_progress`) that updates after each photo is written. A new `/api/publish/progress` GET endpoint exposes this state.

The frontend polls this endpoint every 500ms while a publish is in progress, updating:
- The progress bar fill width (percentage)
- The progress text ("42 of 330 photos")
- The top-right status badge ("42/330")

When the publish completes (or fails), polling stops and the final result is shown as before.

## Verified

- Test suite: 88 tests passed
- The progress tracking is purely additive — no changes to the publish logic itself, only instrumentation around the existing loop
