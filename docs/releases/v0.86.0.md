## Motivation

Several UX friction points in the photo viewer's people workflow needed attention:

1. **Named face boxes weren't clickable.** If a face was tagged with the wrong person, the only way to fix it was to find the person chip in the sidebar and remove it — there was no way to click the bounding box on the photo itself and correct it directly.

2. **Removing a tag or person chip was slow.** Clicking the X on a chip waited for the API call to complete and then reloaded the entire asset detail before removing the chip from the DOM, making it feel sluggish.

3. **Person picker search was poorly ordered.** Typing "Ter" wouldn't show "Terri" because all matches were sorted alphabetically — "Peters" appeared before "Terri" since "P" < "T". The dropdown's limited height meant starts-with matches were pushed out of view.

4. **Merged people still appeared as separate entries.** After merging "Tim Dominick" into "Timothy Charles Dominick Jr", the old name still showed up as a separate choice in person pickers.

## What changed

### Clickable named face boxes

Named face bounding boxes (the golden boxes on identified faces) now respond to clicks. The CSS changed from `pointer-events: none` to `cursor: pointer; pointer-events: all`. Clicking opens a face corrector popover anchored to the box with two options:

- **Remove [name]** — removes the person assignment from that face
- **Change to:** — opens a person picker to reassign the face to someone else

The popover uses CSS variables (`--surface2`, `--input-border`, `--danger`, etc.) so it renders correctly in both light and dark mode.

### Optimistic UI for chip removal

Tag and person chip removal now uses optimistic updates: the chip is removed from the DOM immediately when the user clicks X, before the API call completes. If the API call fails, the full asset detail is reloaded to restore the correct state. This makes removals feel instant.

### Starts-with sort priority in person picker

The person picker's search now sorts results in two tiers: names that start with the query appear first, followed by names that merely contain it. Within each tier, names are sorted alphabetically. This means typing "Ter" shows Terence and Terri at the top, with Peters and Peter below.

### Alias-aware person picker

The `people_options` API endpoint no longer returns merged aliases as separate entries. Instead, it returns only primary names plus a separate `people_alias_map` dictionary (`{alias: primaryName}`). The person picker searches both primary names and aliases, displaying alias matches with a "(was: old name)" hint. This works across all three pages that use the picker: viewer, faces-review, and people-review.
