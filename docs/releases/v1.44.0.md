# Photos are tagged with what they show, from about 500 subjects

## Why this release

- Automatic tags were chosen from a list of about 50 broad categories such as landscape, beach and food. Common subjects outside that list, for example a deer, a bridge or a birthday cake, could not be tagged.
- Tagging was a separate step that ran only when started on the **Publish photos** page or when an optional setting was on, so a full **Run all scans** left photos indexed for meaning search but untagged.

## What changed

### Photo tagging

- The list that tags are chosen from now holds about 500 subjects, scenes and activities: animals, birds and insects, plants, landscapes, buildings and places, vehicles, food and drink, everyday objects, sports and events, and photographic styles. The earlier 50 categories are part of it.
- A photo keeps the tags that stand out for it: a tag must score close to the photo's best match, up to five tags per photo. A photo that matches nothing well is left untagged rather than given weak tags. The minimum score is 0.19 (previously a fixed 0.22 for every tag).
- Photos that were tagged under the earlier list are tagged again the next time tagging runs, and their previous automatic tags are replaced. This happens once per library.
- Tagging reads each photo's meaning data with the model that created it. Photos indexed with a model other than the default are now tagged; previously they produced no tags.
- The meaning-search model is loaded only when photos need tagging, so a run with nothing to tag finishes without loading it.
- Matching uses a single matrix product when NumPy is installed, so tagging a large library with the larger list stays fast.

### Run all scans

- **Run all scans** on the **Scan your photos** page now runs photo locations, text recognition, meaning search, photo tagging, and face detection, in that order. Photo tagging runs whenever meaning search is set up.
- A failure in photo tagging is reported in the run's summary and does not stop face detection.
- Stopping **Run all scans** also stops photo tagging after the photo being processed.

### Publish photos page

- A new **Re-tag all photos** button sits beside **Classify photos**. It replaces the automatic tags on every photo using the current list. **Classify photos** still tags only photos that have no automatic tags.

### Settings

- **Auto-classify photos after meaning search** (Settings, Metadata publishing) is now on by default. Existing installs keep the value they have saved. The setting applies to meaning search started on its own; **Run all scans** tags photos either way.

### Manual

- The **Run all scans** section describes the photo tagging step, the **Re-tag all photos** button and the new setting default.

## Verified

- Full test suite: 685 tests passing. New tests cover the list of subjects, keeping only standout tags, the minimum score, the five-tag limit, re-tagging after a list change, **Re-tag all photos**, an interrupted pass, skipping the model load, and meaning data from a different model.
