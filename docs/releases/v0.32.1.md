Feedback on the Scan photos page: "chunky and clunky," wants a compact,
polished pass. `web/css/scan-photos.css` was only 33 lines but dense with
repeated magic numbers -- no shared spacing or radius scale, so every card,
tile, and control carried its own slightly-too-generous padding and
rounding (14px card radius, 22px card padding, 9px tile radius, 21px stat
numbers) with nothing tying them together.

Rewrote the file around a small consistent scale
(`--radius-lg/md/sm` at 10/8/6px) instead of one-off values, and pulled
every size down a notch: card padding 22px → 15px×17px, stat-tile padding
12px → 9px×10px, stat numbers 21px → 18px, section headings 17px → 13.5px,
job-status/job-actions gaps and margins trimmed by 2-4px each, progress
bar 8px → 6px tall, buttons 10px×15px → 8px×13px. The header row, spinner,
and date input all got the same treatment. No structural or DOM changes --
every element the JS targets by class/id is untouched, this is styling
only, and the same tightening carries through the `@media(max-width:700px)`
mobile rule.

## Verified

- Full automated suite: 79 tests, all green
  (`PYTHONPATH=src python -m unittest discover -s tests`) -- confirms the
  CSS-only change didn't touch anything the Python test suite exercises.
- Loaded the page against a scratch library on a separate server instance
  and confirmed via computed styles that the new values are actually
  applied (10px card radius, 13.5px headings, 18px stat numbers) and that
  no console errors appear.
- Could not capture a pixel screenshot in this session (the browser pane
  rendered at a 0px-height viewport throughout, so what did render was
  measured through the mobile breakpoint, not the desktop layout) --
  worth an actual look at real desktop width before calling this done;
  happy to iterate further on specific spots that still feel off.
