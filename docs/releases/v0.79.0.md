# LensLedger v0.79.0 — Reconnection screen and multi-library startup picker

## Motivation

When a library's folder disappeared — a removable drive was unplugged, a folder was moved, or a cloud sync hadn't finished — LensLedger fell back to the OS Pictures folder and showed the first-run "Set up LensLedger" screen. This made users think they had lost all their data. A real user hit this scenario and panicked because the page said "Choose your first library" and "Build my library," with no indication that their existing library was fine.

Separately, users with multiple libraries had no way to choose which one to open at startup — the app always auto-opened the last-used library.

## What changed

### Reconnection screen (Problem 1)

When LensLedger detects that known libraries exist in its state file but the current database has no assets (indicating a disconnected library), it now shows a "Welcome back" screen instead of the first-run setup. This screen:

- Lists all known libraries with their accessibility status ("Ready" or "Not found")
- Highlights the last-used library with a "Last used" badge
- Shows which libraries have an existing index ("Indexed" badge)
- Clearly states **"your data is safe"** — the drive was disconnected or the folder was moved
- Offers a Browse button to point to a new location
- Includes a "Set up a new library instead" escape hatch that goes to the original onboarding page

The true first-run onboarding screen only appears when there are genuinely no previously known libraries.

### Multi-library startup picker (Problem 2)

A new "Ask which library to open at startup" toggle in Settings → Photo libraries. When enabled and multiple accessible libraries exist, opening LensLedger shows a library picker instead of auto-opening the last-used library. The picker:

- Lists all accessible libraries with selection
- Includes an inline toggle to turn the picker preference on or off
- Saves the preference via the existing settings API

Once any query parameter is present (sort, search, scope, etc.), the picker is bypassed and the normal viewer loads — so bookmarks and deep links still work.

### Backend changes

- Added `load_all_known_libraries()` to `library_config.py` — returns every library ever recorded, including ones whose folders no longer exist, with accessibility status and current-root flags
- Added `startup.show_library_picker` to settings defaults
- Added `/api/library/reconnect-options` GET endpoint returning all known libraries with database existence status

### New files

- `web/css/reconnect.css` — styles for both the reconnection and picker pages
- `web/js/reconnect.js` — client logic for library selection, reconnection, and the picker preference toggle

## Verified

- **Test suite**: 87 tests, all passing
- **Reconnection page**: visually verified — shows "Welcome back" with correct messaging, library list with status badges, browse and reconnect buttons
- **First-run bypass**: `?fresh=1` correctly shows the original onboarding page
- **Settings toggle**: "Ask which library to open at startup" appears under Photo libraries, saves correctly
- **Dark mode**: page inherits theme variables from theme.css correctly
