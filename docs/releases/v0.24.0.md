LensLedger can now actually find new faces — not just match against a
fixed, one-time historical import.

## The real gap behind "why is my People count too low"

Every face LensLedger has ever known about — 2,210 of them across a
50,910-photo library — came from a one-time historical import that predates
the app itself. Nothing in LensLedger could detect a *new* face in a photo
outside that original set: `face_locations.py` only ever recovered exact
bounding boxes for embeddings that already existed, and
`generate_face_suggestions.py` only ever matched embeddings that already
existed. If a face wasn't in that original import, LensLedger had no way to
ever find it — which is why photo counts per person looked too low even
for people confirmed in dozens of photos.

## Real detection, not just matching

Library health has a new "Face detection" job that runs actual face
detection — InsightFace, the same optional model already used for
bounding-box recovery — against every photo that has never been
face-scanned before. It writes the detected embedding and exact box
directly; no separate recovery pass needed. New faces need zero special
handling to become searchable: `face_learning.learn()` already scores every
row in the face table against confirmed people's profiles, so a newly
detected face is suggestion- and auto-confirm-eligible the moment it's
found.

Like meaning search, this is an optional, large local-only download — the
panel explains what it does and offers a one-click "Set up face detection"
before anything downloads. Once installed, scanning is a pausable,
resumable background job, the same shape as OCR and meaning search, built
for scanning tens of thousands of photos without blocking anything else.

## Verified

- Full automated suite (54 tests), including new coverage for detection,
  resumability (already-scanned photos are correctly skipped), and
  cancellation.
- Verified with real detection, not just mocks: installed the actual
  optional packages, ran detection against a safety copy of the real
  50,910-photo library, fed the results through the real matching pipeline
  with zero errors, then ran it live through the actual app against the
  real library — real progress, real faces found, zero errors.
