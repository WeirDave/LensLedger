# LensLedger v0.48.0 — Global settings page, collections UI, database import/export, model selection

## Motivation

LensLedger had no central place to configure its behavior. Library switching required restarting the server, scan preferences were hardcoded, the meaning search model was fixed to ViT-B-32, and there was no way to export or import the enrichment database. Users who reorganized their photos or migrated machines had no recovery path.

## What changed

### Settings page

A new `/settings` page is accessible from the navigation menu. It provides a unified configuration interface organized into sections:

- **Photo libraries** — view, add, switch, and remove photo collections without restarting.
- **Scan preferences** — configure OCR worker threads, OCR batch size, and meaning search batch size.
- **Meaning search model** — choose between ViT-B-32 (fast, small), ViT-B-16 (better quality), and ViT-L-14 (highest quality). Changing the model re-indexes photos on the next meaning search run.
- **Display preferences** — photos per page, default sort order, filmstrip thumbnail size.
- **Folder watching** — toggle automatic file detection and set the check interval.
- **Camera upload auto-ingest** — enable/disable, configure source and destination folders, define sorting rules.

Settings are persisted to `settings.json` in the LensLedger data directory alongside `library-state.json`.

### Database import/export

- **Export** creates a portable ZIP archive containing a verified copy of the SQLite database, all face data files, and a manifest recording the library root path, schema version, photo count, and app version.
- **Import** restores from a LensLedger export ZIP. If the library root has changed since the export, paths are automatically remapped. The existing database is backed up before replacement.

### Multi-model semantic search

`semantic_index.py` now supports three CLIP models instead of only ViT-B-32. The `encoder_for()` function resolves model names from a `SUPPORTED_MODELS` dictionary. The settings page exposes model selection with size and quality descriptions.

## New files

- `src/settings_config.py` — settings persistence: `load_settings()`, `save_settings()`, `get_setting()`, defaults, available models list.
- `web/css/settings.css` — settings page styles.
- `web/js/settings.js` — settings page interactivity: library management, model selection, ingest rules, save/load.

## Verified

- Test suite: 79 tests passed.
- Browser verification: settings page renders correctly with all sections, no JavaScript errors (existing CSP warnings from theme.js are pre-existing and unrelated).
- Navigation menu: Settings link appears correctly between Photo map and Help & Support.
