## Motivation

The settings page was missing all nav menu panel CSS, causing the slide-out menu to render with a full-size logo image and unstyled links. Additionally, the "Set up meaning search" button on the scan page triggered a direct pip install with no model choice — the new Settings page model section was disconnected from the install flow.

## What changed

### Settings page CSS fix

Added the full set of `.menu-panel`, `.menu-backdrop`, `.menu-close-btn`, and related styles to `settings.css`. The nav menu now slides out correctly with the brand header, navigation links, and close button properly styled — matching every other page.

### Meaning search setup moved to Settings

The scan page's "Set up meaning search" button is now a link that navigates to `/settings#meaning-search`. The Settings page "Meaning search model" section now handles the full setup flow:

- Shows install status (not installed / installing / error / installed)
- Provides an install button with confirmation dialog
- Shows an indeterminate progress bar during installation
- Polls for status updates every 2 seconds while installing
- Hides the setup area and shows model selection once installed
- Scrolls to the section automatically when arriving via `#meaning-search` hash

### Scan page changes

- The "Set up meaning search" button is replaced with a styled link ("Set up meaning search in Settings") pointing to `/settings#meaning-search`
- The link is hidden when meaning search is already installed (same behavior as before)
- "Build / resume meaning index" button remains on the scan page for running the indexer

## Verified

- Test suite: 79 tests passed
- Browser verification: Settings page renders correctly with properly styled nav menu, model section shows install status, scan page link styled correctly
