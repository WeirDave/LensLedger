A whole year of carefully-named folders just started counting.

## Folder tagging had a hard stop at 2025

`generate_historical_folder_tags.py`, the tool that turns a descriptive
folder name like "2019_04_12 - Egret, Palm Tree, Tom Stuart Bridge" into
real searchable tags, had a hardcoded rule: only folders dated 2025 or
earlier were ever considered. Every folder from this entire year — hundreds
of them — was silently skipped.

That's fixed at the root: scanning now infers tags for any folder that
doesn't have them yet, automatically, with no year cutoff and no separate
script to remember to run. When a folder's name doesn't match one of the
curated categories (birthdays, beaches, restaurants, and around 150 others),
it falls back to using the folder's own descriptive text as the tag
directly — so a folder named "Out with Candy" or "Downtown LA and Olvera
Street" always gets *something* instead of nothing.

A new `database_tools.py backfill-folder-tags` command retroactively covers
folders that were already indexed before this fix existed, since an
ordinary scan only revisits changed files. Run against the actual library
tonight (after a verified backup): folder-tag coverage went from 37,354 of
50,910 photos to all 50,910.
