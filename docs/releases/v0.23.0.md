LensLedger's search actually searches now, the filmstrip no longer stops at
250 photos, and a near-certain face match doesn't have to wait for a click.

## Search was broken — now it's smart

Searching with the default "Everything" scope has been silently broken: any
text query raised a database error under the hood and always returned zero
results. The cause was combining SQLite's full-text `MATCH` with an `OR` in
one clause, which FTS5 refuses to evaluate. That's fixed, and while fixing it
this release adds real relevance ranking — a search for "birthday" now
returns the best matches first ("Best match" sort) instead of only sorting by
date.

## No more 250-photo wall

The filmstrip used to stop hard at 250 photos with a "Next page" link. It now
loads more automatically as you scroll, backed by a new pagination endpoint
that shares the exact same query logic as the initial page, so scrolled-in
results can never drift out of sync with what you searched for.

## Near-certain face matches confirm themselves

A face match at least 90% confident, with a wide margin over the next-best
guess, is now confirmed and published to the photo's metadata immediately —
the same safety-backed publish path (backup, write, verify) a manual
confirmation uses. Anything less certain still goes to the review queue
exactly as before; an auto-confirmed match is one click away from being
corrected, same as any other.

## Library health panel is now actionable

"People to review," "Mapped photos," and "Review Bin" in the Library health
panel are clickable and take you straight to that screen instead of just
reporting a number.

## Hardening

- Added `X-Frame-Options` / `Content-Security-Policy` to close a clickjacking
  gap, switched the CSRF check to a constant-time comparison, and fixed a
  narrow race condition where a concurrent request during a library switch
  could see a new library root paired with the old catalog.
- Moved the app's page CSS and JavaScript out of the Python server file into
  served static files — the change that made the Content-Security-Policy
  above possible without weakening it for inline scripts.
- Escaped SQL `LIKE` wildcards in the people-name search and standardized
  metadata-backup filename timestamps on microsecond precision.

## Verified

- Full automated suite covering the search fix and relevance ranking,
  infinite scroll pagination, and auto-confirm (including that it actually
  publishes to the JPEG's XMP metadata with a verified safety backup).
- Manually exercised in a live browser against a 320-photo library: search
  ranking, scrolled pagination, the auto-confirm publish path verified
  end-to-end with ExifTool, and the new Content-Security-Policy confirmed to
  actively block an injected inline script.
