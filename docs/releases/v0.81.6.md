LensLedger already had a persistent log file (`LensLedger.log`) and a "Copy diagnostics"
button, but there was no streamlined way for a user to report an issue and attach that
context. Someone hitting a problem had to manually copy diagnostics, open GitHub, create
an issue, and paste everything in — easy to forget or get wrong.

## What changed

A new **"Report an issue"** button in the Help & Support section of the hamburger menu.
Clicking it:

1. Fetches the current diagnostics (version, schema, integrity, counts, last scan).
2. Fetches the last 50 lines from `LensLedger.log` via a new `/api/log/recent` endpoint.
3. Opens a GitHub new-issue form pre-filled with:
   - A `Bug:` title prefix for the user to complete.
   - Template sections for "What happened?" and "Steps to reproduce".
   - A **Diagnostics** block with the system info.
   - A **Recent log** block with the tail of the log file.

If the URL would exceed GitHub's URL length limit (~8000 chars), the log is trimmed to the
last 20 lines automatically.

### Backend

- Added `GET /api/log/recent` — returns the last 200 lines of `LensLedger.log` as JSON.

### Frontend

- Added `reportIssue()` in `theme.js` — gathers diagnostics + log, builds the GitHub
  issue URL, and opens it in a new tab.
