# Keep best copies of duplicate photos in one step

## Why this release

- Cleaning up identical photos meant Ctrl+clicking every extra copy in every set and choosing **Trash selected**. A library with hundreds of sets took hundreds of selections.
- Trashing a copy discarded anything attached to it in LensLedger: a rating, tags, a subject, a caption, or a confirmed person. A copy filed in an event folder also held that folder's tags, which the other copy did not have.
- The **Exact duplicates** and **Similar photos** views regrouped the whole library for every page of the filmstrip, and the full-file comparison that confirms two photos are identical was kept only until LensLedger restarted.

## What changed

### Exact duplicates view

- **Keep best copies** is a button at the top of the page, next to the count of photos that need tags. It appears only in the **Exact duplicates** view, set from the **Search scope** list or the **Duplicate photos** menu entry, and only when there are sets to clean up.
- The button opens a confirmation panel that gives the number of sets, the number of copies that would move, the space they use, and examples of which photo stays in a few sets. Nothing moves until **Keep best copies** is chosen in that panel. If the sets changed after the panel opened, for example because a scan finished, LensLedger asks for the preview again instead of acting on a list the person did not see.
- In each set the photo listed first stays. That is the likely original: names marked as a copy, such as `IMG_0001 (copy).jpg`, come last, then the shortest name. The other copies move to the Review Bin, and each can be restored from the menu under **Trash & restore**.
- The view's existing narrowing applies: text typed in the search box, a chosen date, a minimum rating and a map location limit which sets are cleaned up.
- At most 1,000 copies move in one run. When more remain, the result says so and running it again continues.
- If anything fails part way, every file already moved is put back and no change is kept.

### What carries over to the photo that stays

- A rating, when the photo that stays has none or a lower one.
- A subject, when the photo that stays has none.
- Tags it lacks, including the tags the other copy's folder gave it. These appear as photo tags on the photo that stays.
- People confirmed on another copy and not on the photo that stays. A person only suggested on the photo that stays becomes confirmed.
- A caption or note, when the photo that stays has none.
- Nothing is removed from the other copies. A restored copy has its own rating, tags and people exactly as before.

### Speed

- Both duplicate views remember their sets until photos are added, rescanned, removed or moved to the Review Bin, so later pages and later visits no longer regroup the library.
- The full-file comparison is stored in a new table in the library's database (schema version 26) and reused while the file's size and modified time are unchanged. A changed file is compared again.

### Documentation

- The manual, in the written manual and on the manual page, describes **Keep best copies**.

## Not changed

- **Similar photos** is not part of this action. Photos that only look alike are never moved automatically.
- No file is deleted. Everything moved can be put back from the Review Bin until the Review Bin is emptied.

## Verified

- Test suite: all tests passing, including new ones for the stored full-file hash and its reuse, a changed file being compared again, the remembered sets being recalculated after the library changes, which copy stays, the merge of rating, subject, tags, folder tags, people and caption, a lower rating or a different subject never replacing the existing one, the confirmation token refusing a stale preview, nothing moving when there are no duplicates, and restoring a cleaned-up copy from the Review Bin.
- Browser: the button and confirmation panel were checked in the light and dark themes against a generated library, and a full run moved the copies and left the view empty.
