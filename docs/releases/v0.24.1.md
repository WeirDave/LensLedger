A same-day fix, caught by actually watching the last release run against
the real library.

## Face detection was going to re-scan the same photos forever

`scan_for_faces()` only ever marked a photo as scanned by giving it a
`face_embeddings` row — but a landscape, an object, a photo with no one in
it never gets one. That meant every faceless photo would have been
reprocessed on every future scan pass, permanently, and the "remaining"
count in the health panel would never reach zero even right after a fully
complete run.

This was caught live: the first real run against the full 50,910-photo
library finished with zero errors but still showed 815 photos "remaining"
after processing every single eligible one. Fixed with a dedicated
`face_scanned` column that's set whether or not a face was actually found
— the exact same convention OCR's `ocr_scanned` already uses, so a
transient failure still gets retried but a confirmed "no one in this
photo" doesn't get checked again forever.

## Verified

- Full automated suite (55 tests, including new coverage confirming a
  faceless photo is never rescanned).
- Applied the schema migration to the real library after a fresh verified
  backup, then ran the corrective pass live to bring the previously
  affected 815 photos in line with the fix.
