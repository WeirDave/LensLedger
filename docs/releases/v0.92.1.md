## Context

The Publish page had a `max-width: 900px` constraint that left a lot of unused screen space on wider monitors, making the failure table feel cramped. Failed file paths were plain text with no way to navigate to the actual file — you had to manually find the folder.

## What changed

**Wider layout.** The Publish page `max-width` increased from 900px to 1200px, letting the content table and failure details spread out on larger screens.

**Clickable file paths in failure table.** Failed file paths are now styled as clickable links. Clicking one calls `/api/reveal-path` to open the containing folder in Explorer (Windows) or Finder (macOS), so you can quickly find and inspect the problematic file.

**Mobile responsive styles.** Added a `@media (max-width: 600px)` breakpoint that reduces padding, shrinks font sizes and the logo, and wraps the summary line for small screens.

The failure table was also refactored from string-concatenated HTML to DOM construction so that click handlers on the file path buttons work correctly.
