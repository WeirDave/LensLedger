## Motivation

Renaming a person with many confirmed photos (e.g. 166) caused the GUI to freeze for a long time. The Edit Person modal's Save button would stay disabled and the page would not reload until every confirmed JPEG had its embedded metadata rewritten — a process that runs exiftool multiple times per file, creates a safety backup, and verifies pixel integrity. For a person with dozens or hundreds of photos, this could take minutes.

## What changed

The `set_person_names` API endpoint now returns immediately after committing all database changes (name, aliases, tag sync, search row rebuilds, stale tag cleanup). The JPEG metadata publishing — the slow part — is handed off to a background thread. The GUI reloads instantly with the updated name, and the console log reports when background publishing finishes (or if it fails, at which point it restores backups for the affected files).
