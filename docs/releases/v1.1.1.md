## Summary

Meaning search and face detection were generating thousands of "cannot identify image file" errors for `.heic` and `.heif` photos. The root cause: `pillow-heif` is listed as a dependency but was not installed in the running environment. Every module that uses PIL to open HEIC files wraps the `pillow_heif` import in `try/except ImportError: pass`, silently swallowing the failure. The indexing queries then selected every HEIC file as a candidate, attempted to open each one individually with PIL, and recorded a per-file error.

## What changed

Instead of trying to open files in formats PIL cannot decode and failing on each one, the scan queries now check which image extensions PIL actually has decoders for and exclude unsupported ones from the candidate list entirely.

- Added `unsupported_image_extensions()` helper in `photo_index.py` that compares `IMAGE_EXTENSIONS` against `PIL.Image.registered_extensions()`.
- Updated `semantic_index.build_index()` to exclude unsupported extensions from its SQL query.
- Updated `face_scan.scan_for_faces()` to exclude unsupported extensions from its SQL query.
- Added a startup cleanup in `connect()` that clears stale "cannot identify image file" errors for unsupported extensions, so previously-errored HEIC files are cleanly skipped instead of lingering as errors in the UI.

When `pillow-heif` is installed, `.heic`/`.heif` appear in PIL's registered extensions and are processed normally — no code path is lost.

## Verified

- Full test suite: 113 tests passed.
- Confirmed `pillow_heif` is not installed in the current environment, and `.heic`/`.heif` are correctly identified as unsupported by the new helper function.
