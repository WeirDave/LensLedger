Direct user feedback on "Name faces": too many repeats, and picking the same
name from the dropdown for each one felt like exactly the kind of busywork
Google Photos got rid of years ago.

## Confirm one, group the rest

The complaint, paraphrased: naming faces one at a time means clicking through
several near-identical crops of the same person before reaching someone new.
Google Photos solves this by learning from your choice and folding matching
photos into the same decision instead of asking again.

`/faces-review` now does the same thing. `_find_similar_unidentified_faces()`
in `photo_search.py` runs right after a face is confirmed: it decodes that
face's stored embedding and scores it (cosine similarity, via the same
`decode_vector`/`dot` primitives `face_learning.py` already used) against
every other still-unidentified face. Anything at or above 0.76 — the
existing `SUGGESTION_THRESHOLD` People review's "Find more matches" already
uses — comes back with the save response.

The page pulls those matches out of the main grid and into a group banner
above it: "Also looks like *Name* — N photos," thumbnails, all pre-checked.
One click on "Confirm all" applies the name to every checked match; any
single one can be unchecked first, or the whole group dismissed with "Not
these" to fall back to reviewing them individually. Dismissed or unchecked
faces return to the normal queue exactly as before — nothing is silently
dropped.

This is deliberately *not* auto-confirm. A wrong auto-match would mislabel a
photo without anyone noticing; grouping still puts the decision one click
away, but a human looks at the thumbnails first.

### Why this works from photo one

`face_learning.learn()`'s existing profile-based matching only kicks in once
a person has at least two confirmed faces to build a centroid from — the
first photo of someone new gets no help. The new matching is direct
face-to-face similarity against the one embedding that was just confirmed,
so grouping works immediately, even for the very first photo named for a
person.

## Verified

- Full automated suite (65 tests, including a new
  `test_naming_a_face_returns_similar_unidentified_faces_as_matches` in
  `tests/test_server.py`) green.
- Manually verified live in a browser against a temporary test library:
  seeded five faces (three with near-identical embeddings, two dissimilar),
  confirmed via a real click that naming one pulled the other two into a
  match group with the name pre-filled; confirmed "Confirm all" applies the
  name to checked matches and returns any unchecked one to the normal grid
  without losing it; confirmed "Not these" releases the whole group back to
  the grid with no duplicates and no faces going missing; confirmed the
  grid's own auto-refill (`loadMore`) never re-adds a face that's currently
  parked in a group.
