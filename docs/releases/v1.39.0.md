# Meaning search matches a person's appearance

## Why this release

- Meaning search scored whole photos only. A feature of one person, such as a beard or a bald head, covers a small part of most frames, so it barely moved the score and photos that showed it were not ranked first.
- Selecting a person under More filters narrowed the list to that person's photos but did not change how they were ranked against a description of their appearance.

## What changed

### Searching for how someone looks

- Choose **Meaning** as the search scope, open **More filters**, select the person under **People (all of them)**, and type a description in the search box, for example `beard`, `bald head` or `wearing glasses`.
- Each photo scores by the better of two matches: the whole photo, and the face of each selected person in it. A photo with a close match on the face now ranks above one that only matches loosely as a whole. Photos with no prepared face data keep their whole-photo score, so descriptions of a scene, such as `beach`, rank as before.
- Without a person selected, Meaning search matches whole photos only, as before.
- The person needs confirmed photos. A suggested face does not count.

### Preparing faces

- For every located face, LensLedger encodes a square crop centred on the face and large enough to include the top of the head, hair and beard, using the meaning-search model already set up. The vectors are stored in the library database (schema version 28, table `face_semantic_embeddings`).
- This runs by itself at the end of a face detection run (including **Run all scans**) and at the end of a meaning search run. It does nothing unless meaning search is installed and its model is already downloaded, and it never starts a model download.
- Only faces without a vector are encoded, so later runs cover new faces only. Faces marked as not a face are skipped. Changing the meaning-search model prepares the faces again on the next run.
- The first run on an existing library encodes every located face and takes a while. Progress appears in the console log as **Face appearance index**.

### Limits

- The model matches the overall look of a face, not exact detail. Plain descriptions work better than precise ones.

## Verified

- Full test suite: 652 tests, all passing.
- New tests cover the face crop geometry, incremental indexing, skipping ignored faces, ranking by face against a better whole-photo match, unchanged scores for photos without face data, and the search page passing the selected people to the ranking.
