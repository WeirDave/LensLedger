The update flow got a real fix this time, and empty searches finally say so.

## Updates no longer create a mystery second copy

Clicking "Check for updates → Download, install & restart" from a copy that
wasn't already a managed installation — a source checkout, for
instance — used to silently create a brand-new managed copy somewhere else
on disk and launch it there, with no clear explanation of what just
happened. The update panel now recognizes an unmanaged copy and explains
what to do instead (`git pull` for a checkout, or run `Install
LensLedger.cmd` once if you deliberately want a separate managed copy) —
the install button doesn't even appear. The backend refuses the request
too, so this can't happen by accident from any angle.

## The update dialog no longer hangs forever

After a real managed-install update, the dialog used to say "LensLedger
will reconnect automatically" and then just sit there — nothing ever
checked whether the new version had actually come back up. It now polls
until the server responds again and reloads the page for you.

## Empty searches say so

A search with zero results used to leave the filmstrip blank and show a
confusing "0–0 of 0" in the header. All three spots — the summary line, the
main photo area, and the filmstrip — now say plainly that nothing matched.

## Verified

- Full automated suite (40 tests, including a new test asserting the
  update-install endpoint refuses unmanaged copies).
- Manually verified live: the update panel's messaging and hidden install
  button for this unmanaged source checkout, and the empty-search message
  across all three UI spots, with a normal non-empty search confirmed
  unaffected.
