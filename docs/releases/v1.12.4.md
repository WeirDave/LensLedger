## Why this release

When a photo is renamed or moved to another folder, the library scan
recognises it by its contents. It keeps the photo's existing record, so its
tags, people, faces and search data follow it. Three things are stored
against the file's path rather than the photo, and those stayed at the old
path:

- **The subject.** The scan re-applied the subject from the new path, found
  none there, and cleared it.
- **Tags removed from the photo.** They came back.
- **The record of the last write.** "Restore last publish" was no longer
  offered for the photo, even though its safety copy still existed.

The scan also kept the old file extension on record. A PNG renamed from
`.jpg` to `.png` was still treated as a JPEG.

## What changed

- When the scan recognises a moved or renamed photo, its subject, removed
  tags and write history move to the new path with it.
- The photo's file type is updated to match its new extension.
- If the new path already has its own subject or removed tags, those are
  kept.

## Verified

- Full test suite, all passing, run on a clean copy of this release.
- New test: a PNG named `.jpg`, given a subject, a removed tag and a write
  record, is renamed to `.png` and the library rescanned. The photo keeps
  its record, its extension is now `.png`, its subject is still applied as a
  tag, and the removed tag and the write record follow it. Without the
  change, the file type stays `.jpg` and the rest is left behind at the old
  path.
